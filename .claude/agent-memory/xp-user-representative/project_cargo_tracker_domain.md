cargo-tracker の業務の流れは「輸送要求 → 営業の審査 → 営業が見積りと経路方針を提示 → 荷主の回答（詳細経路設計へ進む・辞退・相談）→ 経路設計者の経路確定 → 荷主が見積りと承認済み経路を承認 → 営業が本予約確定 → 追跡」（要件定義のエンドツーエンド業務フロー。2026-10-01 のレビューで設計側の順序の誤りを R-01 として修正済み）。本予約より前は「輸送要求」、以後は「貨物予約」と呼び分ける。

**Why:** 2026-10-01 に UI 設計・NFR・運用要件を利用者視点でレビューした際に把握した前提。

**How to apply:** 次回以降のレビューで、前回指摘した次の論点が解消されたかを確認する（2026-10-01 にすべて「修正する」方針で設計へ反映。解消の確認は次回のレビューで行う）。
- 荷主への通知（見積り提示・本予約確定・確認中）が MVP に無い
- 見積りの辞退・相談の操作、輸送要求の複製（利用シーンに記載あり）が UI に無い
- 荷受人画面（C-11）が日本語のみで欧州の荷受人が読めない
- 有人対応の営業時間が平日 9-18 JST のみで欧州の営業時間とほぼ重ならない。営業日カレンダー（日本・欧州の祝日）未定義
- 鮮度 FRS-02（12 時間）が日次の手動取込と噛み合わず、確認中が乱発する恐れ
- 「本予約」が船腹確保（船会社のブッキング確認）を意味するかが曖昧。カット日・通関中の表示が無い
- 二者確認（訂正承認）とデータ責任者の取込が少人数に依存し、不在時の代行が未定義

- 社内画面の時刻は JST を主、UTC を括弧で併記（BR-10、UI 設計）

2026-10-02 Bolt 5（US-02 審査）レビューで示した利用者側の判断（次回確認する）:

2026-10-03 Bolt 6〜8 レビュー: Bolt 5 で示した「差し戻し案件を最初の提出時刻順で出す」は荷主一覧（C-02）で実現。人の決定 D-20（書類は任意、PDF/PNG/JPEG、10MB、送り状 1・梱包明細 1・その他 3）、D-24（差戻しは画面で見えるだけ・メール運用なし・期限なし）、UI-HO-04 は開発側の人が触って段階入力の採用を決めた（実荷主での確認ではない）。指摘した残り（次回確認する）:
- 差戻し理由が「送り状を直して」でも、引き継いだ書類を差し替えられず出し直せない（行き止まり）。差し替えは「後の Bolt」
- 他の項目の誤りで、正しく選んだ書類まで黙って消える（誤りの要約は誤ったファイルしか言わない）
- 不足事項は「1 行に 1 つ」と営業に書かせるのに、荷主の詳細では改行が潰れて 1 行になる
- 差戻しを荷主へ知らせる手段が無い（D-24）。パイロットで荷主が気づかず KPI-01 が伸びる恐れ。窓口の案内に電話・メールが無く JST のみ
- 営業の審査画面で、版 2 で足された書類と引き継いだ書類の区別が無い
- UI-HO-04 は実際の荷主（リピート利用者を含む）で確かめ直す必要

2026-10-05 Bolt 9・10 レビュー: D-25（書類は種類ごとに差し替え）、選んだ書類が消える案内、不足事項の改行、出し直し失敗の警告は解消を確認。US-03 は Bolt 10 で提示、Bolt 11 で失効・置換。指摘した残り（次回確認する）:

2026-10-05 Bolt 11（US-03 失効・置換）レビューで指摘した論点（次回確認する）:
- 再見積りの最中（旧版が置換済み・新版が承認待ち）、荷主の C-04 は置換済みの旧版だけを最新として示し「新しい見積りは担当営業にご依頼ください」と出る。輸送要求の状態は「見積提示済み（お客様の対応待ち）」のまま。営業が作成中なのに荷主へ依頼を促し、状態とも矛盾する。「新しい見積りを準備中」の案内が要る
- 受付一覧（S-02）は見積り作成中だけを出すため、提示済み・失効・置換後の承認待ちの見積りへ営業が一覧から辿れない（再見積りの入口が無い）
- 業務責任者に確かめる: 承認待ちの期限切れ（D-36）、算出時点での置換（提示前に旧版を無効にしてよいか）、失効を荷主へ知らせるか、期限切れの提示済みを荷主が「失効」と見たときの次の行動

2026-10-06 Bolt 12（US-24 AC1、詳細経路設計へ進む回答）レビューで示した利用者側の判断（次回確認する）:
- 経路設計中に見積りが失効したとき、荷主に「新しい見積りは担当営業にご依頼ください」と求めるのは誤り。遅れは A 社側の作業中に起きるので、A 社（担当営業）から連絡すると案内する。依頼済みの記録も消さない
- 経路設計中の失効は US-04 AC2 で本予約を止める。営業の S-02 の経路設計中の表で、期限切れ・期限が近いものが一目で分かる必要がある。S-04 の失効の案内には営業の次の行動を書く
- C-05「進む」は発注・予約の確定ではないと画面で明示する（荷主が押すのをためらう）。押し間違えたときの取り消し先（担当営業）も示す

2026-10-07 Bolt 17（US-06 S-05・S-06）レビューで示した利用者側の判断（次回確認する）:
- S-05 は依頼の新しい順だけで、見積有効期限・希望到着期限の近さが分からない。期限の近い順（少なくとも見積有効期限の列）が要る。荷主名も無い
- 適合候補に「期限まであとどれだけ余裕があるか」が無く、比較の決め手が欠ける。候補の見出しに経由港（直行／SGSIN 積替え）を出す
- 規則の無い港を除外するのは安全側で可だが、「接続できない」は物理的に不可と誤読される。「接続時間規則が未登録のため判定できない」とし、実際の接続時間と、US-07 の専門判断で救える道が要る
- 日時の表記（Asia/Tokyo（UTC+09:00）（UTC …））が長く、候補ごとに何度も出て比較を妨げる。UI 設計の「JST（UTC 00:00）」の短い形へ
- 「ほかに n 件」は算出直後の一時表示だけで、開き直すと消える。「候補提示済み」は荷主へ提示したと誤読される
