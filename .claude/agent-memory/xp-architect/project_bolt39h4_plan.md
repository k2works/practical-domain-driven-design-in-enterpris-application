Bolt 39h4 計画（2026-11-13、validating-design）で見つけた要点。

- `AcceptanceCriteriaCoverageTest` は見出しを `startsWith` で探し、節の中の `|` の行をすべてデータの行として読む。「### Release 1.0 の受入条件（照合の表の前の対応）」は「### Release 1.0 の受入条件」で前方一致し、4 列の表があると落ちる。新しい照合の表は別の見出しにし、前の対応の見出しは接頭辞を共有させない
- 航海には「既存の採用値との矛盾」は起きない（D-143。矛盾は主要実績の追跡番号だけ）。航海の差異は版の逆転だけ。差異は比べる相手の採用値があるときだけなので「差異のまま＝採用されていない」は成り立たない
- G-06c・G-06b(a) は入力に差異・欠落を持たないので、Golden の案件としては落ちようがない（見張り）。要件 :805 の「専門家判断へ送る案件」に当たるのは候補なしの (b) だけ
- test_strategy :537「Release 1.0 で Must の全受入条件の表」は、すでに閉じたストーリー（US-06・US-07・US-16・US-18 ほか）に締める Bolt が残っていないので、持ち主を決めないと宙に浮く
- UC-06 3a（候補なしの理由を示し専門判断へ）は MVP だが未実装。W8（US-20）への送りが release_plan に登録されていない
