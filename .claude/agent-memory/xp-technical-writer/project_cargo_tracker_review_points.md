Bolt 1〜3（2026-10-01〜02）のレビューで見つかった、以降の Bolt でも再発しやすい論点。

- 顧客向け画面は「見積依頼（輸送要求）」を併記する決まり（ui_design の画面オブジェクト節）。テンプレートでは「輸送要求 ID」だけが出がち
- D-4 の UUID 表示は Bolt 4 で解消（完了画面・URL・KPI 一覧とも業務番号）。以後は「業務番号」欄に「版 1」まで入る表記と、ui_design の画面ごとの行（S-22 など）が実装に追従しているかを見る
- 計画からの変更は「結果」行に追記されるが、計画本文の元の記述（例: 確認ポイント 4 の NOT NULL）は直されず残りがち。両方を突き合わせる
- 形式の誤りの文言（「数字で入力してください」）がドメインの規則（1 以上の整数・小数 3 桁）とずれやすい
- 場所（UN/LOCODE）は大文字だけを受け付ける。小文字入力の扱いが UI 側で抜けやすい
- 報告書のテスト件数は `apps/cargo-tracker/build/test-results/{test,uiTest}/*.xml` の tests・skipped 属性の合計で突き合わせる（Bolt 3 終了時 test 75 件うち skip 2、uiTest 17 件うち skip 3。uiTest は ArchUnit 等も混ざる既知課題）。CI は `gh run list --workflow cargo-tracker-ci.yml` と `gh run view <id> --json jobs`、時刻は `git log --date=iso` で照合する。報告書の「期間」の終了時刻・所要時間がコミット時刻と合わないことが続く（Bolt 3、Bolt 4 は約 4 時間 50 分と記載、実際は 11:19〜15:55 で 4 時間 36 分）
- Bolt 5（2026-10-02）: 報告の「時間の内訳」が計画の「結果」の時刻と 1 分ずれる、報告コミット（22:41）より後の完了時刻（22:45）を予定値で書く、が起きた。両文書の時刻とコミット時刻を三者で照合する。計画の途中でステップを分割（2→2a・2b）すると、引き継ぎ表など前半の本文に旧番号が残る
- 社内画面のエラー要約の見出しが「入力内容に N 件の誤り」固定で、古い版・競合・審査中でないなど入力でない拒否にも出る。文字数超過の文言が確定側にも「不足事項」を含む（Bolt 5 時点）
- 手順書に作者のローカル `.env` の値が混入しやすい（Bolt 3 で SonarQube の URL が 9001。スクリプトの既定は 9000、LOCAL_SONAR_PORT / SONAR_HOST_URL で変わる）。版（Node.js など）は tech_stack に根拠があるか確かめる
- `sonar-local:gate`/`check` は Bolt 2 レビュー後、OK 以外で失敗するよう直り、scan は `sonar.qualitygate.wait=true`（2026-10-02 確認）
- status: stable・verified 済みの文書（ADR、設計、要件）を AI が決定の反映で書き換えるとき、generated だけ更新して verified や更新履歴が付かないことがある。承認待ちの印（履歴行・log）があるかを見る
- 計画・release_plan のチェックボックスが、終了報告の人の承認前に [x] にされがち。また「開発基盤」など上位項目が [ ] のまま残る
- Bolt 10（2026-10-05）: 計画の状態の記号に `[?]` 承認待ちがあるのに、承認を次のステップとまとめるステップを `[x]` にする。画面イメージ（salt）の入力例と実装の受け付ける形がずれる（金額の 3 桁区切りを salt に書くが変換は BigDecimal で弾く）。データモデルの「NOT NULL を CHECK で守る列」の列挙がマイグレーションの CHECK と 1 列ずれる。画面一覧（ui_design の表の行 119 など）と URL の表で Bolt の追記が片方だけになる
- ユーザーマニュアル docs/manual（2026-10-10 初版レビュー）: 状態名は TransportRequestLabels（荷主は customerStatus、社内は status）と QuotationViews で照合する。マニュアルは失効時の文言（「担当営業にご依頼ください」・「再見積りはまだ画面で操作できません」）や処理中の案内を推測で書きがち。2.2 が荷主のレイアウトだけで社内（「cargo-tracker 社内」、窓口のフッターなし）が抜ける。キャプチャに丸数字の印がない。章内アンカー（#41-…）は HTML 版の slugify（ops/scripts/manual.js）では合うが、mkdocs の toc 既定では日本語が落ちる
- 記事 docs/article（2026-10-10 walking-skeleton-tour レビュー）: 「AT-01〜06 は ArchUnit」とまとめがち（AT-03 は Modulith、AT-04 は独自テスト、AT-06 は Gradle）。業務ルール層の受入は cucumber-spring の小さなコンテキストで動くので「Spring を起動せず」は不正確。`./gradlew check` は Docker が要る。マイグレーションは common と {vendor} の 2 系統。dev-data に KPI 計測記録の行が既にある。日本語見出しのアンカーは mkdocs 既定で壊れる
- Bolt 32c（2026-10-14）: A-03 は止められた利用者にも理由を示さない方針（文言は無操作の理由のまま）。利用停止の利用者は再ログインで A-01 の一般的な誤り（失敗回数には数えない）。症状が「ログインできない」に移るので、付録 B は Q1-1 と Q1-2 の相互参照を見る。マニュアルは利用者向けに「利用を止める」「役割を外す」、設計は「利用停止」「役割の取消し」と書き分けている
- Bolt 32d（2026-10-14）: 規則の文が「上の dev の例外」のように、別文書（ADR-011 の dev のコードの部品）にしかない記述を「上の」で指しがち。コミットや履歴の要約（「埋め草の数を失敗へ倒す」）が実装の判定（全体が 8 の倍数か）より強く言うことがある。要約語と実装の条件を突き合わせる
- Bolt 32b（2026-10-14）: session の警告は「操作」を画面の読み込みと延長だけで数える（入力の打鍵は数えない）。利用者の「操作」の語感とずれるので、文言とマニュアルで何を数えるかを見る。A-03 の「開いていた画面に戻ります」は Bolt 32e まで画面と事実が食い違い、マニュアルが画面の文言を引用して打ち消している。ログイン後の戻り先は invalidSessionUrl 経由では保存されず役割のホーム（FirstTotpSuccessHandler は SavedRequestAware なので経路で変わる）。キャプチャは manual_screenshots.feature で撮る
- Bolt 32e（2026-10-14）: 覚えた要求は session（Cookie）に付くので、同じブラウザの別のタブは同じ扱い（「別のタブでは戻らない」は誤り。戻らないのは別のブラウザ・端末）。戻るのは「失効の後に最初に開こうとした GET の画面」で、ナビゲーションを押せばその行き先。他社の荷主が業務番号の URL を開くと A-04 でなく「見つかりません」になる画面がある（ADR-012・マニュアルの「認可で拒まれ A-04」は役割違いのときだけ正しい）。A-03 の「送信していない入力は保存されていません」は、失効の後に送信した利用者には「送信したから保存された」と読める
- Bolt 32f（2026-10-14、T-90）: 「控える」が利用者が自分で書き留める意味（戻り先のない画面の案内・付録 B）とシステムが sessionStorage に写す意味の両方で使われ、1 文の中で衝突しがち。控えに印を付ける公開の画面は A-03 だけでなく 403・413 もあるので、「ログアウトの前に〜」の文言が 413（ファイル過大）や CSRF の 403 で事実と合わない。ui_design が「マニュアルで一覧を確かめるよう補う」とした 8 時間のぎわの二重の送信がマニュアルから漏れやすい。控えは 8 時間で消えるのでなく「8 時間を過ぎると戻さない（ログインした画面を開いたときに捨てる）」。ログアウトの送信で消えるのはそのタブの控えだけ
- Bolt 33a（2026-10-15、A-06）: 「ほかのパソコンやタブ」と書きがちだが、同じブラウザのタブは Cookie を共有するので「設定したブラウザ」に当たる（完了で新しい session に替わり、他のタブは A-03 でなく A-01 になる、とコードから読める）。トークンの期限は発行から 30 分なので「A-06 を開いたまま 30 分」の後は「リンクを開き直す」では通らず依頼し直しが要る（ui_design はそう書き、マニュアルが食い違った）。再設定の途中で A-03 に出た利用者は Q1-2 の行に当たる場所がない
- Bolt 34（2026-10-16、S-20 役割の変更）: 新しい役割の章を足しても 00 章の役割の表と 02 章の「役割ごとのホーム」の列挙が追従しない。用語集は「運営する会社」、画面は「運用する会社」と 1 字ずれた。ui_design の salt の付けられない旨（「荷主企業の利用者だけに付けられます」）と実装（「運用する会社の利用者には付けられません」）が食い違う。自分自身・荷受人の利用者の詳細にも役割のフォームを出し、選ぶと必ず拒否になる（設計で消せる誤り）
- Bolt 34b（2026-10-16、管理範囲）: 共通の 404 を 2.3（403）の注意・補足に 1 行で置き、02 章冒頭の画面の表・付録 B に行がない。追跡番号の照会は専用の not-found 画面なので「存在しない番号は共通の 404」と一般化しがち。用語は設計で「管理範囲」（AdministrationScope、判定）と「担当範囲」（user_assignment の表、W6 の登録）を使い分け、画面は「管理する企業」。空の一覧・範囲外の 404 とも「誰に頼むか」が無い
- Bolt 34d（2026-10-17、S-20 利用停止と再開）: 34 と同じく 00 章の役割の表・章一覧と用語集の「システム管理者」が追従しない。停止の理由の「緊急停止」は効き目が他の理由と同じ（次の request）なのに名前が即時の停止に読める。詳細は理由・停止した人・時刻を示さないので、2 章・付録 B が「システム管理者にお問い合わせ」と送った先の 11 章に、問い合わせを受けた管理者の手順（利用状態・企業の無効化・ロックの見分け）がない。拒否「利用状態は既に…です」がマニュアルの表から漏れる
- Bolt 37b2（2026-10-22、S-06 情報不足）: 社内の時刻は DateTimeDisplay.staff で「… Asia/Tokyo（UTC+09:00）（UTC …）」と括弧を 2 つ持つので、理由の括弧の中に時刻を入れると閉じ括弧が 3 重になる（接続不足は時刻を括弧の外に出す形）。マニュアルが「データ責任者に航海の取込を依頼」と書くが、航海の取込の手順はマニュアルに無い（W7）。用語集・8.2 冒頭の「除外＝期限に間に合わない」が新しい除外の理由に追従しない。設定値（許容時間）をマニュアルに固定値で書きがち。ui_design の salt の理由の文言・並びが実装とずれる
- Bolt 37d2（2026-10-22、S-06 再設計要）: 「版」を経路版とリリースの 2 つの意味で使いがち（「今の版」「後の版」）。「再設計（新しい経路版を作ること）の操作は、まだありません」と書く。「引き直す」はドメインの語で利用者の語にしない（画面は「航海の予定が使えない」）。salt 図は注意の枠と欄の並び（枠が先、理由・時刻は承認者の欄の行）が実装とずれやすい
- Bolt 37e3（2026-10-23、再設計要の文言）: 文言は社内（「経路が再設計要」＋相談先）と荷主（「割り当てた経路の見直しが必要になった」「担当営業にご相談ください」）で書き分ける。「状態の組み合わせの表の行 N」は Bolt ごとに別の表なので、文書では「Bolt 37e3 計画の…行 N」と出典を付ける（37e2 の行 13 と 37e3 の行 13 が同じ段落で衝突しがち）。S-04 の「承認済みで失効」の案内（荷主の再承認が要ります）は印があっても今のままで、新しい見積りも承認できないことと食い違う（計画の範囲外として残った）
- Bolt 39h2 ステップ 1（2026-11-12、設計文書の直し）: release_plan の台帳の「状態」列の確かめる相手が「期限」列とずれやすい（開始準備で D-147〜D-149 の状態が「追跡責任者」、期限が「データ責任者」。39h の D-141〜D-146 でも同じ直しをした）。英語名を変えたときは用語集の行だけでなく、ADR・data_model・domain_model のリポジトリの行に残る旧名（`quarantinedOf` など）に「Bolt N で名前を改めた」を添え、経緯の文は消さない。plantuml の scoop の shim は jar のディレクトリへ cd するので、相対パスでは「No diagram found」になる（`java -jar <plantuml.jar> -charset UTF-8 -tsvg <絶対パス>` で描画を確かめる）
- Bolt 39h2 ステップ 9（2026-11-12、マニュアル）: 一覧の名前を変える（「判断を待つ隔離」→「判断を待つ隔離・差異」）と、12 章だけでなく 00-はじめにの役割の表（:28）にも旧い語が残る。編集範囲を 3 ファイルに絞られた依頼では直さず報告に回す。付録 B は成功の知らせ（「隔離を却下しました。」）を載せず、判断済み・採用できない理由など誤りに見える文だけを載せる慣習
