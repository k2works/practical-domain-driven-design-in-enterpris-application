新しいフォーム画面のレビューで、前例の決まりから外れやすい点（Bolt 26c の S-13 で見つかった。2026-10-10）。

- エラーの文言は表示名で始めない（エラー要約が「表示名: 文言」になるため。2026-10-05 に人が決めた。ui_design の共通部品「エラー要約」）。S-13 は「場所を入力してください」「発生時刻は現在より前…」で外れていた。前例の文言は quotation の `QuotationViolationMessages`
- 既存の記録を結果として示す形（Bolt 24・26c の AC2）では「今回の入力は登録していない」を文言で言う。言わないと、内容が違っても更新されたと思われる
- 一覧の項目に「実績 N」のような番号があるのに、発生時刻の順の `ol` にすると、リストの番号と項目の番号がずれる
- 日時のテキスト欄の `inputmode="numeric"` は iOS で「-」「:」・空白を打てない（見積依頼の前例から引き継いだ。共通部品の課題）
- salt の画面イメージで既定の選択（(X)）を描くと、実装（既定なし）とずれる
- 2026-10-10 時点で templates/error/404.html が無く、404 は Spring の既定ページ（英語、ナビなし）になる。利用者が番号を入力して照会する画面（C-10 など）では 404 が主な経路になるので必ず見る
- 番号の入力の誤りの文言は、番号の文字集合（追跡番号は I・L・O・0・1 を使わない）と正規化（大文字化）に合わせる

**Why:** 前例をまねて作る画面でも、文言とリストの形は画面ごとに書き直されるので、決まりから外れやすい。
**How to apply:** フォーム画面のレビューでは、まずこの 5 点を見る。関連: [[project-async-status-display]]
