# ADR-020: AWS は東京リージョンにステージングと本番の 2 環境を置く

日付: 2026-11-16

## ステータス

承認済み（2026-11-16、human:kakimomokuri が選択肢から選んだ。W10 の Bolt 50）。ただし AWS のアカウントと予算の上限は未決で、下の「未決」に残す。

## コンテキスト

- ADR-008 は AWS の ECS Fargate・RDS・S3 を採用し、リージョンを東京に**仮置き**して、非機能要件で確定するとした。
- 荷主はアジア・欧州にいるため、データの所在地と越境移転（NFR-PRIVACY-01）がリージョン選定の制約になる。
- W10 は Terraform のコードと検証（plan・静的検査）まで作り、`apply` は行わない（W10 計画の CP-1）。
- 環境構成は `architecture_infrastructure.md` が、ローカル・デモ（Heroku。ADR-013）・ステージング・本番と定めている。

## 決定

| 項目 | 決定 |
| :--- | :--- |
| リージョン | 東京（`ap-northeast-1`）。Terraform ではリージョンを変数にして、直書きしない |
| 環境 | **ステージングと本番の 2 つ**。Terraform は環境ごとの変数ファイルで切り替え、構成は同じにして規模だけを変える。デモ（Heroku）はこの 2 つに含めない |
| アカウント | 環境ごとに AWS アカウントを分けるかは**未決**。Terraform の状態の保存先とプロバイダーの認証は変数にして、どちらでも動くようにする |
| 予算の上限 | **未決**。Terraform の変数（AWS Budgets の上限）は空にし、決まったら入れる |
| `apply` | W10 では行わない。実アカウントと認証情報が人から用意されるまで、plan と静的検査までとする |

### 代替案

| 案 | 見送った理由 |
| :--- | :--- |
| リージョンを決めずに変数のままにする | 越境移転の論点を先送りしたまま IaC を書くと、S3 の保存場所や RDS のバックアップ先をあとから直すことになる |
| シンガポール・フランクフルトなど | 荷主の所在地は広いが、パイロットの利用者は日本の営業・追跡・監査の担当者が中心（運用体制）。越境移転の論点が増える |
| 環境を 3 つ以上にする（開発用を足す） | 開発とデモは既存の環境（ローカル・Heroku）で足りる |

## 影響

### ポジティブ

- Terraform のコードのリージョンと環境が定まり、W10 の Bolt 51 以降を進められる。
- 日本のパイロット利用者に近く、越境移転の論点が最小になる。

### ネガティブ

- 荷主が海外から使うときの遅延は、パイロットの範囲外として扱う。
- アカウントの分け方が未決のため、状態の保存先とプロバイダーの設定は変数に出す手間がある。

## コンプライアンス

- Terraform の検証で、リージョンと環境が変数で与えられ、コードに直書きがないことを確かめる（Bolt 51）。
- 本番の `apply` は人の承認を必須にする（`architecture_infrastructure.md` の CI/CD）。
