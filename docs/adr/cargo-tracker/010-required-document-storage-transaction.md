# ADR-010: 必要書類のファイルは DB のトランザクションの外で保存し、失敗したときは補償で消す

必要書類の中身の保存を DB のトランザクションの外に出し、DB の保存が確定しなかったときは保存したファイルを補償で消す。取りこぼしは S3 のライフサイクルか定期の片付けで拾う。

日付: 2026-10-05

## ステータス

承認済み（Bolt 6〜8 開発成果物レビューの D-26 で、human:kakimomokuri が 2026-10-05 に AI の提案どおり決定。実装は運用準備（W10、#28）で S3 の保存と一緒に行う）

## コンテキスト

- 荷主は提出と出し直しで必要書類を添付できる（D-20、Bolt 7）。中身は書類の保存のポート（`RequiredDocumentStorage`）の向こうに置き、DB にはオブジェクトキーだけを持つ（[データモデル](../../design/cargo-tracker/data_model.md)、ADR-007・008）。
- Bolt 7 の実装は、コマンドサービスの `@Transactional` の中で、輸送条件の検証を通った後、DB の保存の前にファイルを書く。
- [Bolt 6〜8 開発成果物レビュー](../../review/cargo-tracker/bolt_06-08_review_20261003.md) の R-05 で、次が指摘された。
  - DB の保存が失敗したときだけでなく、正常系でも参照されないファイルが残る（出し直しの同時の更新で負けたとき、業務番号の採番の前に保存したとき）。
  - ファイルの書き込み（S3 では外部への通信）の間、DB の接続とトランザクションを保持する。
- ファイルの保存と DB の保存を 1 つのトランザクションにはできない（S3 は分散トランザクションに参加しない）。

## 決定

**ファイルの保存を DB のトランザクションの外に出し、トランザクションが確定しなかったときは保存したファイルを消す（補償）。補償で消せなかったファイルは、DB の記録を正として後から片付ける。**

| 項目 | 方針 |
| :--- | :--- |
| 順序 | 検証 → ファイルの保存（トランザクションの外）→ DB の保存（トランザクション）。ファイルの保存はキーを返すだけで、DB の行がなければ業務上は存在しない |
| 補償 | DB のトランザクションがロールバックしたとき（同時の更新で負けた、制約違反、障害）、その要求で保存したキーを消す。トランザクションの完了の通知（`afterCompletion`）か、アプリケーション層の明示の後始末で行う |
| 取りこぼし | 補償の前にプロセスが止まったファイルは、DB の `required_document.object_key` に無いキーを、保存から一定時間の後に消す。本番は S3 のライフサイクルの規則か定期の片付けのジョブ、開発はローカルのファイルシステムのため片付けない |
| 前の版の書類 | 差し替えた前の版の書類（D-25）は、前の版の行が参照しているので消さない（追記専用） |
| 実装の時期 | 運用準備（W10、#28）で S3 の実装と一緒に行う。それまでは開発環境のローカルのファイルシステムだけで動くため、参照されないファイルが残っても影響は小さい |

### 代替案

| 案 | 却下理由 |
| :--- | :--- |
| 今のまま（トランザクションの中で保存し、片付けない） | 正常系でも参照されないファイルが残る。S3 への通信の間、DB の接続を保持する |
| 定期の片付けだけにする（補償をしない） | 片付けまでの間、参照されないファイルが残り続ける。消してよいかの判断が、保存からの経過時間だけになる |
| DB の保存を先に行い、ファイルを後から保存する | DB の行が参照するファイルがない時間ができ、保存に失敗すると書類が取得できない行が残る（取得が 500 になる） |
| 書類を DB に入れる（BLOB） | ADR-007・008 で、原本は S3 に置くと決めている。DB の容量とバックアップの時間が増える |

## 影響

### ポジティブ

- DB のトランザクションが短くなり、外部への通信の間に接続を保持しない。
- 参照されないファイルが、補償と後からの片付けの 2 段で残らなくなる。
- DB の記録を正とするので、どのファイルが業務上存在するかが 1 か所で決まる。

### ネガティブ

- 補償の処理と、片付けのジョブ（または S3 のライフサイクルの規則）を作って保守する必要がある。
- 補償が終わるまでの短い間、参照されないファイルが存在する。

## コンプライアンス

- W10 の実装で、出し直しの同時の更新で負けたとき・DB の保存が失敗したときにファイルが残らないことを統合テストで確かめる。
- 出し直しで書類に違反があるとき、ファイルを保存しないことを単体テストで確かめる（Bolt 9）。
- 差し替えた前の版の書類が消えないことを統合テストで確かめる（Bolt 9）。
