# ADR-022: 必要書類のウイルスの検査は S3 の非同期の検査（マネージド）で行う

日付: 2026-11-16

## ステータス

採用（2026-11-16、human:kakimomokuri が「推奨で進めて」）。実装は Release 1.1 の頭。**それまで、パイロットで書類の添付を使わない**（Bolt 7 の決定のとおり、パイロット開始の条件）。

## コンテキスト

- Bolt 7 は必要書類の形式を 3 つに絞り、中身で判定し、`attachment` と `nosniff` で返すところまでを作った。ウイルスの検査は入れておらず、方式は W10 で決めるとした（Bolt 7 終了報告）。
- 必要書類は S3（ADR-008）に置く（W10 の Bolt 51 の Terraform に、必要書類のバケットがある）。保存先は社内の端末が開く書類のため、感染の経路になる。
- ADR-008 は運用の負担を小さくするため、マネージドサービスを選ぶ方針。

## 選択肢

| 案 | 内容 | 利点 | 欠点 |
| :--- | :--- | :--- | :--- |
| A | ECS のタスクにサイドカー（ClamAV）を置き、アップロードの要求の中で同期に検査する | 検査が済むまで保存しない。画面の流れが単純（結果をすぐ返す） | 定義ファイルの更新、メモリ（タスクの大きさ）、サイドカーの運用を自分で持つ。検査が遅いと応答が遅れる（PERF の影響） |
| B（推奨） | S3 に保存したあと、AWS のマネージドのマルウェア検査（Amazon GuardDuty の S3 のマルウェア保護）が非同期に検査し、結果をオブジェクトのタグに付ける。アプリは**「検査済み」のタグが付くまで、その書類を開かせない** | 定義ファイルの更新と検査基盤の運用が要らない。アプリの応答に影響しない | 検査が非同期なので、書類に「検査中」の状態が要る（画面と状態の追加）。AWS の機能の仕様と費用を、実装の前に確かめる |
| C | 検査しない（書類の添付を使わない運用を続ける） | 変更なし | 書類の添付が使えず、US-01 の必要書類の業務が運用で代替になる |

## 決定

**B（推奨のとおり）。** 書類は次の状態を持つ: 検査中（保存直後）、検査済み（タグが無害を示す）、拒否（タグが脅威を示す。書類を隔離し、有人案件にする）。開けるのは検査済みだけ。実装は Release 1.1 の頭に Bolt を立てて行い、Terraform（必要書類のバケットの保護の設定）、アプリの状態、画面、マニュアルを含める。

## 影響と確かめること（実装の前）

- **AWS の機能の仕様と費用の確認**: この ADR は機能の存在と動作の理解にもとづく。実装の計画で、公式の資料で対象のバケット・結果のタグの名前・費用・リージョンの対応を確かめる。確かめて合わなければ A に切り替える。
- パイロット開始の条件（release_plan の開始条件）: 「必要書類のウイルスの検査が動いていること」は、この実装の完了を指す。それまで添付を使わない。
