# ADR-016: 予約は commit 時刻を渡して見積りの公開 API で確定に使えるかを確かめる

見積りの有効性の判定（BR-10、Q-INV-06）は見積りの 1 か所に置く。予約は commit 時刻を渡して見積りの公開 API に照会し、確定に要る写しか、使えない理由を受け取る。

日付: 2026-10-08

## ステータス

承認（方針は 2026-10-08 に human:kakimomokuri が W4 の開始準備で決めた。文面は Bolt 23 の終了報告の承認で確かめる）

## コンテキスト

- BR-10: 予約確定の commit 時刻が見積有効期限より前のときだけ有効で、同時刻以後は失効。B-INV-02（予約）と Q-INV-06（見積り）が同じ規則を述べている。
- 予約（U6）は見積り（U1）の下流で、見積りの公開 API とイベントに依存してよい（ADR-001・ADR-014）。
- Bolt 11 レビュー R-19 は、見積りに「予約確定に使えるか（commit 時刻）」を置き、予約から見積りの判定をどう問い合わせるか（公開 API か有効期限の写し）を ADR で決めるとした。
- 見積りはすでに、荷主の承認で割り当てた経路の写し（経路版と区間）を持つ（ADR-014、Bolt 20）。

## 決定

| 要素 | 決定 |
| :--- | :--- |
| 判定の置き場所 | 見積りの 1 か所（Q-INV-06）。予約は有効期限の比較を持たない |
| 照会 | 見積りの公開 API（`quotation :: api`）に、業務番号と見積り番号と commit 時刻を渡す（2026-10-08 の Bolt 23b で見積り ID から改めた。画面の URL に内部の ID を出さない D-4 のため。呼び出し元は予約だけ）。見積りが承認済みで commit 時刻が有効期限より前のときだけ、確定に要る写し（輸送要求 ID・版、業務番号、見積り ID、荷主企業、荷受人、貨物区分・要約、荷主承認者と承認時刻、割り当てた経路版）を返す。それ以外は理由（失効・未承認・置換済み・見つからない）を値で返す（ADR-014 の「業務の拒否は結果の値で返す」） |
| commit 時刻 | 予約の確定のトランザクションの中で、保存の直前に `Clock` から取った時刻とする。同じ値を見積りへの照会に渡し、`booking_version.committed_at` に記録する（判定と記録を同じ値にする）。DB の実際のコミットはその後になるが、業務上の commit 時刻はこの値と定める |
| 照会の時点 | 確定の POST の同じトランザクションで照会する。確定の画面（S-09）の表示のための照会は参考で、確定の可否は POST の照会で決める |
| 経路版 | 予約は経路設計（`routing`）に問い合わせず、見積りが割り当てた経路の写しを使う。再設計要・旧版の経路版の拒否（B-INV-05、Q-INV-10）は、見積りの側が DE-06 を受けて承認・確定を止める形で W6 に足す |
| 写しの扱い | 予約は確定の後に見積りへ問い合わせ直さない。予約版は不変で（B-INV-08）、確定の時点の写しを持つ |

### 代替案

| 案 | 採らない理由 |
| :--- | :--- |
| 予約が有効期限の写しを DE-04（荷主の承認）などで受けて自分で判定する | 規則の写しが 2 か所になり、置換・再見積りの反映が遅れる。予約が見積りのイベントを購読して状態を持つ必要がある |
| 経路設計に公開 API を作り、予約が経路版の状態を直接確かめる | 予約の依存に `routing` が加わる。見積りがすでに割り当てた経路の写しを持ち、再設計要は見積りの側で止められる |

## 影響

### ポジティブ

- 期限の規則と境界のテスト（1 分前・同時刻・1 分後）は見積りの側の 1 か所で済む。
- `booking` の依存は `quotation :: api` だけになる。

### ネガティブ

- 照会は見積りの行を読むだけでロックしないため、照会と予約の保存の間に、別のトランザクションで見積りが置換される（再見積り）か、経路の再設計要（DE-06。W6）で承認・確定を止められると、止める前の見積りで確定し得る。置換は営業担当者の操作で、確定と同時に起きるのはまれ。B-INV-11（1 つの見積りから予約は 1 件）は貨物予約の UK で守る。
- DE-06 との競合を厳密に防ぐ方法（照会で見積りの行を `FOR SHARE` で読む、または見積りの版を照会の結果に含めて確定で期待版として渡す）は、DE-06 を作る W6 で決める（Bolt 23 の既知の課題）。

## コンプライアンス

- 見積りの API の単体テストで、境界の 3 点（1 分前・同時刻・1 分後）を確かめる。
- ArchUnit と ModularityTest で、`booking` が `routing` に依存しないこと、予約のコードが見積りの有効期限を比較しないことを確かめる。

## 改訂の経緯

- 2026-10-08: Bolt 23b で、照会の鍵を見積り ID から業務番号と見積り番号に改め、結果に荷主の承認時刻を足した。S-09 を業務番号と見積り番号で開き、画面の URL に内部の ID を出さないため（D-4。human:kakimomokuri が決定）
