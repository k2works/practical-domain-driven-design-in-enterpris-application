# 付録 A 用語集

本マニュアルと画面で使う言葉です。

## 1. 業務用語

| 用語 | 意味 |
| :--- | :--- |
| 荷主 | 貨物を送る会社。荷主担当者が見積依頼を出し、見積りと経路を承認します |
| 荷受人 | 貨物を受け取る会社。見積依頼の作成で選びます |
| A 社 | cargo-tracker を運用する会社（自社）。営業担当者・経路設計者・追跡管理者・システム管理者が所属します。利用者の管理の画面では「運用する会社」と示します |
| システム管理者 | 利用者を登録し、利用者の業務の役割を付けたり外したりし、利用者の利用停止と再開、ロックの解除、認証アプリの登録の解除、担当企業の割り当てを行う役割（[11 章](11-利用者の管理.md)）。業務データは変更できません。システム管理者・監査担当者の役割の付け外しと利用停止・再開は画面では行いません |
| 利用状態（利用中・利用停止） | 利用者が cargo-tracker を使えるかどうか。利用停止の利用者はログインできず、ログイン中なら次の操作でログアウトします。システム管理者が利用者の詳細で停止し、再開します（[11 章](11-利用者の管理.md)）。2 章・付録 B の「管理者が利用を止めた」「利用を止められた」は、この画面の「利用停止」と同じことです（所属する企業の利用を止めることは別の操作です） |
| 停止の理由 | 利用停止のときにシステム管理者が選ぶ理由（利用終了・異動・緊急停止）。どれを選んでも効き目は同じで、監査のため記録されます。停止中の利用者の詳細に、停止した人と停止した日時とともに示されます（[11 章](11-利用者の管理.md)） |
| 担当範囲 | 業務担当者が扱える業務データの範囲。今は担当企業で決まり、担当範囲のある役割（営業担当者・経路設計者・追跡管理者・カスタマーサポート）の利用者だけが持ちます（[11.8](11-利用者の管理.md#118-担当範囲の変更の確認)）。システム管理者の管理範囲とは別のものです |
| 管理範囲 | システム管理者が利用者を扱える企業。運用の手順で割り当てます。範囲外の利用者は一覧に出ず、詳細を開くと「画面が見つかりません」と示されます（[11 章](11-利用者の管理.md)） |
| 担当企業 | 営業担当者・経路設計者・追跡管理者・カスタマーサポートが扱える荷主の企業。システム管理者が利用者の管理（[11.8](11-利用者の管理.md#118-担当範囲の変更の確認)）で割り当てます。社内の見積依頼と予約と経路設計と追跡の画面には担当企業の荷主のものだけが示され、担当企業の外を開くと「画面が見つかりません」と示されます |
| 職務分離 | システム管理者・監査担当者に、業務データを変更できる役割を併せて付けない決まり。役割の変更で併せて選ぶと拒まれます |
| 見積依頼 | 荷主が出す、輸送の条件と貨物の情報。業務番号で識別します |
| 業務番号 | 見積依頼の番号（TR-2026-0001 の形）。お問い合わせのときに伝えます |
| 版 | 見積依頼を出し直すたびに増える番号。差し戻された見積依頼を直して出し直すと版が 1 つ増えます |
| 審査 | 営業担当者が見積依頼の輸送条件と書類を確かめること。確定すると見積りの作成へ進み、足りなければ差し戻します |
| 差戻し | 営業担当者が見積依頼の直しを荷主に求めること。理由と不足事項が荷主に示されます |
| 見積り | 料金根拠（料金明細）・合計・有効期限・経路方針。見積り番号（見積 1 など）で識別します |
| 有効期限（見積有効期限） | 見積りが有効な期限。この時刻より前に本予約を確定する必要があります。社内の経路設計の画面では「見積有効期限」と示します |
| 失効 | 有効期限を過ぎて見積りが使えなくなった状態。新しい見積りが要ります |
| 予約確定済み | 担当営業が本予約を確定した見積依頼の状態。追跡番号と追跡の状況は予約一覧で確かめます |
| 置換済み | 再見積りで新しい見積りに置き換えられた見積りの状態。読み取り専用になります |
| 再見積り | 有効期限を過ぎた見積りなどを、担当営業が出し直すこと。荷主の承認の後に失効した見積りは、承認済みの経路のまま料金と有効期限だけを出し直します |
| 経路方針 | 見積りの時点の経路の目安（主な経由地、概算の出発と到着）。詳細な経路は経路設計者が確定します |
| 詳細経路設計 | 荷主が見積りに回答した後に、経路設計者が航海と接続から経路を決めること |
| 経路候補 | 航海の情報と接続時間の規則から算出した経路の案。期限・接続・情報の古さの条件をすべて満たすものは「適合」、満たさないものは理由とともに「除外」 |
| 判定時刻 | 経路候補を算出した時刻。この時刻より後に出発する区間で候補を作り、この時刻に航海の情報が古くないかを判定します |
| 情報不足 | 経路候補に使う航海の情報が、取得から許容時間（いまは 24 時間）を過ぎていること。その候補は除外され、確定する時刻に情報不足なら適合の候補でも確定できません |
| 古くなった候補 | 経路候補を算出した後に、区間が今の航海と一致しなくなった候補（航海がないときも）と、適合の候補の航海の情報が取得から許容時間を過ぎた候補。経路候補の比較を開いた時点の航海と比べて示し、確定できません。案件の状態としては記録せず、同じ情報版で元の値に戻ると表示は消えます。情報不足とは区別します。古くなった候補には、算出の後に情報不足になった適合の候補を含みます |
| 確定した経路（経路版） | 経路設計者が判断根拠を残して確定した経路。番号（RC-…）と版で識別します |
| 区間 | 経路のうち、1 つの航海で積地から揚地まで運ぶ部分。社内の画面の語で、荷主の画面とマニュアルの荷主の章では「航海」と示します |
| 再設計要 | 確定した経路が、外部情報（航海の予定など）の更新で希望到着期限・接続時間を満たさなくなった、または区間の航海の予定が使えなくなった（欠航・寄港の取りやめ・寄港の予定の矛盾など）状態。システムが評価して付けます。再設計要の経路では確定し直せません。再設計（新しい経路版を作ること）の操作は、まだありません。再設計要の経路を割り当てた見積りは、荷主が承認できず、本予約を確定できず、有効期限まで再見積りもできません。再設計の操作と案件を終える操作が入るまでは、営業担当者が荷主に新しい見積依頼を出すよう案内し、古い見積依頼と案件はそのまま残します（運用の決まり。経路設計者の画面には、担当営業がそう案内すると示されます）。荷主の画面には「再設計要」と示さず「割り当てた経路の見直しが必要」と示し、担当営業への相談を案内します |
| 出発済み | 経路の最初の区間の出発予定を、判定の時刻（経路の確定の時刻、荷主の承認の時刻、本予約の確定の時刻、再見積りの時刻、画面を表示した時刻）に過ぎていること。出発予定と同じ時刻も出発済みです。出発済みの経路は確定できません。割り当てた経路の最初の区間が出発済みの見積りは、荷主が承認できず、本予約を確定できず、荷主の承認の後なら有効期限まで再見積りもできません。営業担当者は荷主に新しい見積依頼を出すよう案内し、古い見積依頼はそのまま残します（再設計要と同じ運用の決まり）。荷主の画面には「区間」「出発済み」と示さず「割り当てた経路の最初の航海がすでに出発した」と示し、担当営業への相談を案内します |
| 参照した航海情報の版 | 経路候補の判定に使った航海の情報の版。取り込んだ航海は提供元の外部版がそのまま示されます。確定した経路の版（経路版）とは別のものです |
| 承認 | 荷主担当者が見積りと確定した経路を受け入れること。予約の確定ではありません |
| 再承認 | 承認の後に有効期限を過ぎた見積りを、担当営業が承認済みの経路版と経路方針のまま料金と有効期限だけ出し直したとき（再見積り）に、荷主担当者がもう一度承認すること。荷主の画面では「もう一度承認」と示します |
| 本予約 | 営業担当者が確定条件を確かめて確定した予約。確定すると追跡番号が発行されます |
| 追跡番号 | 貨物の追跡のための番号（CT で始まる 14 文字）。英字の I・L・O と数字の 0・1 は使いません |
| 追跡の開始 | 本予約の確定の後に、追跡を始める処理。終わるまでは「追跡の開始待ち」（荷主）・「処理中」（社内）と示されます |
| 輸送中（予約の状態） | 集荷の実績が採用された予約の状態。追跡管理者が集荷の実績を登録または採用すると、少し後に予約の詳細の状態が「確定済み」から「輸送中」になります（[7.3](07-本予約の確定と予約一覧.md#73-予約の詳細)）。追跡の現在状態の「輸送中」（出発の後）とは別のものです |
| 輸送完了（予約の状態） | 引渡しの実績が採用された予約の状態。集荷の実績がなくても、引渡しが採用されれば「輸送完了」になります（[7.3](07-本予約の確定と予約一覧.md#73-予約の詳細)） |
| 主要実績 | 集荷・搬入・出発・積替・到着・引渡しの事実。発生時刻と出典とともに記録します |
| 出典 | 主要実績の根拠の情報（現場記録・社内確認・手動入力・外部原本）と、その参照（受付番号など） |
| 出典の外部原本 | 提供元から取り込んだ原本を根拠にした主要実績の出典。追跡の詳細に「外部原本 …（取得 …）」と示されます。主要実績の登録では選べません |
| 採用 | 現在状態を決めるのに使う主要実績の状態。追跡管理者が登録した実績は採用になります（時系列に反すれば確認中、完了した追跡では保持のみ）。取り込んだ実績は下書きで届き、追跡管理者が採用すると採用になります。外部データの取込の分類の「採用」は別の意味です（採用（外部データの取込）） |
| 下書き | データ責任者が外部データの取込で採用した主要実績が、追跡の詳細に届いたときの状態。現在状態を変えず、荷主の追跡の照会にも示されません。追跡管理者が追跡の詳細で採用すると「採用」になり、現在状態が決め直されます（[9.2](09-追跡管理.md#92-追跡の詳細)）。同じ主要実績の下書きが複数あるときに採用できるのは、後から公開された下書きだけです（ほかの下書きは「後から公開された原本に置き換えられました」と示されます） |
| 保持のみ | 予約が完了した貨物と、採用した実績が引渡しまで進んだ貨物に届いた主要実績（取り込んだ実績と、追跡管理者が登録した実績）の状態。記録として残し、現在状態を変えず、荷主の追跡の照会にも示されません |
| 確認中 | 採用済みの実績と時系列に反する主要実績の状態と、そのときの追跡の現在状態。実績の種類の進み（集荷 → 搬入 → 出発・積替 → 到着 → 引渡し）と発生時刻の前後が、採用済みの実績のどれかと逆のときです。実績は消えずに残り、追跡の詳細に「時系列に反する実績があります（実績 N）。採用済みの実績から導いた状態は M です。」と示されます（[9.2](09-追跡管理.md#確認中の追跡を確かめる)）。確認中を解く操作は今後のリリースで提供します |
| 現在状態（現在の状態） | 採用した主要実績から決まる貨物の状態（集荷予定、集荷済みなど）。荷主の画面では「現在の状態」、社内の画面では「現在状態」と示します |
| 当初の到着予定 | 本予約を確定したときの経路の最後の区間の到着予定。実績を登録しても変わりません |
| 最新の到着見込み | 採用した主要実績から見込んだ、いまの到着の見込み。予定より遅れた出発・積替では遅れの分だけ当初の到着予定より後ろに動き、目的地での到着ではその到着の時刻になります。早い出発では早まりません。確認中・下書き・保持のみの実績では動きません（[9.2](09-追跡管理.md#最新の到着見込みと最終取得時刻)） |
| 最終取得時刻 | 採用した主要実績の出典を取得した日時のうち最も新しいもの。追跡一覧・追跡の詳細・荷主の照会の結果に示します。採用した実績がなければ、追跡一覧では「なし」、追跡の詳細と照会の結果では「まだありません」と示します |
| 次の予定の実績 | 次に届くはずの出発・積替・到着の実績。予定区間の出発予定・到着予定のうち、採用した実績が当たる最も後のものの次です。追跡の詳細に「次の予定の実績の予定時刻」として示します（なければ「なし」） |
| 鮮度超過 | 次の予定の実績が予定時刻から 36 時間を過ぎても採用されていないこと。追跡一覧の現在状態の後ろの印と、追跡の詳細の警告の文で示します。画面を開いたときに判定するもので、追跡の現在状態は変わりません。完了した追跡は判定しません |
| 予約版 | 本予約の内容の版。確定したときが予約版 1 です |
| KPI-01 | 経路提示リードタイム。見積依頼の最初の提出から最初の見積りの提示までの時間 |
| データ責任者 | 運送会社・港湾などから受け取った外部データを取り込み、分類を確かめる役割（[12 章](12-外部データ.md)）。A 社に所属します |
| 情報源 | 外部データの提供元（運送会社・港湾など）と原本の種別（航海・主要実績など）の組み合わせ。運用の手順で選定し承認したもの（承認済みの情報源）だけから取り込めます |
| 取込 | 情報源から受け取った CSV ファイルを cargo-tracker に取り込むこと。データ責任者が外部データの取込の画面で行います（[12.1](12-外部データ.md#121-外部データの取込)） |
| 採用（外部データの取込） | 取り込んだ行の分類の 1 つ。初めて受け取った行で、業務で使う値として記録されます。データ責任者が隔離の判断の画面で、判断を待つ内容の違う原本（航海・主要実績）を採用したときも、受け取った値が業務で使う値として記録されます。この採用の理由は任意（1000 文字まで）で、判断した人・時刻とともに記録され、取り消せません。誤って採用したときは、提供元に新しい外部版で正しい原本を送ってもらいます（[12.2](12-外部データ.md#隔離を採用する)）。採用できない隔離は、判断の画面に理由が示されます（[12.2](12-外部データ.md#採用の欄が出ない隔離)） |
| 重複 | 取り込んだ行の分類の 1 つ。提供元・原本の種別・外部 ID・外部版が同じで、この外部版の採用値の元になった原本と内容も同じ行。値は増えません。元になった原本は、はじめはその外部 ID・外部版を初めて受け取ったときの原本で、隔離を採用すると採用した原本に替わります（[12.2](12-外部データ.md#直して送り直すとき)） |
| 隔離 | 取り込んだ行の分類の 1 つ。提供元・原本の種別・外部 ID・外部版が同じなのに、この外部版の採用値の元になった原本と内容が違う行。この外部版の採用値と元になった原本を上書きせずに残します。ファイルや行の形式を確かめられないとき（中身が空のファイルや、選んだ情報源と違う種別のファイルなど）も隔離になります。まず選んだ情報源とファイルの組み合わせを確かめ、それでも分からなければ提供元に確かめます（[12.1](12-外部データ.md#121-外部データの取込)） |
| 隔離の理由 | 取込の結果の画面に示される、隔離になった行とファイルの理由。「4 行目: 列の数がヘッダーと違います（ヘッダー 4 列、この行 5 列）。提供元に確かめてください。」のように、どこ（ファイル・行の番号）・理由・どうすればよいかをファイルの行の順に示します。重複の行の理由は示しません（[12.1](12-外部データ.md#隔離の理由を読む)） |
| 判断を待つ隔離 | 隔離になった受信記録のうち、まだ判断していないもの。隔離・差異の確認の画面に、取込の新しい順・ファイルの行の順で一覧になります。種類は「内容の違う原本」（外部 ID・外部版が同じで内容が違う行）と「形式の誤り」（行やファイルの形式を確かめられず、外部 ID・外部版を読めなかったもの）の 2 つです（[12.2](12-外部データ.md#122-隔離差異の確認)） |
| この外部版の採用値 | 内容の違う原本と同じ提供元・原本の種別・外部 ID・外部版で採用した値のうち、最も新しく公開したもの。航海は外部版の新旧によらず最後に採用した値が経路設計の航海になるので、いま業務で使っている値とは限りません。隔離の判断の画面で、受け取った値と並べて示します。同じ外部 ID で外部版の新しい原本の値は含めません。外部版の新しい原本の値との違いは差異として扱い、まだ画面で確かめられません（[12.2](12-外部データ.md#隔離の判断の画面)） |
| 却下（隔離） | 判断を待つ隔離を、業務で使わないと判断すること。データ責任者が隔離の判断の画面で理由（必須、1000 文字まで）を書いて行います。1 つの取込の判断を待つ形式の誤りは、形式の誤りのまとめての却下の画面で、1 つの理由でまとめて却下できます（[12.2](12-外部データ.md#形式の誤りをまとめて却下する)）。判断した人・時刻・理由が隔離ごとに記録され、その隔離は判断を待つ隔離の一覧から消えます。内容の違う原本を却下しても、この外部版の採用値はそのままです。却下は取り消せません。誤って却下したときは、提供元に同じ原本を送り直してもらいます（[12.2](12-外部データ.md#隔離を却下する)） |
| 要確認（取込） | 取込の結果の画面に示される、取り込めなかった部分があることの知らせ。引用符が閉じないままファイルが終わったときは「12 行目からファイルの終わりまで（29 行）」、ファイルを読めなかったとき（文字コード・ヘッダー・必要な列の誤り、中身が空のファイルなど）は「ファイル全体（データ行 1,234 行）」「ファイル全体（データ行なし）」の形で、取り込めなかった部分を示します。取り込めなかった部分の行は分類されず、まとめて隔離 1 件になります。行の誤りだけのとき（その行が隔離になる）は示されません（[12.1](12-外部データ.md#要確認を読む)） |

## 2. 画面と表記

| 用語 | 意味 |

| UN/LOCODE | 港を表す 5 文字のコード（例: JPTYO（東京）、NLRTM（ロッテルダム）、SGSIN（シンガポール）） |
| 日本時間（Asia/Tokyo） | 画面の日時の基準。荷主の画面は日本時間、社内の画面は日本時間と UTC を併記します |
| ナビゲーション | 画面の左に並ぶ、役割で使える画面の一覧 |
