# 付録 A 用語集

本マニュアルと画面で使う言葉です。

## 1. 業務用語

| 用語 | 意味 |
| :--- | :--- |
| 荷主 | 貨物を送る会社。荷主担当者が見積依頼を出し、見積りと経路を承認します |
| 荷受人 | 貨物を受け取る会社。見積依頼の作成で選びます |
| A 社 | cargo-tracker を運用する会社（自社）。営業担当者・経路設計者・追跡管理者・システム管理者が所属します。利用者の管理の画面では「運用する会社」と示します |
| システム管理者 | 利用者の業務の役割を付けたり外したりし、利用者の利用停止と再開を行う役割（[11 章](11-利用者の管理.md)）。業務データは変更できません。システム管理者・監査担当者の役割の付け外しと利用停止・再開は画面では行いません |
| 利用状態（利用中・利用停止） | 利用者が cargo-tracker を使えるかどうか。利用停止の利用者はログインできず、ログイン中なら次の操作でログアウトします。システム管理者が利用者の詳細で停止し、再開します（[11 章](11-利用者の管理.md)）。2 章・付録 B の「管理者が利用を止めた」「利用を止められた」は、この画面の「利用停止」と同じことです（所属する企業の利用を止めることは別の操作です） |
| 停止の理由 | 利用停止のときにシステム管理者が選ぶ理由（利用終了・異動・緊急停止）。どれを選んでも効き目は同じで、監査のため記録されます |
| 管理範囲 | システム管理者が利用者を扱える企業。運用の手順で割り当てます。範囲外の利用者は一覧に出ず、詳細を開くと「画面が見つかりません」と示されます（[11 章](11-利用者の管理.md)） |
| 職務分離 | システム管理者・監査担当者に、業務データを変更できる役割を併せて付けない決まり。役割の変更で併せて選ぶと拒まれます |
| 見積依頼 | 荷主が出す、輸送の条件と貨物の情報。業務番号で識別します |
| 業務番号 | 見積依頼の番号（TR-2026-0001 の形）。お問い合わせのときに伝えます |
| 版 | 見積依頼を出し直すたびに増える番号。差し戻された見積依頼を直して出し直すと版が 1 つ増えます |
| 審査 | 営業担当者が見積依頼の輸送条件と書類を確かめること。確定すると見積りの作成へ進み、足りなければ差し戻します |
| 差戻し | 営業担当者が見積依頼の直しを荷主に求めること。理由と不足事項が荷主に示されます |
| 見積り | 料金根拠（料金明細）・合計・有効期限・経路方針。見積り番号（見積 1 など）で識別します |
| 有効期限（見積有効期限） | 見積りが有効な期限。この時刻より前に本予約を確定する必要があります。社内の経路設計の画面では「見積有効期限」と示します |
| 失効 | 有効期限を過ぎて見積りが使えなくなった状態。新しい見積りが要ります |
| 予約確定済み | 担当営業が本予約を確定した見積依頼の状態。追跡番号と追跡の状況は予約一覧で確かめます |
| 置換済み | 再見積りで新しい見積りに置き換えられた見積りの状態。読み取り専用になります |
| 再見積り | 有効期限を過ぎた見積りなどを、担当営業が出し直すこと。荷主の承認の後に失効した見積りは、承認済みの経路のまま料金と有効期限だけを出し直します |
| 経路方針 | 見積りの時点の経路の目安（主な経由地、概算の出発と到着）。詳細な経路は経路設計者が確定します |
| 詳細経路設計 | 荷主が見積りに回答した後に、経路設計者が航海と接続から経路を決めること |
| 経路候補 | 航海の情報と接続時間の規則から算出した経路の案。期限・接続・情報の古さの条件をすべて満たすものは「適合」、満たさないものは理由とともに「除外」 |
| 判定時刻 | 経路候補を算出した時刻。この時刻より後に出発する区間で候補を作り、この時刻に航海の情報が古くないかを判定します |
| 情報不足 | 経路候補に使う航海の情報が、取得から許容時間（いまは 24 時間）を過ぎていること。その候補は除外され、確定する時刻に情報不足なら適合の候補でも確定できません |
| 確定した経路（経路版） | 経路設計者が判断根拠を残して確定した経路。番号（RC-…）と版で識別します |
| 再設計要 | 確定した経路が、外部情報（航海の予定など）の更新で希望到着期限・接続時間を満たさなくなった、または航海を引き直せなくなった状態。システムが評価して付けます。再設計要の経路では確定し直せず、再設計（後の版を作ること）は今の版ではできません |
| 参照した航海情報の版 | 経路候補の判定に使った航海の情報の版。「航海番号@版」で示します（例: V-201@1）。確定した経路の版（経路版）とは別のものです |
| 承認 | 荷主担当者が見積りと確定した経路を受け入れること。予約の確定ではありません |
| 再承認 | 承認の後に有効期限を過ぎた見積りを、担当営業が承認済みの経路版と経路方針のまま料金と有効期限だけ出し直したとき（再見積り）に、荷主担当者がもう一度承認すること。荷主の画面では「もう一度承認」と示します |
| 本予約 | 営業担当者が確定条件を確かめて確定した予約。確定すると追跡番号が発行されます |
| 追跡番号 | 貨物の追跡のための番号（CT で始まる 14 文字）。英字の I・L・O と数字の 0・1 は使いません |
| 追跡の開始 | 本予約の確定の後に、追跡を始める処理。終わるまでは「追跡の開始待ち」（荷主）・「処理中」（社内）と示されます |
| 主要実績 | 集荷・搬入・出発・積替・到着・引渡しの事実。発生時刻と出典とともに記録します |
| 出典 | 主要実績の根拠の情報（現場記録・社内確認・手動入力）と、その参照（受付番号など） |
| 採用 | 現在状態を決めるのに使う主要実績の状態。追跡管理者が登録した実績は採用になります |
| 現在状態（現在の状態） | 採用した主要実績から決まる貨物の状態（集荷予定、集荷済みなど）。荷主の画面では「現在の状態」、社内の画面では「現在状態」と示します |
| 予約版 | 本予約の内容の版。確定したときが予約版 1 です |
| KPI-01 | 経路提示リードタイム。見積依頼の最初の提出から最初の見積りの提示までの時間 |

## 2. 画面と表記

| 用語 | 意味 |
| :--- | :--- |
| UN/LOCODE | 港を表す 5 文字のコード（例: JPTYO（東京）、NLRTM（ロッテルダム）、SGSIN（シンガポール）） |
| 日本時間（Asia/Tokyo） | 画面の日時の基準。荷主の画面は日本時間、社内の画面は日本時間と UTC を併記します |
| ナビゲーション | 画面の左に並ぶ、役割で使える画面の一覧 |
| エラー要約 | 入力に誤りがあるとき画面の上に示される誤りの一覧。項目をクリックすると入力欄に移ります |
| 準備中の画面 | まだ作っていない画面。「この画面は準備中です」と示されます |
| 認証アプリ | 6 桁のコードを 30 秒ごとに表示するスマートフォンのアプリ。ログインの 2 段目に、そのコードを入力します |
| 認証コード | 認証アプリに表示される 6 桁の数字。ログインの 2 段目と、認証アプリの登録・登録し直しで入力します |
| 回復コード | 認証アプリを使えないときに、認証コードの代わりに 1 回ずつ使える 8 文字のコード（例: 1a2b-3c4d）。認証アプリを登録したとき・登録し直したときに 10 個示されます |
