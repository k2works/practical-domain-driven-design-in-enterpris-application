## 判断と学び

- 計画の「占有で直列にする」は、同時の 2 つは防げても、順に来る二度押しを防げなかった。条件付きの更新の条件に「読んだ値のまま」を入れると、同時と順の両方を 1 つの仕組みで扱える
- 再認証なしの経路を受け入れる判断は、「その経路がいつまで有効か」と組で決める。計画の段階では印の期限を確認ポイントに挙げていなかった
- 変更の影響を受ける既存のテストを探すとき（T-122）、1 つのクラスだけを見て、ロックのテストの回復コードのログインの期待を見落とした。`recoveryCode` で grep すれば見つかった
