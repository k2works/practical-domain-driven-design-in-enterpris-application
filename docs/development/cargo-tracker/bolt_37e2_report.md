## 判断と学び

- 並行の守りは、届く順の表の片方の向きだけを確かめても足りなかった。「先に読んでから押さえる」の誤りは、押さえた側が値を変える向きでしか見えない
- 受入シナリオで「最初のまま」を確かめるときは、上書きする実装でも同じ値になる入力では検証にならない。保存されたかどうか（集約の版）を見る
- テストの偽物も並行のテストで使うなら、スレッドに安全にする

### ふりかえり（KPT）

- Keep: 届く順の表と状態の組み合わせの表を計画に書き、行ごとにテストの名前を付けた。PostgreSQL の待ちを `pg_blocking_pids` で確かめ、直列や遅いだけで通らないテストにした
- Problem: 逆の向きのロックの確かめ、DE-06 の配信の統合テスト、循環的複雑度の確かめを、開発レビューと `check` まで見落とした
