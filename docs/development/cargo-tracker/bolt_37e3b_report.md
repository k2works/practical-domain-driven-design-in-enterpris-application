## 判断と学び

- 変異のスクリプトの置換の誤りで、変異が「落ちた」ように見えた。全件が落ちたときは、狙った検査で落ちたのではなく前提（起動）が壊れていると疑う
- データベースの CHECK 制約が拒む変異は、検査に届かない。変異は制約を満たす形で当て、制約が守るものと検査が守るものを分けて書く
- キャプチャの撮影も動画の撮影も全部を撮り直すので、その Bolt の外の差分を戻す手間が毎回要る
