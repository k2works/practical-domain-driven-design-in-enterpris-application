## 判断と学び

- 生き残った変異は、テストが空振りしている場所を教える。主要実績の例外の文に要約が入らないので、ログの確かめが主要実績の組だけでは何も守っていなかった
- 書式の文字を防ぐテストは、ソースに生の文字を書くと、それ自体がセキュリティのホットスポットになる。テストの文字列はエスケープで書く
- 層の規則が拒んだら、置き場所を動かさず規則の例外を判断として記録する（CLAUDE.md の決まり）。規則の Javadoc の「使う Bolt で使う層に限って足す」が判断の拠り所になった
