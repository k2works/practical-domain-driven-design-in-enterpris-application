## 判断と学び

### 設計への反映（反映済み）

- ユーザーストーリー: US-02 の決定に D-24（差戻しは画面で見えるだけ、期限なし、不足事項は自由記述、仮の営業担当者を承知）と、荷主に見せる審査記録の範囲
- ドメインモデル: 荷主の一覧の照会 `findSummariesByShipper`、一覧の行の状態、荷主に見せる差戻しの知らせ `SendBackNotice`（理由と不足事項だけ。下書きのときの、現在の版への差戻し）
- UI 設計: C-02・C-04・C-03 の編集の URL、提出の完了画面の C-04 への統合、状態と「いま誰の対応待ちか」の対応表
- 手順書: 開く URL に C-02 を足し、提出の後に C-04 が出ることを書いた

### AI の判断（承認の場で確かめてほしいこと）

- **出し直せないときの文**: 編集を開いたときと出し直しを送ったときで、「TR-2026-0001 版 1 は審査中のため出し直せません」と同じ文にした。いまの状態を読み直して示す
- **同時の更新**: 詳細に戻して「他の利用者が先に更新しました。内容を確かめてから出し直してください」と示す。入力は残らない（下書きを動かせるのは荷主だけなので、まれと判断した）
- **差戻しの知らせの型**: 荷主に見せる範囲を、画面でなく型（`SendBackNotice`）で決めた。判断者と確定の根拠は型に入っていないので、画面から誤って出せない
