## 判断と学び

- 閾値を入れる前に、その閾値で倒れるテストとデータを先に動かすと、振る舞いの変更と準備の変更を分けられ、デモ環境に倒れる窓も作らずに済んだ。準備の正しさは、テストの件数と結果が変わらないことで確かめられる
- 時刻に依るテストは、比べる相手の時計をそろえる。画面の層は判定と同じ JVM の時計、開発データはマイグレーションを流した時刻と比べる。「今から何時間」の窓はテストの走る時間で揺らぐ
- dev の画面を確かめるときに、TOTP の値の取り出しを誤って一度失敗した。HTML の値を取り出すときは、取り出した値の長さを出力で確かめてから送る（T-166 の差し込み版）
