## 計画から変えたこと

- 拒否の理由の型（`VoyageValuesRejected`・`VoyageValuesRejectionReason`）を足した（開発レビューの指摘 1。`@ValueObject` を付けない前例に合わせ、用語集には足さない）
- 寄港の重複の注記を「N つ目と M つ目の寄港が同じです」に改めた（計画の文も合わせた）
- 写しを守るテストの比べる値に、受ける値と拒む値の両方があることを確かめるテストを足した
- 統合テストは主要実績だけ（テストの情報源の部品が主要実績で固定。寄港の誤りは受入シナリオで確かめる）

## 判断と学び

- 規則を別のコンテキストに写すときは、写しを守るテストを正規表現の文字列ではなく振る舞いで比べる。比べる値に受ける値と拒む値の両方があることも確かめないと、空振りする
- 拒否の理由を型の外で推し量ると、規則が増えたときに誤った理由を書く。理由は規則を持つ型が返す
- ステップごとに SonarQube を流すと（T-234）、前のステップの違反をその場で見つけられる

### ふりかえり（KPT）

- Keep: 寄港の規則の食い違い（39e で毒入りのメッセージになる）を計画の初稿で見つけて人に諮った。ステップごとの SonarQube（T-234）で、最後のステップに違反がまとまらなかった。この Bolt のサブエージェントは heredoc を 1 度も使わなかった（39b2 から 2 本続けて）
- Problem: 変異 V8・V2 の穴が品質ゲートまで残った（行 18 のテストが件数だけを見ていた、種類の一覧から引数を作っていた）
- Try: T-235: テストの名前の「行 N_」に Bolt の接頭辞を付けるかを W7 の締めで決める。T-236: 「起きないこと」を確かめるテストは、件数ではなく呼び出しの記録で確かめる

### 既知の課題（後に持ち込む）

- 39b3: DE-12・DE-13 に値の型を載せると、下流は `externaldata :: events` しか参照できない（イベントの型を開始準備で諮る）。寄港の数に上限がなく、採用値の `value_summary`（VARCHAR(4000)）に入らない航海がありうる
- 39d・39h: 値を表に持たないので、隔離した行の採用と既存の採用値との比較で値を作り直すにはファイル全体の原本のヘッダーが要る（選択肢を 39d の開始準備で諮る）
- 39e: `Voyage` の class 化と経路設計の規則の追加のときは、外部データの写しと写しを守るテストも直す。寄港の重複は外部データの片側だけの規則
- W7 の締め: 予約の追跡番号の写しを `ExternalDataCopiedRulesTest` で一緒に守るか、テストの名前の規約（T-235）
- 統合テストの行の原本は共有の PostgreSQL に残る（ADR-004 の設計。提供元を UUID で絞るので干渉しない）
