- 0 件の画面は UI では作れない（共有の DB に情報源が残る）ので、コントローラーのテスト（照会を mock）で確かめ、UI の受入シナリオとキャプチャから外した

## 判断と学び

- サブエージェントに渡す前提（データ責任者はほかの役割と重ねない）を、コードで確かめずに書いた。整合性検証が見つけた（T-239 の違反）
- 画面の Bolt はマニュアルとキャプチャと動画で大きくなるので、初稿の時点で縦に分ける案を推奨にしたのは妥当だった（1 本では約 8 時間）

### ふりかえり（KPT）

- Keep: アウトサイドインで 35 件の Red を先に確かめ、Green に進んだ。開発レビューのユーザー代表の視点で、マニュアルの説明の欠け（データ責任者が誤った行動をとる）を見つけた。サブエージェントは heredoc を 1 度も使わなかった（39b2 から 7 本続けて）
- Problem: 前提をコードで確かめずに担当に渡した（T-239 の違反）。UI のテストのデータが共有の DB に残るため、0 件の状態を UI で作れない
- Try: T-243: 画面の Bolt で状態の数を 0 件にする受入シナリオが要るときは、計画の時点でコントローラーのテストに下ろすと決める
