## 判断と学び

- 引き直しの仕様は「組が 1 つに決まらなければ選ばない」で考えると漏れがない。計画では積地の重複だけを見て、揚地の重複を見落とした。候補探索が区間をどう作るか（どの寄港も揚地にできる）から、引き直しで区別できない形を数え上げるべきだった
- 画面の文言は、同じ画面にすでにある語（経路版・参照した航海情報の版）と、次にすることの案内の前例と突き合わせてから書く。計画の承認の場では文の趣旨しか見ていなかった
- 変異のスクリプトで gradle が起動していないのに「生き残った」「落ちた」と出た。判定は出力の文字列ではなく、テストの結果の XML と終了コードで行う
