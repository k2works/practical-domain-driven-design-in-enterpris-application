## 判断と学び

- 旧版から新しい集約へ値を写す操作は、写す値の組と、入力で上書きされる値の組を分けて書かないと、写した値と入力の値が食い違う集約ができる（今回は経路版と経路方針）。同じクラスなら、旧版の 1 つの操作が新しい集約の private のフィールドに書けるので、値を外に出さずに済み、呼ぶ順序への依存も消える
- メモリのリポジトリの受入テストは、集約の中の値が揃っていれば通る。子の表（区間）を書くかどうかは PostgreSQL の統合テストでしか捕まらない
- 受入テストのステップを使い回すときは、数える対象（配信していないイベントか、シナリオの始めからのイベントか）を実装で確かめる
