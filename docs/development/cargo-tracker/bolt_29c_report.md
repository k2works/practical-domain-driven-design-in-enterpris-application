## 判断と学び

### 既知の課題（後に持ち込む）

- 撮影のデータの航海番号（`UI-…-DIRECT` など）を業務の名前にする（Bolt 29b・29c の開発レビュー）
- 開発レビューの任意の指摘 10〜12（議題 4）
- 採用情報版の値の書式の決定と分解（W7 の外部原本の取込）

### ふりかえり（KPT）

- Keep
  - 開始準備の 2 つの検証がそろって「S-06 の語は S-07 にも出る」と指摘し、範囲の漏れを着手の前に見つけた
  - 骨組み（空の実装）を先に置いたので、Red 19 件がコンパイルの失敗ではなく本命のアサーションで落ちた（T-88）
  - 数値の書式の境界値（指数の表記、大きな値、丸め）を最初の Red に入れた
- Problem
  - 開始準備の最初の棚卸しで、表示の部品が使われている画面（S-07）まで追わなかった。文言の定義の場所から使う側の画面を数える手順が抜けていた
  - 「参照した航海情報の版」のたとえを、既存のたとえの表の意味（時刻表＝予定）と照らさずに足した
- Try
  - T-97: 画面の文言を変えるときは、文言を作る部品（Views・Labels・断片）を使っているテンプレートとコントローラーを `grep` で数え、変わる画面の一覧を計画に書く
  - T-98: UI 設計のたとえの表に行を足すときは、既存の行のたとえと意味がぶつからないかを読み比べる
