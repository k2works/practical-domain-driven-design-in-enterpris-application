## 決定

(1) **通知はイベントにする**（W8 CP-7。ADR-014 の方向: 経路設計は追跡に依存せず、追跡が購読する）。経路設計が DE-32 `RouteCandidatesNotFound` を発行し、追跡の `RouteCandidatesNotFoundEventHandler` が有人案件を起票する。追跡のモジュールの依存に `routing :: events`（公表された言語）を足す。

(2) **発行の条件**（`RoutingCase.candidatesNotFoundReason`）: 候補を算出した経路版で、候補が 0 件（理由 `EXTERNAL_DATA_MISSING`。経路に使える航海がない。G-06b）、または候補はあるが適合が 1 件もない（理由 `NO_CONFORMING_CANDIDATE`）。**すべて貨物種別だけで除外された案件は発行しない**（Bolt 39i の手動の窓口のまま）。発行は候補の算出を保存した後（`RoutingCaseCommandService.calculateCandidates`）。再算出のたびに発行されるが、有人案件の重複の判定が未終結の同じ案件の二重の起票を防ぐ。

(3) **`kind` の割り当て**（台帳 D-161。仮）: 候補なし → 見積り相談（優先度 通常）、外部データの欠落 → 外部停止（優先度 高。復旧照合が要る案件になる。手動の情報源に経路設計案件を残す）。担当部門は経路設計部、荷主企業を残す。`kind` の CHECK は変えない。

(4) **S-06 の表示**: 候補の見出しの下に「専門判断のため、有人案件（外部停止／見積り相談）として引き継ぎました。受付番号は「有人案件」の一覧で確かめてください。」を示す（既存の理由の文はそのまま）。起票は追跡が非同期に行うので、受付番号は S-06 に出さない。

(5) **起票できないとき**（営業カレンダー未登録など）は例外を上げ、発行記録を未完了のまま再配信に任せる（40-13 と同じ）。
