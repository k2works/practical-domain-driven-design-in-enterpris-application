## ふりかえり（KPT）

### Keep

- 受入シナリオ（Red）→ 内側の TDD → シナリオが通る、の順で縦割りを通せた。ステップごとにコミットし、ビルドが通る状態を保った
- テストが一度で通ったときに、わざと壊して失敗することを確かめた（AT-01、配信テスト）
- 5 視点のレビューを並列に回し、実装の欠陥 5 件をクローズの前に直せた
- 契約テスト（メモリ上・PostgreSQL・H2 の 3 実装で同じテスト）で、テストダブルと本物のずれを機械的に防げるようにした

### Problem

- 設計にある約束（ARCH-HO-01 の受信側の冪等性、ADR-007 の Clock の精度）を、Bolt 計画のステップに落とさなかった。ウォーキングスケルトンの「入れないもの」に書いていなかったため、黙って抜けた
- テストダブルを本物より緩く作り、本物の欠陥を隠した
- 配信テストの待ち条件を緩く書き、他のテストの行で満たされうる形にした
- 依存の向きの誤りをテストでなく目視で見つけた（AT-02 がない）
- 画面の文言（見積依頼の併記、エラーの直し方）を UI 設計の横断ルールと突き合わせなかった
