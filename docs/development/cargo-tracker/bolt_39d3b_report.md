## 判断と学び

- 判断の追記と採用値の追記の順は、セーブポイントの有無で決まる。セーブポイントの中の判断を先に書けば、同時の判断に負けた側は判断済みに戻り、採用値を書かない。順を逆にすると PostgreSQL では負けた側のトランザクションが中断する
- 業務の判断の推奨は、2 つの検証で同じ穴を指されたら差し替える。初稿の (m) は「採用できる」だったが、取り消しを作らない決定と合わせると、元のキーの誤りを直す道がなくなっていた

### ふりかえり（KPT）

- Keep: 2 つの整合性検証が (m) の帰結と、同じ情報版で値の違うイベントを着手前に見つけた。作業を止める指示のときに、途中の状態と再開の位置を残した
- Problem: 作業を止めたとき、コンパイルの通らない Red のコミットを develop に残した。私は「push しない」と書いたが、その後 origin/develop に入り、11-06 から 11-09 まで develop の CI が赤になり、デモ環境への配備も止まった（push は私の操作ではない）。途中で止めるときに、壊れたコミットを develop に積まない形を選べた
