## 開発レビュー

プログラマー（テスター・アーキテクトの観点を含む）とテクニカルライター（デモの台本、シナリオの読みやすさ）の 2 つの観点で行った。プログラマーの観点では、照合のテストが Gherkin を行単位で手で解析していたため、取りこぼしが「通る」側に出ることと、後片付けのフックの別の漏れ（`@US-24`）が見つかった。テクニカルライターの観点では、台本だけでは一人で操作できない入力値と手順の抜けが見つかった。

| # | 指摘 | 重大度 | 対応 |
| :--- | :--- | :--- | :--- |
| P-1 | 後片付けのフックに `@US-24` が漏れている（タグの列挙では足し忘れる） | 必須 | 直した。航海を入れたシナリオだけを消す形にし、タグの列挙をやめた |
| P-2 | 照合が例・ルールのタグ、`フィーチャ:` などのキーワード、行末のコメントを取りこぼす | 必須 | 直した。Cucumber の解析器（`io.cucumber:gherkin`。cucumber-bom の版）で Pickle にして数える。例の `@wip`・ルールのタグを含む Feature の文字列で解析を確かめる単体テストを足した |
| P-3 | 表の行が書式から外れると黙って照合から落ちる | 必須 | 直した。節の表のデータの行は 1 行も読み落とさず、読めない行は失敗にする。その単体テストと、表にあるのにシナリオがない受入条件を見つける単体テスト（T-88 の手作業の確かめを回帰のテストにした）を足した |
| P-4 | AT-05 で、自分の公開 API の実装に依存しても禁止されない。他のコンテキストの公開 API を許す分岐が試されていない。対象外の組み立てが明記されていない | 推奨 | 直した。`interfaces.api.internal` を禁止に加え、判定を直接確かめる単体テストを足し、テスト戦略の AT-05 に対象外と他のコンテキストのドメインイベントも禁じることを書いた |
