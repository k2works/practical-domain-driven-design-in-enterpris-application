## Bolt ゴール

CI の画面の層のジョブで、session の失効の入力の保持の CSRF の拒否のシナリオが、マシンの速さに依らず決まって通る。揺らぎの原因を再現で確かめ、テストの待ち方を画面の実際の状態（控えの印）に合わせる。

### 確かめたい仮説

| # | 仮説 | この Bolt で分かること |
| :--- | :--- | :--- |
| H1 | 403 の画面（CSRF の拒否）では `session-input.js` が deferred で読まれ、DOMContentLoaded で控えに `passedPublic = true` を書く（`session-input.js` の `publicPage`）。ステップ「権限がない画面が表示される」は見出しが見えるかだけを待つので、遅いマシンでは印が付く前に次のステップ「見積依頼の一覧を開く」（`page().navigate`）へ移る。一覧の画面では `reason === 'submit' && !passedPublic` の控えを古いとして捨てるので、案内「送信できなかった入力があります。」が出ずに落ちる | 403 の画面の `/js/session-input.js` の応答を保留したまま次の画面へ移ると、2 つのシナリオが決まって落ちる（Red）。待ち方を直すと、保留しても（待ちの間に応答を返せば）通る（Green）。落ちたときに sessionStorage の控えの有無を記録し、H1（控えが古いとして捨てられた）と偽の時計の候補を見分ける |

### 開始準備で確かめたこと

（W6 の開始準備の事実集め。行番号は 2026-10-20 の develop の `27d5f4131`）

- **落ちた記録**:
  - Bolt 35（`bolt_35_report.md:107`）。CI の run 39182866242 で 2 回続けて落ち、3 回目で通った。attempt 1 で落ちたのは「CSRF のトークンが合わず拒まれた送信でも見積依頼の一覧の案内から入力を戻せる」（`session_timeout_ui.feature:147-153`）、attempt 2 で落ちたのは「案内の "入力していた内容を消す" を押すと控えが残らず…」（:155-164）。どちらも `AssertionFailedError`。
  - Bolt 33e の CI（`bolt_33f_report.md:102` に記録）。32f の CSRF の拒否のシナリオで 1 回落ちた。
  - run の ID と落ちたシナリオの名前の出典は CI のログ（`gh run view --attempt 1/2 --log-failed`）。成果物（`cargo-tracker-ui-reports`、ID 12157651031・12157737372）の XML では、2 回とも `containsText("送信できなかった入力があります。")` が `#session-input-status` を 5000 ms のあいだ 14 回調べ、`Received: ""` のまま落ちた。案内は遅れたのではなく一度も出ていない（H1 と合い、`announce` の 500 ms の候補は弱い）。成果物の保存期間は 14 日なので 2026-11-02 ごろに消える（この計画に事実を写した）
  - 3 回とも同じ前提「CSRF の 403 → 見積依頼の一覧を開く → "送信できなかった入力があります。"」を通る。
- **画面の側**: 403 のテンプレート（`templates/error/403.html:12`）は `main` に `data-session-input="rejected"` を付ける。公開の画面のレイアウト（`layout/public.html:12`）は `session-input.js` を `defer` で読む。
- **テストの側**:
  - 「権限がない画面が表示される」（`SessionTimeoutUiSteps.java:320-324`）は見出し「権限がありません」が見えるかだけを待つ。
  - 「見積依頼の一覧を開く」（:238-241）は `page().navigate` で移る。
  - 控えが消えるのを待つ形（`waitForFunction` で sessionStorage を見る。:339）は、すでにある。
  - session の切れの後の送信のシナリオは、`publicPage` が印の後に書く「入力を戻す旨」（A-03 の `#session-input-note`）を待つので、同じ競合を持たない。
- **CI**: 画面の層のジョブに再試行はなく、`uiTest` は並列の指定がない（`build.gradle:121`、`.github/workflows/cargo-tracker-ci.yml`）
- **ほかの候補（弱い）**: 知らせを 500 ms 遅らせる `announce` と、Playwright の偽の時計（`BrowserSession` の `clock().install`）の組み合わせで、`containsText` の既定の待ち時間を超える。`BrowserSession` は `@ScenarioScope` でシナリオごとに新しい context を作るので、ほかのシナリオの後片付けや sessionStorage の持ち越しは起きない
- **同じ形の範囲**: 控えを扱うのは `session_timeout_ui.feature` だけ。413 を経るシナリオはなく、A-01 は印を付けない画面。A-03 を経るシナリオは、入力を戻す旨（`#session-input-note`）を待つか、戻り先が同じで `passedPublic` に依らず戻るので、同じ競合を持たない。実際に直すのは :147-153 と :155-164 の 2 つの見込み
- **待つ条件の注意**: 「権限がない画面が表示される」（:320-324）は認可の 403 のシナリオ（:166-174）でも使う。こちらは控えの理由が `expired` で `rejected` の印もないので、`publicPage` は控えを消さず `passedPublic` も立てない。「印あり、または控えなし」を待つとこのシナリオで時間切れになる。`document.readyState !== 'loading'` は deferred script の前に `interactive` になるので足りない

## スコープ

### 入れるもの・入れないもの

| 入れる | 入れない |
| :--- | :--- |
| 遅らせて揺らぎを再現する確かめ（スクラッチパッドの使い捨ての差し込み） | 画面の JS とテンプレートの変更（仮説が外れたときに止めて諮る） |
| CSRF の拒否の 403 を経た後に、控えの印が付くのを待つステップ（同じ形の全部。見込みは 2 つのシナリオ） | 画面の層の開き直すループの共通化（#50。W6 の 37b・37c の前に写しを数えて決める） |
| 繰り返しの確かめと、#50 の印 | CI のジョブの再試行の設定（揺らぎを隠すので入れない） |

### 設計の約束

- テストは、画面の利用者が実際に見る状態か、画面が自分で書く状態（控えの印）を待ってから次へ移る。時間で待たない（`waitForTimeout` を使わない）
- 待ちは CSRF の拒否のステップ（「CSRF のトークンが合わない状態で見積依頼の作成画面のフォームを送信する」の後）の側に置き、待つ条件は「控えがあり `passedPublic` が真」にする（先に控えがあることを確かめる。T-106）。認可の 403 のシナリオが使う共通の「権限がない画面が表示される」には条件を足さない（控えの理由が違い、条件が成り立たないため）。画面の JS の内部の関数は呼ばない

## ステップ計画

各ステップの終わりに対象のシナリオを流し、最後に `check` と `uiTest` を流して件数を数える（T-151）。コミットは pathspec で行い（T-110）、push してアプリの CI を確かめる（T-26）。

- [ ] **1. 再現（Red）**: 使い捨ての差し込みで、403 の画面の `/js/session-input.js` の応答を保留する。Playwright Java の route の handler はテストのスレッドで呼ばれるので、handler の中で待たない。`Route` を控えるだけで応答せず、保留したまま次の画面へ移る（Red）。Green の確かめでは、待ちのステップの間にテストのスレッドから `resume` する。差し込みはテストのソースに一時的に置き、ステップ 3 の後に消す。落ちたときは sessionStorage の控えの有無を記録する。差し込みを外すと通ることも確かめる（T-164）（完了の判定: 保留すると 5 回中 5 回落ち、控えが捨てられている）
- [ ] **2. 写しを数える**: 公開の画面を経た後にすぐ次の画面へ移るステップを、画面の層のステップの全体で数える（T-148）（完了の判定: 直す箇所と、該当しない理由を含む一覧）
- [ ] **3. 直し（Green）**: CSRF の拒否の後に控えの印を待つステップを足し、2 の箇所で使う。保留しても（待ちの間に応答を返せば）通ることを確かめ、差し込みを消す（完了の判定: 保留して 10 回、差し込みなしで 10 回通る）
- [ ] **4. 品質ゲートと開発レビューと終了報告**: `check`・`uiTest`・SonarQube（ほかの Gradle が終わってから。T-147）、push して CI の画面の層のジョブを 2 回流して緑を確かめ、MkDocs の配備を確かめる（T-126）。#50 の該当の項目に印を付ける（閉じる条件は W6 の残りの Bolt の CI の ui ジョブの観察。確認ポイント 3）。終了報告で release_plan（W6 の Bolt 36 の行と主なタスク）・開発の索引・mkdocs を完了に直す
