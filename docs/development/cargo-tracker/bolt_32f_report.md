## 計画からの変更

- `data-user` を利用者の ID の一方向の値にした（議題 2 の (a)）
- 知らせの領域を `aria-live` にした（議題 2 の (b)）。既存の HTML のコメントに `role="status"` があると `@WebMvcTest` が落ちたので、Thymeleaf のコメントにした
- 別の利用者のシナリオは、社内の一覧を開いてから確かめる形にした。32e の復帰で、ログインし直した直後は荷主の画面（403）に着くため
- 開発レビューで、印を付ける画面の明示（議題 3）と文言（議題 4）を変えた。計画の確認ポイント 1・7・8 の文言は、UI 設計で決め直した
- 対照の変異（③）は同値と分かった（指標）

## 判断と学び

- 「どの画面を経たか」をレイアウトという構造上の位置で暗に決めると、レイアウトを共有する画面（認可の 403）の意味まで変わる。印は、意味を持つ画面に明示して置く
- 「変えた欄だけを写す」は、hidden の欄では初期の値が値に追随するので、許す一覧と 2 重に効く。変異の確かめで、テストが見分けられないことが分かった
- 知らせの文言は、出る場面をすべて並べてから決める。最初の「ログアウトの前の」は、session が生きたままの開き直しと CSRF の 403 で事実と合わなかった

  - 変異の確かめで、空振りするテストと同値の変異を見分けた

  - 印を公開のレイアウトに一律に置いた

  - T-124: 「この画面を経た」で振る舞いを変えるときは、レイアウトでなく画面に印を明示する。印の有無の対をテストにする

### 既知の課題（後に持ち込む）

- 期限の到来の後に入力した分は、控えに写らない（`pagehide` では写さない）
- JS の単体の層がなく、入力の控えの規則は E2E だけで確かめている。radio・checkbox は貨物種別で確かめた。select・同じ名前の欄・GET のフォームを写さないこと・8 時間ちょうどの境界は確かめていない。画面の層のテストの時間が問題になったら、`page.setContent` で固定の HTML を置く層を作る
- `sameOriginPath` が 2 つのファイルに重複している（両方のコメントで指し合う。ビルドの仕組みを入れるときにまとめる）
- 社内の画面のフォームで写して戻す道は、画面の層で通っていない（同じ部品を通る）
- 利用者の鍵は仮名化（秘匿が要るなら HMAC）
- 共用のパソコンで、閉じたタブの復元で控えが戻ること（PRV-01 は「提案」のまま。管理・コンプライアンス責任者の確認を待つ）
- 32e から持ち越した、要求の属性の名前の 3 組の重複（33b）

## 支援技術の手動確認の手順（議題 6。人が行う）

準備: dev で起動し（`./gradlew bootRun`）、荷主（dev のアカウント）でログインする。期限の到来を待つ間は、ブラウザの開発者ツールで時計を進めるか、30 分待つ。NVDA＋Chrome または VoiceOver＋Safari で、各項目を 2〜3 回試す。

1. **戻したことの知らせ**: C-03 で段階 1〜2 に値を入れる（貨物種別は「一般」以外）。期限の到来の案内が `alert` として読まれることを確かめてから、「画面を開き直す」を押す。開き直した直後に、操作をしなくても「前に入力していた内容を戻しました。…すべての段階に戻しました。…」が読まれるか。読み込みの読み上げと重なって落ちないか
2. **フォーカスの位置**: 1. の後、フォーカスが知らせに奪われていないか。Tab の順は「ヘッダー → ナビ → 戻した入力を消す → main の先頭」か。閲覧モードで上から読むと、知らせが main の前に読まれるか
3. **戻した値の追随**: 段階の一覧で段階 2 と確認の段階へ移り、戻した値が欄と要約にあるか。貨物種別の案内が読まれ、提出が「使用不可」と読まれるか
4. **「戻した入力を消す」**: Enter で押す。フォーカスが知らせの領域へ移り、「戻した入力を消しました。」が 1 回だけ読まれるか。フォーカスの枠が見えるか。貨物種別の案内が消え、提出が使えるようになるか
5. **送信が拒まれた場合の案内**: 送信の前に別のタブでログアウトしてログインし直す（CSRF のトークンが替わる）。そのうえで C-03 を送信すると 403 になる。次に見積依頼の一覧を開き、「送信できなかった入力があります。」が読まれるかを確かめる。リンクの一覧（NVDA の Insert+F7、VoiceOver のローター）で、「入力していた画面を開く」「入力していた内容を消す」が単独で意味を成すかも確かめる
6. **「入力していた内容を消す」**: 5. の案内で押す。フォーカスが領域へ移り、「入力していた内容を消しました。」が読まれるか。次の Tab で main の先頭へ進むか
7. **拡大**: 拡大鏡 200〜400% と幅 320px で、知らせと期限の到来の案内（上端に留まる）がフォーカスを隠さないか（2.4.11）

結果は「済み・問題なし」か「問題あり（項目と内容）」で返してほしい。問題があれば、この Bolt で直すか後の Bolt に送るかを諮る。
