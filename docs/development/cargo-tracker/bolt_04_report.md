## 判断と学び

### 設計への反映（反映済み）

- D-10: ドメインモデルの用語集（業務番号、業務番号の採番、輸送条件の入力、提出の検証結果、貨物、荷姿）、Q-INV-12（期限の境界と数量の値）、Q-INV-13（業務番号を変えない・重複させない）、DE-01 の表示用の業務番号
- データモデル: 業務番号の列と一意制約、年ごとの採番の表（`number_year`。`year` は H2 の予約語）と採番の手順、KPI 計測記録の業務番号の列（null を許す）
- ユーザーストーリー: US-01 の決定（D-10、期限の境界、AC2 をこの Bolt でどう読むか）

- 手順書: 完了画面の UUID の負債の記述を消し、仮の荷受人の設定を書いた
- 前提の違い（R-09）: マイグレーションは「既存の行はない」前提で列を `NOT NULL` で足した（行があるのはローカルの H2 と Testcontainers だけで、どちらも起動のたびに作り直す。作り直しの手順は要らない）。一方、DE-01 と KPI 計測記録の業務番号は、イベントの進化の規則に従い「業務番号のない古いイベントがある」前提で null を許す。後者は、発行記録に残った未完了のイベントを再配信する場合に備えるためである

## レビューとクローズ

[Bolt 4 開発成果物レビュー](../../review/cargo-tracker/bolt_04_review_20261002.md) の指摘を、クローズの前に直した（R-01〜R-24。詳細はレビューの「対応結果」）。主なものは次のとおり。

- **時計に依存するテスト（R-01）**: 実際の時計で動くテストが固定の期限 `2026-11-02` の見本を使い、その日を過ぎると落ちる状態だった。見本の期限を 2099 年にした
- **他社の番号の照会（R-02）**: 完了画面は業務番号（連番）を URL のキーにしたのに荷主企業で絞っていなかった。リポジトリから画面まで荷主企業で絞り、他社の番号は見つからない（404）ようにした。認証（US-18）では主体を差し替えるだけで済む
- **採番の接続の枯渇（R-03、D-13）**: 起動時に今年と来年の年の行を用意し、接続のプールの大きさ（10）を超える 16 本の同時の採番でも止まらないことを確かめた。提出の中の別のトランザクションは、年をまたいで動き続けた場合の予備として残した
- **検証と変換の時間的結合（R-04）**: 輸送条件の入力の検証が、輸送条件か違反のどちらかを返す形にした
- **文言の網羅（R-06）**: 項目と理由のすべての組で文言を確かめるテストを足し、特殊貨物の文言が「直し方」で終わっていない（「（手動窓口）」で終わる）ことを見つけて直した

対応の後も、`check`（235 件）、`uiTest`（5 シナリオ）、CI（`a348f15`、`check`・`ui`）、SonarQube の品質ゲート（PASS、指摘 0 件、カバレッジ 98.1%）は緑。GitHub の #2 は、AC2 の必要書類が残るため開いたまま In Progress にし、進み具合をコメントした。
