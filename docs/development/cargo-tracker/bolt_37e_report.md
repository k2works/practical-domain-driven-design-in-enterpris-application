## 判断と学び

- 集約の値（`AssignedRoute`）に事実の写し（印）を持たせると、写す操作（再見積り）が増えずに済んだ。印を見積りの状態にしていたら、状態の組み合わせが倍になり、再見積りにも引き継ぎのコードが要った
- 照会し直しで正しさを守る設計は、永続化の層のキャッシュの振る舞いに頼ることになる。テストはメモリ上のリポジトリだけで、データベースの振る舞いはコードとレビューでしか確かめられなかった
- 開発レビューで、INSERT の経路だけが確かめられていないと分かった。変異は「自分が書いた分岐」から選びがちで、写しの列（保存の文）を落とす変異を計画に入れていなかった
