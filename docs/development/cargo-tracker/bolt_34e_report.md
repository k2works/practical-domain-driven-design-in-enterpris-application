## 判断と学び

- 「作り手を限る」だけでは「何を判定したか」までは守れない。不変の集約なら、判定した実体そのものを承認に持たせると、組み立てた別の実体も、変えた後の再利用も同じ確認で捕まえられる
- 判定した値の出どころを 1 つにするなら、版だけでなく、確定の後に使う値（監査・副作用）もすべて承認から取る。使わないデータを持つ承認は、どちらが正かの迷いを生む
- 型の引数を持つ sealed の拒否は、record ごとに型の引数を持たせ、パターンで網羅すれば、controller の届かない枝が消える

  - ステップ 3・4 をサブエージェントに任せ、その間に Gradle を流さなかったので、テストの結果のファイルがぶつからなかった（T-147）

  - サブエージェントがテストの件数を途中で数え、少なく報告した（後で数え直して同じと確かめた）
