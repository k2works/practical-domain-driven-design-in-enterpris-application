## 決定

(1) **URL**: 一覧 `GET /staff/service-cases`（絞り込みは `?filter=` の `open`（既定。未終結）・`unreceived`（未受領）・`overdue`（期限超過）・`in-progress`（対応中））、詳細 `GET /staff/service-cases/{受付番号}`、受領 `POST /staff/service-cases/{受付番号}/receive`（PRG で詳細へ戻り、結果を示す）。形式の誤った受付番号とない受付番号は 404。

(2) **認可**: `/staff/service-cases/**` は社内の運用役割（カスタマーサポート・営業担当者・経路設計者・追跡管理者・データ責任者。`ServiceCaseAuthorization` の `OPERATING_ROLES`、台帳 D-159）だけ。役割の集合は 1 か所（`ServiceCaseAuthorization`）に置き、`SecurityConfiguration` の URL の規則は同じ集合を並べる。システム管理者・監査担当者・荷主担当者は 403。担当企業の範囲は有人案件には掛けない（D-159: 社内の運用役割はどの案件も扱える）。

(3) **照会**: `ServiceCaseQueryService`（一覧・詳細）を足す。一覧の絞り込みは、リポジトリの `findByStatuses`（状態の集合と件数の上限）と既存の `findReceiptOverdue` で決め、期限超過かどうかは読むときの判定（`isReceiptOverdue`）で示す。上限は 200 件で、超えるときは「新しい 200 件だけ」ではなく「期限の古い 200 件だけを示しています」と示す。

(4) **S-14 の表示**: 受付番号（S-15 へのリンク）・種類・優先度・担当部門・状態（状態バッジ。文字とアイコンで示し、色だけにしない）・受領期限・期限超過の印を示す。**空のときは理由を示す**。

(5) **S-15 の表示**: 種類・状態・担当（受領者と受領時刻）・受領期限・回答期限・次回更新・復旧照合（外部停止だけ）・出典・進捗の履歴・回答の履歴。**受領のボタンは受付済み・上位対応中のときだけ**。進捗の更新・回答・終結・再開の操作は 40-12 で足す。

(6) **受領の結果の文**: 受領した「受付番号 を受領しました。対応中にしました。」、受領できない状態「この案件は受領できる状態ではありません（今の状態: …）。」、競合「ほかの更新が先にこの案件を変更しました。…」、権限なし 403。

(7) **ナビゲーション**: 運用役割の利用者に「有人案件」のリンクを出す。
