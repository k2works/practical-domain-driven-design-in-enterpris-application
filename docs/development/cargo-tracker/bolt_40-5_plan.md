## Bolt ゴール

`ServiceCase`（有人案件）が、US-20 の状態遷移（受付済み → 対応中 → 回答済み → 終結 → 再開、受領期限超過の上位対応中、重複終了）を不変条件つきで守る。永続化（40-6）・コマンド（40-7・40-8）・画面は含めない。

## 決定

(1) **置き場所**: 追跡コンテキスト（ドメインだけ）。集約 `aggregates.ServiceCase`、エンティティ `entities.CaseProgress`・`CaseAnswer`、値 `CaseNumber`・`ServiceCaseKind`・`ServiceCaseStatus`・`MissingItem`・`ServiceCaseDraft`。

(2) **不変の集約**: メソッドは新しい `ServiceCase` を返す（`TrackingRecord` と同じ流儀）。状態に合わない操作は `IllegalStateException`。業務上の拒否（必須項目の不足、復旧照合が未完了の終結）は結果の型で返す（40-7 の「必須項目の不足は引き継がず入力を保持」、40-8 の「不足する照合結果の表示」に使う）。

(3) **種類ごとの必須項目（仮。台帳 D-158）**: US-20 AC1 の「原因、担当、期限、旧版・新版、手動入力出典、顧客連絡、復旧照合」を、種類ごとに次の表で具体化した。文書に種類ごとの定めがなかったので私が置いた仮定で、業務責任者に確かめる（顧客連絡は表に列がないので、40-7 の入力で扱う）。

| 種類 | 必須の項目（共通の原因・担当部門に加えて） |
| :--- | :--- |
| `CUSTOMER_INQUIRY`・`QUOTATION_CONSULTATION` | 荷主企業 |
| `AMENDMENT`・`REDESIGN` | 予約か追跡番号、旧版、新版 |
| `EXTERNAL_OUTAGE` | 手動入力の出典。復旧照合は必須（種類で決まる） |
| `REJECTED_MILESTONE` | 追跡番号、参照した出典 1 つ以上 |
| `SAGA_FAILURE` | 予約 |

(4) **期限**: 起票で `ServiceDeadlines`（Bolt 40-4）を受け取る。受領期限・回答期限・次回更新日時はそれを写す。営業時間外の優先度高（数え始めが起票の時刻より後）は `acknowledgedAt` に起票の時刻を持つ（US-20 AC8。受付番号と次回更新日時を直ちに返した時刻）。

(5) **escalation**: 受領期限を過ぎた受付済みを上位対応中にする（`escalate(now)`。期限前・受付済みでないときは変えない）。期限の超過を読むときに判定するか定期処理で検出するかは 40-9 で決める。

(6) **再開**: 終結から対応中へ戻る。受付番号・進捗・過去の回答はそのまま持ち、顧客の回答（未解決）を最後の回答に記録する（SC-INV-03）。
