- 準備中の画面に予定の週は出さない。代わりに荷主には「使えるようになるまでは、担当営業にご連絡ください。」を示す。

- 発行から 8 時間を過ぎた session のままのログインの送信も A-03 へ移す。session に CSRF のトークンがない古いフォームの送信も A-03 へ移す（トークンが誤っていれば 403）。
- multipart の上限の超過の案内を `/error` の 413 の画面に移した（議題 5）。H2 のコンソールを外した（議題 4）。
- 開発用の設定の守りは `identity.devlogin` に置き、Flyway の設定の組み立てで動かす（開発用の利用者がマイグレーションで入る前に止める）。
- 無操作 30 分は `spring.session.timeout` で決める（D-50）。

  - 5 つの視点のレビューが、fail-open の 3 か所と、利用者の行き止まり（画面のない役割、A-04 の問い合わせ先）を独立に見つけた
  - 設定を確かめるテストを既定と違う値で書き直したことで、30 分が偶然成り立っていたことを見つけた
  - 骨組みを足して前提の失敗を本命の失敗に変えてから Red を記録できた（T-39）
- **Problem**:
  - 無操作 30 分の設定の鍵の誤りを、ステップ 3 の境界の 3 点のテストが見つけられなかった（既定の値と一致していた）
  - 失敗に倒すかどうか（属性・引数・役割の対応がないとき）を計画で決めず、レビューで初めて直した
  - 開発用の守りを、守る対象（マイグレーション）より後に動く部品にしていた
  - 人の承認ゲート（スキーマ・セキュリティ）を止めずに進め、承認を後でまとめて受けることになった（T-36 に従った）
- **Try**:
  - T-41: 設定の値で決まる振る舞いのテストは、既定と違う値で 1 本書く（既定と一致して偶然通らないように）（AI、すぐ）
