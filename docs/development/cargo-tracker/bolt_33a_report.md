## 判断と学び

- 人の決定の文言（「完了の前に」）と、実装の都合（方針の誤りで送り直せる）が食い違うことは、実装の途中では気づかず、開発レビューで 3 つの観点が別々に見つけた。決定を実装に移すときに、計画の決定の表を見直す
- 公開の URL の session に権限（password を設定できる）を置くときは、ログインと同じく session の ID を変える。計画と 2 つの整合性検証では出なかった
- 「コミットの後に行う」は、呼び出し側にトランザクションがないことに依存していた。テストが統合テストだけだと、Spring Session の `REQUIRES_NEW` のために順序を入れ替えても通る
