## 判断と学び

- 直接入れた事実は、集約の操作の守りも、別のコンテキストの時計も通らない。だれが順を守るかを書くと（T-162）、開発データでは「テストが守る」しかないことが分かり、守る行を表に置けた。開発レビューで、見積り側だけでなく経路設計の側と写しの一致も守る行が要ると分かった
- 変異の道具が「すべて落ちた」と返すときは、1 つを手で当てて同じ結果になるかを確かめる。道具の失敗（Gradle が起動しない）が、変異が落ちたように見えていた
- 書くだけで読まれない列への変異は、スモークテストで捕まえる対象ではない（等価な変異）。生き残った変異は、読む経路があるかを先に確かめる
