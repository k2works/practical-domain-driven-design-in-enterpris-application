## 判断と学び

- 要確認のような導ける状態は、スキーマに持たせる前に既存の記録から復元できるかを先に確かめる。今回はファイルの誤りの受信記録がファイル全体の原本のキーを持つことをコードで確かめ、列を足さずに済んだ
- 同じ判定を 2 か所（照会と画面）で持つと、片方にだけ当てた変異は mock の側で見えない。変異は判定の置き場所ごとに当てる

### ふりかえり（KPT）

- Keep: 整合性検証が、決めた名前が既存のクラスと重なることや、拒否の後に 0 件になる場合を着手前に見つけた。業務の判断を、推奨を 1 つに決めたうえで議題の先頭に置き、人が後から見直せる形にした
- Problem: 私が照会の値に決めた名前（`UnreadablePart`）が既存のクラスと重なっていた（コードで確かめずに決めた。T-239 の違反）。担当のサブエージェントが標準入力を待つ `python -` を 1 度流した（すぐに止め、影響はない。39b2 から続いた違反なしの記録が途切れた）
- Try: T-246: 新しい型の名前を決めるときは、同じコンテキストの中で同じ単純名のクラスがないかを検索してから決める

### 既知の課題（後に持ち込む）

- 描画を含む GET が 1.9 秒（10,000 件の隔離のうち 100 件を示す）。非機能要件はないが、初回のテンプレートのコンパイルを含むかを W10 の負荷テストで分ける
- 直した行を取り込み直すと採用になるか、新しい外部版で送り直すと採用になるかは、マニュアルに書いていない（39d の再送の扱いで決める）
- 39d: すべての隔離の一覧（S-17）、理由の符号を表の列で持つか、情報源の並びの規則
- 返済の候補: `transport-request-form.js` を見積依頼と S-16 で共用している
