## Bolt ゴール

顧客 Web と社内業務 Web のすべての画面が、共通レイアウト（ヘッダー、左ナビ、顧客 Web の窓口の案内）と Bootstrap 5.3 の部品で表示され、画面ごとに書いていたスタイルが共通の CSS に移る。荷主は見積依頼の作成と編集を、輸送条件・貨物・書類・確認の 4 段階で入力でき、キー操作だけで段階を行き来して提出できる。

## AI の仮定

- 段階の見出しは、段階の名前と番号を持つリストにし、現在の段階に `aria-current="step"` を付ける。前の段階の見出しはリンクにして戻れるようにする。
- 「次へ」で段階を移ったら、フォーカスを次の段階の見出しへ移す（支援技術に段階の変化を伝える）。
- 共通の CSS は Bootstrap の上書きを最小にし、24 CSS px の操作範囲、`scroll-padding`、表の横スクロールの囲み、長い語の折り返しだけを足す。
- 入口の一覧（`static/index.html`）はテンプレートにし、レイアウトを使わない（荷主と社内のどちらでもない入口のため）。Bootstrap の見た目だけをそろえる。

## リスクと対策

| リスク | 影響 | 対策 |
| :--- | :--- | :--- |
| Bootstrap の部品（ナビの畳み、フォームの部品）が axe-core の違反になる | 画面の層が赤になる | 既存のシナリオを安全網にして画面ごとに移し、違反が出た部品は Bootstrap の部品を使わず素の要素に戻す |
| 段階入力で既存の C-03 のシナリオ（キー操作の提出）の操作が変わる | シナリオの書き換えが増える | 期待する結果（C-04 に版 1、エラー要約）は変えず、段階を進める操作だけを足す |
| 段階入力と骨格を同じ Bolt に入れて半日を超える | Bolt が長引く | 打ち切りの線 1〜3 |
| Bootstrap と htmx の版の脆弱性 | 本番の依存の検査で止まる | 技術スタックの版を使い、本番の依存の検査（`check`）で確かめる |
