## 総合評価

人の決定は、日付と承認者付きで ADR・設計・要件に漏れなく反映された（architect、user-representative）。画面の層の 2 つのスイートの振り分け、シナリオごとのブラウザの分離、権限の否定側と肯定側のテスト、T-8 で見つけた検査の穴（Gradle の UP-TO-DATE）は高く評価された。

一方、次の 2 つが構造上の穴として挙がった。

- **最小権限の検証がない**: アプリ本体と他のテストは PostgreSQL の所有者（superuser）で接続している。アプリケーション利用者の権限で動くのは、権限テストが手書きした SQL だけである。Flyway とアプリの DB 利用者を分ける構成（DA-02 の手順 2）が、まだコードで表せていない。
- **保護が黙って外れうる（fail-open）**: 追記専用の表は名指しで `REVOKE` する。新しい表で書き忘れると、保護が黙って外れる。

あわせて、完了画面が内部の ID（UUID）を見せていることが、D-4（画面に UUID を出さない）と食い違っている。テストのコードの次の点も、シナリオが増える前に直すべきとされた。

- 静的に起動するブラウザ
- 読み直しを繰り返す待ちの書き方
- DOM の位置への依存
- Javadoc の解析
- axe の検査がステップの書き忘れで空振りすること

修正のうち、テストや実行で裏付けたもの:

- **R-01**: 画面の層をアプリケーション利用者で動かすと、Spring Modulith 2.1 が既定で起動時に `CREATE SCHEMA` を実行するため起動に失敗した。設定のメタデータの「既定 False」は、実際の挙動（`matchIfMissing = true`）と違っていた。自動初期化を無効にして、最小の権限で主要な流れが通るようにした。CI の `ui` ジョブでも緑
- **R-02**: 追記専用の印を外すと、表の集合の一致と更新・削除のテストが失敗した
- **R-06**: ラベルを外すと、違反を確かめるステップのない 320px のシナリオも、フックで失敗した
- **R-15**: `TransportRequestVersion`（エンティティ）も対象になり、用語集の「輸送要求版」と一致した
- **R-17**: `test` のスキップは 0 件になり、`uiTest` から業務ルール層のシナリオと ArchUnit が外れた
- **品質ゲート**: `check`（`test` 74 件、`documentationTest` 1 件）、`uiTest`、CI（`41ec8d2`）、SonarQube（PASS、Code Smell 0）はすべて緑
