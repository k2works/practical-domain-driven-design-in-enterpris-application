    cargo-tracker ユーザーストーリー¶

    契約¶

    • 各ストーリーは単独で観測できる利用者価値を表す。
    • 受入条件は Given / When / Then で判定し、未決の閾値や権限詳細を推測しない。
    • 要確認 を含む条件は、参照する OQ の承認後に具体値を補完する。
    • 優先度は初期パイロットの価値・事故防止・代替可否で判定する。Must はパイロット成立に不可欠、Should は本格展開前に必要、Could は荷主または有人窓口で代替可能な拡張とする。

    横断受入条件¶

    以下は US-01〜US-13、US-16〜US-20 の人が操作する画面・対話部分、および US-14・US-15 の手動取込・差異確認・復旧照合画面に適用する。バックグラウンド処理自体は操作条件の対象外とする。

    • Given キーボードだけを使用、When 主要業務フローを操作する、Then 全操作へ到達でき、現在のフォーカスを視覚的に識別できる。
    • Given 入力項目または状態を表示、When 利用者が内容を認識する、Then 明示ラベルがあり、状態やエラーを色だけで伝えない。
    • Given 入力エラー、When 検証に失敗する、Then 入力値を保持し、エラー要約、該当項目、理由、修正方法を示す。
    • Given 入力エラー、非同期更新、確認中への遷移、または有人案件の escalation、When 状態が変化する、Then 視覚表示とともに支援技術が認識できる方法で通知される。
    • Given 本予約確定、取消し、権限変更、実績訂正、荷受人への共有・取消し、When 実行を要求する、Then 対象、現在状態、変更内容、影響、実行者を示して明示的な確認を求める。
    • Given 操作が失敗または完了、When 結果を表示する、Then 回復可能なら取消しまたは再実行手段を示し、回復不能なら実行前にその旨を明記する。

    トレース: BR-13、NFR-ACCESS-01、OQ-07。本節では列挙した機能条件を判定し、WCAG 2.2 AA 全体の適合判定は UI 設計とテスト戦略で行う。

    U1 輸送要求・見積り¶

    US-01 輸送条件を提出する¶

    荷主として、必要な輸送条件を下書きして提出したい。営業担当者に正確な見積りを依頼するためだ。

    項目 内容
    優先度 Must
    トレース RQ-01、BUC-01、UC-01、BR-01、BR-03、KPI-01、H-5

    受入条件:

    • Given 必須条件がそろった自社の下書き、When 荷主が提出する、Then 新しい予約版が審査中となり提出者と時刻が記録される。
    • Given 必須条件が不足する下書き、When 荷主が提出する、Then 不足項目が示され下書きのまま保持される。
    • Given 別企業の荷主情報、When 利用者が提出する、Then 提出は拒否され確定済みデータは変更されない。
    • Given 危険物・冷凍貨物・その他特殊貨物、When MVP の輸送要求として提出する、Then 対象外であることが示され提出されず手動窓口が案内される。

    US-02 輸送条件を審査する¶

    営業担当者として、提出条件と必要書類を審査したい。見積り可能な案件だけを次へ進めるためだ。

    項目 内容
    優先度 Must
    トレース RQ-04、BUC-01、UC-02、BR-01、KPI-01、H-5

    受入条件:

    • Given 審査中の予約版、When 営業担当者が条件充足を判断する、Then 判断者・時刻・根拠が記録され見積り作成可能になる。
    • Given 書類または契約条件の不足、When 営業担当者が差し戻す、Then 理由と不足事項が記録され予約版が下書きになる。
    • Given 審査開始後に更新された予約版、When 古い版の審査を確定する、Then 確定は拒否され最新版の再審査が要求される。

    US-03 根拠付き見積りを提示する¶

    営業担当者として、料金根拠と有効期限を伴う見積りを提示したい。荷主が判断できるためだ。

    項目 内容
    優先度 Must
    トレース RQ-01、RQ-04、BUC-01、UC-03、BR-01、BR-10、KPI-01、H-1

    受入条件:

    • Given 審査済みの輸送要求版と料金根拠、When 営業担当者が見積りを確定する、Then UTC の時点で保存された有効期限が利用者のタイムゾーンと UTC offset を伴って表示される。
    • Given 料金根拠または有効期限の不足、When 営業担当者が提示する、Then 提示は拒否され不足項目が示される。
    • Given 予約確定の commit 時刻が見積有効期限と同時刻または後、When 予約確定に利用する、Then 利用は拒否され再見積りが必要と示される。
    • Given 失効または置換済みの見積り、When 再提示、承認、または予約確定に利用する、Then 操作は拒否され読取専用の旧版と新しい見積版の作成手順が示される。

    U6 予約管理¶

    US-04 予約を確定する¶

    荷主として、合意した見積りと承認済み経路で本予約を確定したい。追跡可能な輸送を開始するためだ。

    項目 内容
    優先度 Must
    トレース RQ-01、RQ-02、BUC-02、UC-04、BR-01、BR-03、BR-10、H-5

    受入条件:

    • Given 予約確定の commit 時刻が見積有効期限より前である見積り、必須貨物情報、荷主担当者 1 名の承認、承認済み経路版、When 営業担当者が BR-01 を確認して本予約を確定する、Then 有効な予約版、一意な追跡番号、commit 時刻が記録される。
    • Given 予約確定の commit 時刻が見積有効期限と同時刻または後、When 確定条件を検証する、Then 予約は確定されず見積りの失効と再見積りの必要性が示される。
    • Given 確定条件のいずれかが不足、When 確定する、Then 予約は確定されず不足条件が示される。
    • Given 同一の承認要求が再送される、When 確定処理する、Then 予約を重複生成せず既存の追跡番号が返される。
    • Given 危険物・冷凍貨物・その他特殊貨物を含む輸送要求、When 本予約を確定する、Then 確定は拒否され MVP 対象外であることと手動窓口が示される。

    MVP の決定: 荷主内の入力者・承認者は分離せず、荷主担当者 1 名の承認を受入条件とする。荷主内の職務分離は後続段階で再検討する。

    US-05 予約を変更・取消しする¶

    荷主として、事情の変化に応じて予約を変更または取消したい。現在の合意内容を正しく保つためだ。

    項目 内容
    優先度 Should
    トレース RQ-01、RQ-04、BUC-02、UC-05、BR-04、H-5

    受入条件:

    • Given 本予約前の輸送要求、When 荷主が条件を変更する、Then 承認を要さず旧版を保持した新しい輸送要求版が記録される。
    • Given 本予約前の輸送要求、When 荷主が取下げる、Then 承認を要さず理由を伴って取消済みになる。
    • Given 本予約後かつ集荷実績採用前、When 荷主が変更または取消しを申請する、Then 予約状態を変更せず営業承認待ちとして記録される。
    • Given 集荷前の変更申請を営業担当者が承認、When 料金または経路へ影響する、Then 旧版を保持した新しい予約版が変更中となり再見積り・荷主再承認または再設計の必要性が示される。
    • Given 集荷前の取消申請を営業担当者が承認、When 取消しを確定する、Then 理由と承認者を伴い取消済みになる。
    • Given 集荷実績が採用済み、When 通常の変更または取消しを申請する、Then 自動処理は拒否され要求と理由が記録され有人の例外対応へ引き継がれる。
    • Given 同じ予約を別利用者が先に更新済み、When 古い版から変更する、Then 上書きは拒否され最新版の確認が要求される。

    要確認: 変更・取消しの費用と申請期限は OQ-04 の残決定としてパイロット開始前に確定する。

    U2 経路設計¶

    US-06 経路候補を比較する¶

    経路設計者として、制約を満たす候補と除外理由を比較したい。根拠のある経路を選ぶためだ。

    項目 内容
    優先度 Must
    トレース RQ-02、RQ-06、BUC-03、UC-06、BR-02、BR-11、KPI-01、GR-01、H-9

    受入条件:

    • Given 見積り済み輸送要求と利用可能な航海・港湾情報、When 候補を算出する、Then 採用候補、除外候補、理由、情報鮮度を比較できる。
    • Given 到着予定時刻が希望到着期限より後、または接続時間が航路別の必要最小接続時間未満の候補、When 算出する、Then 候補から除外され不適合となった時刻、閾値、参照情報版が示される。
    • Given 到着予定時刻が希望到着期限と同時刻、かつ接続時間が必要最小接続時間と同値の候補、When 算出する、Then 日時制約を満たす候補として扱われる。
    • Given 外部情報源が停止中、When 候補を算出する、Then 最終採用値と取得時刻が示され情報不足として識別される。

    US-07 専門判断を伴う経路を確定する¶

    経路設計者として、例外条件の判断根拠を記録して経路を確定したい。規制と責任を追跡できるためだ。

    項目 内容
    優先度 Must
    トレース RQ-06、BUC-03、UC-07、BR-02、BR-11、GR-01、H-9

    受入条件:

    • Given 日時制約を満たす候補、When 権限を持つ設計者が根拠を記録して承認する、Then 承認 commit 時点で再検証され、根拠・承認者・commit 時刻・外部情報版を伴う経路版が確定する。
    • Given 判断根拠または専門家権限の不足、When 確定する、Then 確定は拒否され不足理由が示される。
    • Given 承認中に候補の情報版が更新済み、When 確定する、Then 承認は無効となり再判断が要求される。
    • Given 確定経路の外部情報が更新され日時制約を満たさなくなる、When 更新を評価する、Then 予約は自動取消しされず経路が再設計要となり旧情報版が保持される。
    • Given 旧版または再設計要の経路版、When 再確定または新規予約へ割り当てる、Then 操作は拒否され新しい経路版の作成が要求される。

    AI の仮定: US-07 が扱う専門判断は一般貨物の運用例外に限定する。危険物・冷凍貨物・その他特殊貨物の専門家承認は OQ-03 の後続決定まで本ストーリーへ含めない。

    US-08 経路を再設計する¶

    経路設計者として、欠航や条件変更時に未実行区間を再設計したい。輸送を継続しながら変更根拠を残すためだ。

    項目 内容
    優先度 Should
    トレース RQ-02、RQ-06、BUC-03、UC-08、BR-04、BR-11、KPI-05、H-5

    受入条件:

    • Given 確定経路と再設計原因、When 新候補を承認する、Then 新旧関係と変更根拠を伴う新経路版が予約へ割り当てられる。
    • Given 実行済み区間、When 再設計する、Then 実績は変更されず未実行区間だけが対象になる。
    • Given 外部情報更新により確定経路が再設計要、When 再設計を開始する、Then 予約を維持したまま参照した旧情報版と不適合理由が再設計条件として引き継がれる。
    • Given 実行可能な新候補がない、When 再設計する、Then 旧版と影響範囲が保持され手動の例外対応へ引き継がれる。

    U3 基本追跡¶

    US-09 荷主が輸送状態を照会する¶

    荷主として、予定と主要実績を自分で照会したい。問い合わせずに輸送状況を判断するためだ。

    項目 内容
    優先度 Must
    トレース RQ-03、BUC-04、UC-09、BR-07、KPI-02、KPI-03、H-4

    受入条件:

    • Given 自社に許可された予約、When 追跡番号で照会する、Then 現在状態、予定、主要実績、出典、取得時刻が表示される。
    • Given 予定と実績が矛盾する、When 照会する、Then 一方で上書きされず、判明事実、未確定事項、確認中、出典、次の行動、次回更新日時、担当窓口が表示される。
    • Given 外部情報源が停止中、When 照会する、Then 最終採用値、取得時刻、最新性を保証しない旨、次の行動、次回更新日時、担当窓口が表示される。

    US-10 荷受人が許可範囲を照会する¶

    荷受人として、荷主から許可された到着予定と主要実績を照会したい。受領準備を行うためだ。

    項目 内容
    優先度 Could
    トレース RQ-03、BUC-04、UC-09、BR-07、KPI-02、H-7

    受入条件:

    • Given 荷受人に予約単位の参照を許可、When 追跡番号で照会する、Then 到着予定、現在状態、主要実績、最終更新時刻だけが表示される。
    • Given 許可のない予約、When 荷受人が照会する、Then 貨物情報は開示されず試行が記録される。
    • Given 参照を許可された予約、When 荷受人が照会する、Then 料金、契約条件、書類、他の予約は表示されない。
    • Given 荷主担当者が参照許可を取消し済み、When 荷受人が既存 session で照会する、Then 対象予約は表示されず取消し後の試行が記録される。
    • Given 許可された予約が確認中または鮮度超過、When 荷受人が照会する、Then 開示範囲内の判明事実、未確定事項、次の行動、次回更新日時、担当窓口が表示される。

    MVP の決定: 開示範囲と予約単位の許可・取消しは BR-07 を適用する。

    US-11 顧客照会を引き継ぐ¶

    カスタマーサポートとして、顧客と同じ根拠の追跡情報を確認したい。正確に回答し、必要なら担当部門へ引き継ぐためだ。

    項目 内容
    優先度 Must
    トレース RQ-05、BUC-04、UC-09、UC-20、BR-07、BR-09、KPI-02、H-7

    受入条件:

    • Given 照会権限と対象顧客を確認済み、When 追跡番号を照会する、Then 顧客へ開示可能な情報と社内の確認状態が区別して示される。
    • Given 回答に必要な情報が確認中、When 担当部門へ引き継ぐ、Then 対象、照会内容、参照した出典、優先度、担当部門、回答期限、次回更新日時を持つ受付番号が発行される。
    • Given カスタマーサポート、When 予約の代理確定または変更を試みる、Then 操作は許可されない。

    AI の仮定: カスタマーサポートは照会・引継ぎだけを行い、予約を代理操作しない。

    US-20 照会・業務例外を回答・終結まで追跡する¶

    カスタマーサポートまたは業務担当者として、引き継いだ顧客照会・業務例外の担当受領、進捗、回答、復旧照合を追跡したい。顧客への約束と安全な手動代替を完了するためだ。

    項目 内容
    優先度 Must
    トレース RQ-03、RQ-05、RQ-08、BUC-02〜BUC-04、UC-05、UC-08、UC-15、UC-20、BR-09、BR-17、KPI-02、KPI-04、H-7

    受入条件:

    • Given 顧客照会または変更・取消し、再設計、外部停止の業務例外、When 担当者が引き継ぐ、Then 原因、担当、期限、必要な旧版・新版、手動入力出典、顧客連絡、復旧照合を持つ一意な受付番号が発行される。
    • Given 受付済み案件、When 担当者が受領する、Then 担当者と受領時刻が記録され状態が対応中になる。
    • Given 受領期限までに担当者が受領しない、When 期限を迎える、Then 上位の運用責任者へ escalation され依頼元へ担当未確定と次回更新日時が示される。
    • Given 対応中案件、When 担当者が進捗を更新する、Then 進捗、次回更新日時、更新者、更新時刻が記録され顧客へ共有できる。
    • Given 回答可能な案件、When 担当者が回答を記録しカスタマーサポートが顧客へ回答する、Then 顧客回答履歴を保持して終結する。
    • Given 終結済み案件で顧客が未解決と回答、When 再開する、Then 同じ受付番号と過去の回答履歴を保持して対応中へ戻る。
    • Given 復旧照合が未完了、When 担当者が終結を要求する、Then 終結は拒否され不足する照合結果が示される。

    US-12 主要実績を登録する¶

    追跡管理者として、出典を伴う主要実績を登録したい。現在状態を正しく更新するためだ。

    項目 内容
    優先度 Must
    トレース RQ-08、BUC-04、UC-10、BR-05、BR-06、KPI-03、GR-02、H-4

    受入条件:

    • Given 対象予約と重複しない主要実績、When 出典と発生時刻を指定して登録する、Then 実績が保存され現在状態が再評価される。
    • Given 同じ出典識別子の実績が登録済み、When 再登録する、Then 重複生成されず既存記録が示される。
    • Given 時系列に反する実績、When 登録する、Then 原本は保持されるが現在状態には直ちに反映されず確認中になる。
    • Given 取消済み予約、When 主要実績を登録する、Then 登録は拒否され発生事実が有人例外案件へ引き継がれる。
    • Given 完了済み追跡への遅延イベント、When 取り込む、Then 原本は保持されるが現在状態は自動で後退または再開しない。

    US-13 主要実績を訂正する¶

    追跡管理者として、誤った実績を理由付きで訂正したい。原記録を失わず正しい状態を共有するためだ。

    項目 内容
    優先度 Should
    トレース RQ-08、BUC-04、UC-10、BR-05、BR-06、BR-15、KPI-03、GR-02、H-5

    受入条件:

    • Given 誤りのある実績、When 理由を指定して訂正する、Then 原実績を削除せず新しい訂正記録が関連付けられる。
    • Given 訂正理由がない、When 訂正する、Then 訂正は拒否され原実績が維持される。
    • Given 採用済みまたは顧客表示済みの実績、When 追跡管理者が訂正を登録する、Then 登録者と異なる追跡管理者の承認待ちとなり採用値は変更されない。
    • Given 採用前の下書き実績、When 追跡管理者が修正する、Then 二者確認なしで修正され変更者と変更時刻が記録される。
    • Given 訂正登録者本人、When 自分の訂正を承認する、Then 承認は拒否され別の追跡管理者による確認が要求される。
    • Given 完了済み追跡の状態訂正、When 登録者と異なる追跡管理者が承認する、Then 原記録を保持した新しい訂正記録として反映される。

    U5 外部データ¶

    US-14 外部原本を安全に取り込む¶

    データ責任者として、外部原本を重複なく取り込みたい。出典と採否を追跡できる情報を業務へ提供するためだ。

    項目 内容
    優先度 Must
    トレース RQ-06、RQ-08、BUC-03、BUC-04、UC-15、BR-08、BR-12、BR-18、KPI-03、GR-02、H-6

    受入条件:

    • Given 選定した運送会社または港湾から受領した承認済みファイル、When データ責任者が手動取込する、Then 原本、提供元、原本種別、外部 ID、外部版、payload、取得時刻、採用値、取込履歴が関連付けて保存される。
    • Given 選定・承認済みの対象情報源が 0 件、When パイロット開始可否を判定する、Then 開始は拒否され情報源の選定と承認が要求される。
    • Given 同一の提供元・原本種別・外部 ID・外部版かつ同一 payload の再送、When 取り込む、Then 重複として記録され採用値を重複生成せず既存結果が返される。
    • Given 同一の提供元・原本種別・外部 ID・外部版で異なる payload、When 取り込む、Then 既存原本と採用値を上書きせず隔離されデータ責任者へ示される。
    • Given 順序逆転または既存値との矛盾、When 取り込む、Then 自動上書きせず差異としてデータ責任者へ示される。

    US-15 外部連携停止から復旧する¶

    データ責任者として、外部連携停止中も根拠付きの手動情報を扱い、復旧後に照合したい。追跡を止めず整合性を回復するためだ。

    項目 内容
    優先度 Should
    トレース RQ-06、RQ-08、BUC-03、BUC-04、UC-15、BR-08、BR-12、KPI-03、GR-02、H-6

    受入条件:

    • Given 外部連携が停止中、When 手動情報を登録する、Then 出典、入力者、入力時刻、仮状態が必須となる。
    • Given 外部接続が timeout、When 取得に失敗する、Then 失敗と取得時刻が記録され間隔を空けて再実行できる。
    • Given 連携が復旧、When 復旧照合する、Then 停止期間の全原本が採用済み・重複・隔離に分類され、受信件数との照合と手動情報との差異が一覧化される。
    • Given 停止期間の全原本が分類済み、When 受信件数が一致して手動情報との差異確認が完了する、Then 復旧照合が完了となり完了時刻と確認者が記録される。

    要確認: timeout、再送間隔、復旧目標は OQ-05 と後続の非機能要件で確定する。

    U4 アクセス・監査¶

    US-18 本人として認証される¶

    利用者として、自分が本人であることを安全に確認してほしい。許可された業務だけを自分の責任で開始するためだ。

    項目 内容
    優先度 Must
    トレース RQ-11、UC-18、UC-16、UC-17、BR-14、BR-15、OQ-07、H-8

    受入条件:

    • Given 有効な企業に所属する事前登録利用者、When 正しいメールアドレス、password、TOTP を提示する、Then 無操作 30 分・最長 8 時間の本人確認済み session が発行され利用者・企業・認証時刻が記録される。
    • Given 誤った認証情報、When 認証を試みる、Then 業務機能へのアクセスは許可されず、利用者の存在や失敗箇所を第三者が推測できる詳細は表示されない。
    • Given password または TOTP の認証が 5 回連続で失敗、When 5 回目の失敗を記録する、Then その時点から 15 分間ロックされ追加試行が拒否される。
    • Given 利用停止済みまたは所属企業が無効な利用者、When 正しい認証情報を提示する、Then session は発行されず認証失敗が監査証跡へ記録される。
    • Given session が無操作 30 分または発行後 8 時間を迎える、When 次の request を行う、Then 業務データを開示せず再認証が要求される。
    • Given 利用停止または権限取消しが確定済み、When 既存 session から次の request を行う、Then 取消した権限による業務データを開示せず再認証または管理者への確認が要求される。

    要確認: password 強度・回復、TOTP の登録・再登録手順は NFR-AUTH-01 と後続のアーキテクチャで確定する。

    US-19 荷受人の参照許可を管理する¶

    荷主担当者として、予約単位で荷受人を追跡へ招待し、必要に応じて許可を取り消したい。取引に必要な情報だけを安全に共有するためだ。

    項目 内容
    優先度 Could
    トレース RQ-03、RQ-11、BUC-04、UC-09、UC-19、BR-07、OQ-07、H-7

    受入条件:

    • Given 荷主担当者が共有権限を持つ本予約、When 予約の荷受人を指定して招待する、Then 予約単位の招待が発行され開示項目と有効期間が示される。
    • Given 招待された荷受人が本人として認証済み、When 招待を受諾する、Then 当該予約の到着予定、現在状態、主要実績、最終更新時刻だけを参照できる。
    • Given 指定先が予約の荷受人と一致しない、When 招待する、Then 招待は発行されず予約情報は開示されない。
    • Given 有効な参照許可、When 荷主担当者が引渡し完了までに取消す、Then 取消し直後から既存 session でも当該予約を参照できない。
    • Given 同じ予約・荷受人への有効な招待または許可、When 再度招待する、Then 重複発行されず既存状態が示される。

    US-16 利用者と権限を管理する¶

    システム管理者として、企業と利用者へ業務上必要な役割だけを付与したい。企業間分離と職務分離を守るためだ。

    項目 内容
    優先度 Must
    トレース RQ-11、UC-16、BR-07、BR-14、BR-15、H-7、H-8

    受入条件:

    • Given 管理対象企業の利用者、When BR-15 の固定役割を付与する、Then 企業・利用者・役割・担当案件の関係と変更履歴が記録される。
    • Given 管理範囲外の企業、When 権限を変更する、Then 操作は拒否され試行が記録される。
    • Given システム管理者または監査担当者、When 業務データを変更できる役割を併用する、Then 付与は拒否され競合する役割が示される。
    • Given 業務担当者、When 担当企業・担当案件以外を操作する、Then 操作は拒否され試行が記録される。
    • Given 利用終了または権限取消し、When アクセス変更を確定する、Then 次の request から拒否され過去の操作履歴は保持される。

    パイロットの決定: 役割、操作範囲、職務分離は BR-15 の役割 × 操作表を正とする。全社展開時の拡張規則は OQ-07 の残項目とする。

    US-17 監査証跡を照会する¶

    管理・コンプライアンス担当者として、重要操作の主体と結果を時系列で照会したい。変更と承認の正当性を検証するためだ。

    項目 内容
    優先度 Should
    トレース RQ-11、UC-17、BR-05、BR-06、H-8

    受入条件:

    • Given 監査対象範囲の権限、When 対象と期間を指定する、Then 操作、承認、変更、訂正の主体・時刻・対象・結果が時系列で示される。
    • Given 権限外の対象、When 照会する、Then 情報は開示されず照会試行が記録される。
    • Given 関連証跡の欠落、When 照会する、Then 欠落が異常として示され調査対象になる。

    要確認: 証跡の保持期間と監査担当の範囲は OQ-07 で確定する。

    ストーリー横断の AI の仮定¶

    • KPI とガードレールの目標値は未承認であるため、受入条件には機能的な測定可能性だけを記述する。
    • H-1〜H-10 は独立したリスク ID ではないため、関連する戦略レビュー指摘としてトレースする。
    • 第 2・第 3 段階の UC-11〜UC-14 は MVP ストーリーに含めず、MVP では手動引継ぎと境界だけを受入条件に含める。
