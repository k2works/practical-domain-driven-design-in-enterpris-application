Bolt 37d2 のレビュー（2026-10-22）で指摘したこと。

- 行 9（再設計要は評価しない）の単体テストは「解消した航海」しか渡さず、ガードを外す変異を単体では落とせない（受入 (d) の件数だけが守り）。まだ不適合の航海で確かめる形を勧めた
- 受入 (d) の 2 度目の評価は時計を進めないので、記録の上書きを時刻で見分けられない
- 入力ポートのテストは操作者 null を渡すことを確かめていない。競合は常に投げる stub で、計画の「版を進める」と違う
- test_strategy の AC4 の行が `RoutingCaseTest` と書くが実体は `RoutingCaseEvaluationTest`
- 画面の「再設計は後の版で行います」が「版」の 3 つ目の意味（ソフトの版）になる。S-04 の前例「今後の更新で入れます」と次の行動（担当営業に連絡）を勧めた
- 候補の「✓ 適合」「期限まで 2 日」が再設計要と並んで残る。ui_design の salt（理由を dl の行、「適合（確定のとき）」、状態の行）と実装がずれる

**Why:** 状態の組み合わせの表（T-163）の行ごとのテストでも、入力の選び方次第で変異を見逃すことがある。
**How to apply:** 「何もしない」行のテストは、ガードを外したら結果が変わる入力（まだ不適合）を選んでいるかを確かめる。関連: [[project-bolt37-route-boundary-tests]]
