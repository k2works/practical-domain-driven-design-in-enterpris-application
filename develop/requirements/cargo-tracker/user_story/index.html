    cargo-tracker ユーザーストーリー¶

    契約¶

    • 各ストーリーは単独で観測できる利用者価値を表す。
    • 受入条件は Given / When / Then で判定し、未決の閾値や権限詳細を推測しない。
    • 要確認 を含む条件は、参照する OQ の承認後に具体値を補完する。
    • 優先度は初期パイロットの価値・事故防止・代替可否で判定する。Must はパイロット成立に不可欠、Should は本格展開前に必要、Could は荷主または有人窓口で代替可能な拡張とする。

    横断受入条件¶

    以下は US-01〜US-13、US-16〜US-20 の人が操作する画面・対話部分、および US-14・US-15 の手動取込・差異確認・復旧照合画面に適用する。バックグラウンド処理自体は操作条件の対象外とする。

    • Given キーボードだけを使用、When 主要業務フローを操作する、Then 全操作へ到達でき、現在のフォーカスを視覚的に識別できる。
    • Given 入力項目または状態を表示、When 利用者が内容を認識する、Then 明示ラベルがあり、状態やエラーを色だけで伝えない。
    • Given 入力エラー、When 検証に失敗する、Then 入力値を保持し、エラー要約、該当項目、理由、修正方法を示す。
    • Given 入力エラー、非同期更新、確認中への遷移、または有人案件の escalation、When 状態が変化する、Then 視覚表示とともに支援技術が認識できる方法で通知される。
    • Given 本予約確定、取消し、権限変更、実績訂正、荷受人への共有・取消し、When 実行を要求する、Then 対象、現在状態、変更内容、影響、実行者を示して明示的な確認を求める。
    • Given 操作が失敗または完了、When 結果を表示する、Then 回復可能なら取消しまたは再実行手段を示し、回復不能なら実行前にその旨を明記する。
    • Given 無操作による session の失効が近い、When 失効の一定時間前になる、Then 失効の予告と延長の手段が示され、失効した場合も未保存の入力は失われず再認証後に再開できる。

    トレース: BR-13、BR-14、NFR-ACCESS-01、OQ-07、WCAG 2.2.1。本節では列挙した機能条件を判定し、WCAG 2.2 AA 全体の適合判定は UI 設計とテスト戦略で行う。

    U1 輸送要求・見積り¶

    US-01 輸送条件を提出する¶

    荷主として、必要な輸送条件を下書きして提出したい。営業担当者に正確な見積りを依頼するためだ。

    項目 内容
    優先度 Must
    トレース RQ-01、BUC-01、UC-01、BR-01、BR-03、KPI-01、H-5

    受入条件:

    • Given 必須条件がそろった自社の下書き、When 荷主が提出する、Then 新しい輸送要求版が審査中となり提出者と時刻が記録され、業務番号が示される（D-4）。
    • Given 必須条件が不足する、または出発地と目的地が同じ下書き、When 荷主が提出する、Then 不足項目と誤り（それぞれの理由と直し方）が示され下書きのまま保持される（D-6）。
    • Given 別企業の荷主情報、When 利用者が提出する、Then 提出は拒否され確定済みデータは変更されない。
    • Given 危険物・冷凍貨物・その他特殊貨物、When MVP の輸送要求として提出する、Then 対象外であることが示され提出されず手動窓口が案内される。
    • Given 自社の過去の輸送要求、When 荷主が複製する、Then 輸送条件を引き継いだ新しい下書きが作られ、希望到着期限と必要書類は再入力が求められる。

    決定（2026-10-02）: 出発地と目的地が同じ輸送要求は誤りとして AC2 で扱う（D-6）。荷主と社内に見せる番号は業務番号 TR-年-年ごとの連番 とし、内部の ID（UUID）は画面に出さない（D-4）。

    決定（2026-10-02、Bolt 4 の開始準備）:

    • 業務番号は初回の提出時に 1 回だけ振り、年は提出時刻の日本時間の年とする。年ごとの連番は 4 桁のゼロ埋めで、9999 を超えたら桁を増やす。欠番を出さない（D-10）。
    • 希望到着期限が提出時刻以前（同時刻を含む）なら AC2 の誤りとする。提出時刻より後なら近い期限でも受け付ける。間に合うかは経路設計（BR-11）で判定する。
    • AC2 の「下書きのまま保持される」は、R1.0 で下書きを保存するまで、入力を残して同じ画面を表示することで満たす。必要書類の扱いは、下の 2026-10-03 の決定（D-20）で必須条件に入れないことにした。

    決定（2026-10-03、Bolt 7 の開始準備。D-20）:

    • 必要書類は、提出の段階では任意で添付できる（インボイス・パッキングリストは見積りの段階では確定していないことが多いため）。書類が足りなければ、営業担当者が審査で差し戻す（US-02）。AC1・AC2 の「必須条件」に必要書類は含めない。
    • 添付できるのは PDF・PNG・JPEG で、1 件 10 MB まで、1 つの版に 5 件まで（商業送り状 1 件、梱包明細 1 件、その他 3 件まで）。形式・容量・件数の誤りは AC2 の誤りとして示し、提出しない。
    • 添付した書類を開けるのは、提出した荷主（荷主企業で絞る）と営業担当者だけ。荷受人・経路設計者への開示は US-10・US-06 で決める。
    • 出し直し（US-02）では、前の版の書類を引き継ぐ。ある種類の書類を 1 件でも選ぶと、その種類の前の版の書類はすべて引き継がず、選んだ書類に差し替える。選ばなかった種類は引き継ぐ。前の版の書類の行は変えない（2026-10-05 の決定。D-25、Bolt 9）。
    • 「その他」の書類も同じで、前の版のその他を残して足したいときは、残したいものも選び直す。新しい版の書類番号は 1 から振り直す。書類ごとの削除（どの種類も選ばずに外す）は入れない。
    • 複製で書類を再提出させるかは、AC5（R1.0）で Q-INV-11 のとおり「引き継がない」とする。

    US-02 輸送条件を審査する¶

    営業担当者として、提出条件と必要書類を審査したい。見積り可能な案件だけを次へ進めるためだ。

    項目 内容
    優先度 Must
    トレース RQ-04、BUC-01、UC-02、BR-01、KPI-01、H-5

    受入条件:

    • Given 審査中の輸送要求版、When 営業担当者が条件充足を判断する、Then 判断者・時刻・根拠が記録され見積り作成可能になる。
    • Given 書類または契約条件の不足、When 営業担当者が差し戻す、Then 理由と不足事項が記録され輸送要求版が下書きになる。
    • Given 審査開始後に更新された輸送要求版、When 古い版の審査を確定する、Then 確定は拒否され最新版の再審査が要求される。

    決定（2026-10-02、Bolt 5 の開始準備）:

    • 審査の判断者は、認証（US-18）ができるまで、設定の仮の営業担当者で記録する。
    • 確定の根拠と差戻しの理由は必須、不足事項は任意で、どれも自由記述（4,000 文字まで）。
    • AC3 の「審査開始後に更新された輸送要求版」は、差戻しの後に荷主が再提出した新しい版を指す。荷主が差戻し理由を見て直し出し直す画面は、Bolt 5 の次の Bolt で作る。

    決定（2026-10-03、Bolt 6 の開始準備。Bolt 5 レビュー D-24）:

    • 差戻しは荷主の画面（見積依頼の一覧と詳細）で見えるだけにする。メールなどで荷主へ知らせる運用は置かない（通知は US-22）。
    • MVP では出し直しの期限を設けない。不足事項は自由記述のままにする。
    • 仮の営業担当者の記録は監査に使えないことを承知のうえで進める（US-18・US-16 の後に本人の記録へ切り替える）。
    • 荷主に見せる審査記録は、直近の差戻しの理由と不足事項だけにする。審査の確定の根拠と判断者は社内の記録として見せない。
    • 荷主は自社の輸送要求だけを一覧・照会・編集・再提出できる。他社の業務番号は存在しないものとして扱う（Q-INV-08）。

    US-03 根拠付き見積りを提示する¶

    営業担当者として、料金根拠と有効期限を伴う見積りを提示したい。荷主が判断できるためだ。

    項目 内容
    優先度 Must
    トレース RQ-01、RQ-04、BUC-01、UC-03、BR-01、BR-10、KPI-01、H-1

    受入条件:

    • Given 審査済みの輸送要求版と料金根拠、When 営業担当者が見積りを確定する、Then UTC の時点で保存された有効期限が利用者のタイムゾーンと UTC offset を伴って表示される。
    • Given 見積りを提示する、When 荷主が内容を確認する、Then 料金根拠と有効期限に加えて、想定する経路方針（主な経由地、概算の日程）と、詳細な経路は経路設計者の承認後に確定する旨が示される。
    • Given 料金根拠または有効期限の不足、When 営業担当者が提示する、Then 提示は拒否され不足項目が示される。
    • Given 予約確定の commit 時刻が見積有効期限と同時刻または後、When 予約確定に利用する、Then 利用は拒否され再見積りが必要と示される。
    • Given 失効または置換済みの見積り、When 再提示、承認、または予約確定に利用する、Then 操作は拒否され読取専用の旧版と新しい見積版の作成手順が示される。

    決定（2026-10-05、Bolt 10 の開始準備。human:kakimomokuri）:

    • US-03 は 2 つの Bolt で作る。Bolt 10 は提示（AC1〜AC3）、Bolt 11 は失効・置換（AC4・AC5）。
    • AC1 の「見積りを確定する」は、算出した見積りを社内承認して提示することとする。社内承認者は、認証（US-18）ができるまで設定の仮の営業担当者で記録する。作成者と承認者を分ける職務分離は入れない。
    • 料金根拠は明細で、1〜10 行。各行は内容（200 文字まで）・金額（0 より大きい、小数点以下 2 桁まで）・参照した契約条件（任意、200 文字まで）。通貨は見積りに 1 つで、USD・EUR・JPY から選ぶ。合計は明細の和（明細の数と通貨の候補は 2026-10-06 に決定。D-36-1・D-36-2）。
    • 有効期限は営業担当者が日本時間の日時で入れ、UTC の時点で保存する。算出の時刻と同じか前なら AC3 の誤りとする。
    • 経路方針は、主な経由地（UN/LOCODE、0〜5 件）と、概算の出発日時・到着日時（必須。到着は出発より後）。
    • 1 つの輸送要求に、作成中・承認待ち・提示済みの見積りは 1 つだけ。置換（AC5）は Bolt 11 で入れる。

    決定（2026-10-05、Bolt 11 の開始準備。human:kakimomokuri）:

    US-18 本人として認証される¶

    利用者として、自分が本人であることを安全に確認してほしい。許可された業務だけを自分の責任で開始するためだ。

    優先度 Must
    トレース RQ-11、UC-18、UC-16、UC-17、BR-14、BR-15、OQ-07、H-8

    • Given 誤った認証情報、When 認証を試みる、Then 業務機能へのアクセスは許可されず、利用者の存在や失敗箇所を第三者が推測できる詳細は表示されない。
    • Given password または TOTP の認証が 5 回連続で失敗、When 5 回目の失敗を記録する、Then その時点から 15 分間ロックされ追加試行が拒否される。
    • Given 利用停止済みまたは所属企業が無効な利用者、When 正しい認証情報を提示する、Then session は発行されず認証失敗が監査証跡へ記録される。
    • Given session が無操作 30 分または発行後 8 時間を迎える、When 次の request を行う、Then 業務データを開示せず再認証が要求される。

    • Given 利用停止または権限取消しが確定済み、When 既存 session から次の request を行う、Then 取消した権限による業務データを開示せず再認証または管理者への確認が要求される。

    • Given 初回ログインの利用者、When password を確認した後、Then TOTP の登録が求められ、登録時に一度だけ使える回復コードが発行される。

    • Given password を忘れた利用者、When 再設定を依頼する、Then 登録メールアドレスへ 1 回だけ使える期限付きの再設定リンクが送られ、再設定後も TOTP の提示が必要となり、再設定が監査証跡へ記録される。
    • Given TOTP の端末を失った利用者、When 回復コードを使う、またはシステム管理者が定めた別経路で本人確認して登録を解除する、Then TOTP を再登録でき、解除が監査証跡へ記録され本人へ通知される。

    • Release 0.1 の #6（AC2）に加え、Release 1.0 の #13 から AC1 の password と session の部分、AC4、AC5 を Bolt 14 で前倒しして作る。AC1 の TOTP、AC3（ロック）、AC6（権限の取消し）、初回の TOTP の登録、password の再設定、TOTP の再登録、失効 5 分前の警告は W5 に残す。
    • AC1 の「利用者・企業・認証時刻が記録される」は、session に置く認証時刻と、監査記録のログインの成功で満たす。
