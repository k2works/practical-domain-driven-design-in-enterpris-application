    2. 【業務の判断】(y) 「古くなった候補」に入れるのは、候補の区間が今の航海と一致しない（航海がないときも）候補と、適合の候補の航海の情報が取得から許容時間を過ぎた候補だけとする。接続時間規則の変更と最初の区間の出発済みは入れず、確定のときの拒否（NO_LONGER_CONFORMING・ALREADY_DEPARTED）のままにする（決定 (2)、行 1〜12。台帳 D-112（仮））: 受け入れること: 算出の後に規則が変わった候補や出発済みの候補は S-06 で適合と示される。受入条件との突き合わせ: UC-06 4a の「候補の根拠となる情報」には接続時間規則も読めるが、release_plan :974 の範囲外である。出発済みは S-07 で拒否と理由を示す（今のまま）。業務責任者に確かめる（D-112。Release 1.0 のパイロットの前）。比べた案: (i) 航海の一致と鮮度だけ（推奨）、(ii) 規則と出発済みも含める（release_plan :974 の範囲を広げる）
    3. 【業務の判断】(z) 除外の候補は、区間が今の航海と合わないときは「古くなった候補」と示し、取得から許容時間を過ぎただけのときは示さない（決定 (2)、行 10・10b・22。台帳 D-113（仮））: 除外の候補はもともと確定できないが、航海が変わると除外の理由が今も当てはまるか分からない。鮮度だけのときに示すと、情報不足で除外した直後の候補に、再算出を促す文が出る（再算出しても同じ結果で、取込の依頼が先。マニュアル 8.2 :91）。release_plan :974 と Bolt 39f の :78 の「取得から許容時間を過ぎた候補も同じ」を適合の候補に絞る。受け入れること: 書き方違いの採用で取得時刻だけ新しくなると、情報不足で除外した候補に何も出ない（再算出すると適合に変わりうるが、S-06 では分からない）。受入条件との突き合わせ: US-06 AC2 の除外の理由の表示は変えない。比べた案: (i) 不一致だけ示す（推奨）、(ii) 除外の候補には何も示さない（変わった航海による除外を今も正しいと読み違える）、(iii) 適合と同じに鮮度でも示す（再算出で変わらない候補に促す文が出る）
