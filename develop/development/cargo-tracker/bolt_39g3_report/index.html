    Bolt 39g3 終了報告 - 採用した実績で最新の到着見込みを動かし、最終取得時刻を示す¶

    承認の議題（T-36。先に確かめてほしいこと）¶

    追跡管理者が予定より遅れた出発・積替の実績を登録または採用すると、最新の到着見込みが遅れの分だけ後ろに動き、最後の区間の揚地での到着を採用すると見込みはその時刻になるようにしました（規則 LatestEstimateRule。【業務の判断】(an)・(ao)）。当初の到着予定は変わりません（T-INV-10）。最終取得時刻は採用の実績の出典の取得時刻のうち最も新しいもの（(ap)）で、S-11 の列、S-12 と C-10 の照会の結果に示します。保存の UPDATE が latest_eta・last_acquired_at を書きます。スキーマ・認可・外部連携は変えていません。計画の確認ポイント 1〜7 は承認済み（2026-11-11）のとおりに実装しました。

    # 確かめてほしいこと 推奨 見る場所

    判断と学び¶

    • 見込みと最終取得時刻を現在状態と同じところで導くと、「採用の実績が変わったときだけ動く」が型の外に出ず、DE-13 と保持のみの経路を個別に守らなくて済む（行 11・13）
    • 導出しない経路があるときは、変異のテストの組で「その経路の後に導出が走る」手順を入れないと、導出の中の条件の変異が生き残る（M6）
    • 画面の層の航海は遠い未来なので、遅れの実績は今より後になり手入力で登録できない。前提で予定をずらすと、固定の日付を実の時計と比べずに遅れを示せる
    • SonarQube はテストのラムダの中の複数の呼び出しを違反にする。引数を先に作ってからラムダに入れる
