    Bolt 38 終了報告 - S-20 の前の直し（エラー要約の形とフォーカス、役割の確定の版の解釈の順、Section の足し方）¶

    承認の議題（T-36。先に確かめてほしいこと）¶

    S-20 の利用者の詳細のエラー要約を共通部品と同じ形にし、役割の確定の POST の版を範囲の判定の後に解釈するようにし、詳細に操作を足す手順を決めました（Bolt 34f の開発レビューの指摘 8・9 と #50 の H1）。

    # 確かめてほしいこと 見る場所
    1 エラー要約の形。要約へフォーカスが移り（transport-request-form.js を読む）、選び方の誤りのリンクは「付ける役割: 役割を 1 つ以上選んでください。」「停止の理由: 利用終了・異動・緊急停止のどれかを選んでください。」で、群の最初の選択肢へ向かう。誤りのある群の fieldset に aria-invalid="true"。欄を描かない利用者（荷受人の企業の利用者など）への拒否は、表示名を付けずにリンクしない 11-role-change-rejected.png、detail.html
    2 見える文言の変更。停止の理由の誤りを「停止の理由を選んでください。」から「利用終了・異動・緊急停止のどれかを選んでください。」にした（開始準備の決定 (4)。共通部品の規則「文言は表示名で始めない」） マニュアル 11 章、ui_design の拒否の文言の表
    3 役割の確定の POST の順（セキュリティ）。管理範囲の外の利用者へ数でない版や版なしを送ると、今までの 400 でなく 404 になり、範囲外の試行が記録に残る（利用状態の確定と同じ順） UserRoleChangeController、行 5 のテスト
    4 詳細に操作を足す手順（38c の「ログインの資格」が最初の利用）。Section の 1 つの値が 1 つの操作（見出しと、選び方の誤りの欄の表示名）、Fields に欄を描くか、anchor の switch にリンク先、テンプレートに領域、controller は Operation を渡す UserDetailPage の Javadoc、architecture_backend の S-20 の画面の構造

    計画は 2026-10-25 に承認を受けた（807d072ed）。計画から変えたのは、開発レビューの指摘で次を足したこと: 行 4c（自分の詳細への選び方の誤り。サービスを mock）、古い版の拒否がリンクせず誤りの印を付けないことの確かめ（変異 V7）、要約の中のリンクの陽性の対照、スクリプトを読むことの MockMvc の確かめ、行 4・4b の出口、行 5 でサービスを呼ばないこと。ErrorSummary から読まれない部品（誤り）を外し、anchor に描く選択肢だけを渡す形にした。

    Red の確かめ¶

    テスト 落ちた理由（中身を作る前）
    行 1・2（MockMvc） リンクの文に表示名がなく、リンク先が fieldset（#roles・#suspension-reason）、aria-invalid がない、停止の理由の文言が古い
    行 4・4b 欄のない利用者への拒否で要約にリンクがある、文言が古い
    行 5 数でない版・版なしが範囲の判定より先に 400 になり、試行が記録されない
    停止の理由の文言のテスト 文言が古い
    行 6・7（画面の層） 要約にフォーカスがない、文言が古い
    行 3 今の実装で緑のまま（陰性の対照）

    判断と学び¶

    • fieldset はフォーカスを受けないので、群の誤りのリンクは最初の選択肢へ向ける。リンクの先への移動はスクリプトでなくブラウザの素の動きで、スクリプトが受け持つのは要約へのフォーカスだけ
    • 欄を描く条件と、リンク先を決める条件は 1 か所にする（テンプレートと Java に分かれると、ない欄へリンクする形に戻る）
    • 変異の道具が改行を変えると、spotlessJavaCheck がファイル全体の差分で落ちる。Bolt 37f3 の 1 回目の check の原因の分からない失敗も同じだったと見られる（ログを残していたので分かった。T-199 の効果）

    ふりかえり（KPT）¶

    • Keep: 2 つの整合性検証で、誤りのキャプチャの見落とし、スクリプトの受け持ちの思い違い、共通部品の文言の規則を計画の段階で直せた。変異を MockMvc と画面の層で分けて確かめた
    • Problem: 変異の戻しで改行を変え、品質ゲートをやり直した。変異 V6 の作り方が粗く（スクリプトの行を消す）、確かめたい振る舞いと違う理由で落ちた。止まっていない変異のテストを、時刻の読み違いで止めた
    • Try:
    • T-200: 変異の道具はファイルをバイトのまま読み書きする（改行を変えない）
    • T-201: 変異は、確かめたい振る舞いだけが変わる最小の形にする（全件が落ちたら、変異を替える。T-187 の言い直し）
    • T-202: 実行中の処理が止まっているかは、プロセスの開始時刻と今の時刻をシェルで比べてから決める
