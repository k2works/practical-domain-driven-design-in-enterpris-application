    仮説の結論¶

    # 仮説 結論
    H1 確定の再検証を ConstraintEvaluator を確定の時刻で呼び直すだけで作れれば、AC3 は参照情報版の比較を足すだけで済む 成り立った。ConstraintEvaluator は 0 か所の変更。ただし AC3 では、航海の情報版の照合も同じトランザクションで行う必要があり、案件の楽観ロックだけでは航海の更新との競合を検知できない（レビュー D-72、architect の低）
    H2 経路版を一覧で持つ形に変えても、Bolt 17 のテストは振る舞いを変えずに通る ほぼ成り立った。書き換えた Bolt 17 のテストは 2 件（確定の記録のない「確定」を作れなくなったための状態の例と、算出の競合の文言の統一）と、テストの補助（インメモリのリポジトリ、コマンドの引数）。振り分けの振る舞いの変更はない
    H3 DE-05 を routing :: events に置けば、見積りの割当ては購読を足すだけで作れる 成り立たなかった。この Bolt の依存は増えなかったが、見積りが購読すると quotation → routing :: events で循環する（レビュー D-71）。「依存が増えない」だけでは次の Bolt の形を確かめられていなかった
