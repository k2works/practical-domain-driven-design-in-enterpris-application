    基本情報¶

    項目 内容

    期間 2026-10-05 13:12 JST（計画の承認のコミット 62f873d）〜 15:15（本報告の初版）。開始準備は 12:47〜13:06（計画のコミット 16eda74）
    対象 U1 輸送要求・見積り。US-03 根拠付き見積りを提示する（AC1〜AC3）。#4（SP 5。Bolt 11 の AC4・AC5 の後にクローズする）
    計画 Bolt 10 計画
    ゴール 営業担当者が審査を確定した見積依頼に、料金根拠（明細）・有効期限・経路方針を入れて算出し、社内承認して荷主へ提示できる。足りなければ提示できず、足りない項目が示される。荷主は見積依頼の詳細で、料金根拠と、利用者のタイムゾーンと UTC offset を伴う有効期限、経路方針、詳細な経路は承認後に確定する旨を確かめられる
    進め方 U1 の密度。承認ゲートは、計画（確認ポイント 1〜6）、ステップ 1・2（業務のルール）、ステップ 3（スキーマ）、開発レビューの判断、本報告の 5 回

    計画からの変更¶

    • 見積り番号は、採番の表を作らず、輸送要求の見積りの番号の最大 + 1 にした。同時の算出は UK で止め、リポジトリがセーブポイントに戻してドメインの例外にし、入力ポートが「見積りがすでにある」として値で返す（R-02）。
    • ER 図の監査の列（created_at など）は、ほかの業務の表と同じく作らなかった。
    • 開発レビューの指摘（下の「開発レビューと対応」）のうち重要度「高」を、この Bolt で直した。
    • 人の依頼で、デモ項目の画面を Playwright で録画し、docs/assets/demo/bolt-10/ に置いて本報告からリンクした（./gradlew demoVideo。シナリオの @demo-<Bolt>/<名前> の印のものだけを録画する。2026-10-05 に過去の Bolt の分も撮り、開発の索引に一覧を足した）。

    仮説の結論¶

    # 仮説 結論 根拠
    H1 見積りを輸送要求と別の集約にし、輸送要求の状態は DE-03 を受けて別のトランザクションで変えれば、2 つの集約を 1 つのトランザクションで更新せずに済む 成り立った（条件あり） QuotationPresentedDeliveryIntegrationTest で、提示のコミットの後に DE-03 が非同期に届き、輸送要求が見積提示済みになって配信が完了することを PostgreSQL で確かめた。受け取りは冪等。条件: 受け取りが失敗したときの配り直しは起動のときだけ（R-03、D-32）で、再起動しない間の定期の配り直しは W10 で入れる
    H2 有効期限を UtcInstant で持ち、表示の共通部品を使えば、AC1 を新しい部品なしに満たせる 成り立った（制約あり） 荷主は customerDateTime（2099-10-08 18:00 Asia/Tokyo（UTC+09:00））、社内は staffDateTime（UTC 併記）をそのまま使った。制約: 利用者のタイムゾーンは認証（US-18）まで Asia/Tokyo に固定
    H3 算出・社内承認・提示を 1 つの集約の状態遷移として作れば、認証の前でも仮の承認者で流れを通せ、後で本人の承認に差し替えられる 成り立った 承認者は PresentQuotationCommand の引数で、画面の層だけが仮の営業担当者（ProvisionalActorProperties）を渡す。差し替えは画面の層の 1 か所

    開発レビューと対応¶

    T-28 に従い、本報告の前に Bolt 9・10 の変更をまとめてレビューした（Bolt 9・10 開発成果物レビュー）。人の判断で、重要度「高」と SonarQube の指摘だけをこの Bolt で直し、中・低は Bolt 11 の最初に回した。

    # 指摘 対応
    R-01 金額に上限がなく、表の NUMERIC(15,2) を超えると 500 金額と合計の整数部を 13 桁までにし、超えたら値で返す。指数の表記の巨大な数は桁を作らずに判定する
    R-02 同時の算出で UK に違反すると 500 リポジトリがセーブポイントに戻して DuplicateQuotationException にし、入力ポートが「見積りがすでにある」として返す。画面は、その見積りへ移して理由を示す
    R-03 受け取りが失敗したイベントを配り直す設定がない 起動のときに配り直す（D-32）。ADR-003 のコンプライアンスに書いた。定期の配り直しは W10
    R-04 算出した後に画面を離れると、承認待ちの見積りに戻れない 作成画面を開いたとき、作成中・承認待ち・提示済みの見積りがあればその見積りへ移す（受付一覧の見積り作成中から戻れる）
    R-05 荷主に、見積りを受け取った後の案内がない C-04 の見積りの節に、回答の画面（US-24）ができるまでの案内を出した（D-33）
    R-11 SonarQube の Code Smell 直した（品質ゲートは PASS）

    判断と学び¶

    設計への反映（反映済み）¶

    • ユーザーストーリー（US-03 の決定）、ドメインモデル（料金根拠と料金明細、見積り番号、Q-INV-17（金額の上限を含む）・18、DE-03 の購読、見積りの提示の段落、用語）、データモデル（quotation・pricing_line）、UI 設計（S-02・S-03・S-04・C-04、S-04 の画面イメージ、見積提示済みの表示名）、ADR-003（起動のときの配り直し）
    • リリース計画（W2 に Bolt 10）

    人の決定¶

    • US-03 を Bolt 10（AC1〜AC3）と Bolt 11（AC4・AC5）に分ける
    • 確認ポイント 1〜6（表と NULL 可の列、料金根拠の明細と通貨、有効期限と経路方針、DE-03 での状態の更新、S-04 の URL と流れ、見積りは 1 つ）
    • 見積提示済みの表示名と案内、スキーマ、見積り番号の採番と監査の列を作らないこと
    • 開発レビューの対応の範囲（高だけ）、D-32・D-33、D-34〜D-36 は業務責任者に確かめる
    • デモ項目の動画を docs/assets/demo/<Bolt>/ に置き、デモ項目に当たるシナリオだけを録画する
