    Bolt 8 計画 - UI の骨格と見積依頼の段階入力のプロトタイプ（#36）¶

    基本情報¶

    項目 内容
    Bolt 第 8 回
    予定 W1（2026-10-05 の週）、3〜4 時間（段階入力を同じ Bolt に入れたため、打ち切りの線を決めておく）
    対象 技術タスク #36 [技術] UI の骨格と見積依頼の段階入力のプロトタイプ（SP 0）。UI-HO-04（C-03 の段階入力の操作性）
    承認ゲート 業務のルール以外はまとめる（Bolt 6 の H3）。業務のルール・スキーマ・セキュリティに関わるステップはない。計画の承認（外部ライブラリの導入を含む）と、終了報告の承認（段階入力の操作性を人が触って確かめる）の 2 回
    アプローチ 開発戦略の序盤のアウトサイドイン。画面の層の受入シナリオから入る。骨格の移行は既存の画面の層のシナリオ（21 本）を回帰の安全網にし、文言とキー操作の期待を変えずに見た目を移す
    前の Bolt Bolt 7 終了報告

    Bolt ゴール¶

    顧客 Web と社内業務 Web のすべての画面が、共通レイアウト（ヘッダー、左ナビ、顧客 Web の窓口の案内）と Bootstrap 5.3 の部品で表示され、画面ごとに書いていたスタイルが共通の CSS に移る。荷主は見積依頼の作成と編集を、輸送条件・貨物・書類・確認の 4 段階で入力でき、キー操作だけで段階を行き来して提出できる。

    確かめたい仮説¶

    # 仮説 この Bolt で分かること
    H1 Thymeleaf のフラグメント（th:replace）だけで、顧客 Web と社内業務 Web の 2 つのレイアウトを作れる（Layout Dialect を足さない） 依存を増やさずにレイアウトを共通にできるか
    H2 段階入力を 1 つのフォームの中のパネルの切り替えにすれば、選んだファイル・サーバーの検証・エラー要約を変えずに、JavaScript がなくても今の 1 画面の形で動く 下書きの保存（R1.0）の前に段階入力を入れられるか
    H3 Bootstrap 5.3 の部品に移しても、既存の画面の層のシナリオ（文言とキー操作）と axe-core（WCAG 2.2 AA）を変えずに通せる Bootstrap の部品が BR-13 を満たすか

    ふりかえりと前の Bolt からの引き継ぎ¶

    入力 内容 この Bolt での扱い
    人の決定（2026-10-03、Bolt 8 の開始準備） 対象は #36。段階入力のプロトタイプも同じ Bolt に入れる。Bootstrap・htmx は WebJars で同梱する（技術スタックの決定のとおり） 計画に入れた。半日を超えないよう打ち切りの線を決めた
    Try T-18（Bolt 5） 押せる範囲（24 CSS px）と横スクロールに効くスタイルは、UI の骨格の共通の CSS で決める ステップ 2 で、画面ごとのインラインのスタイル（入口の一覧、C-02、C-04、S-03 の 4 か所）を共通の CSS に移す
    Try T-22・T-23・T-24（Bolt 7） 書式の整形の後のファイルは、今の形を読んでから書き換える。統合テストの年は grep で確かめる。時刻は同じコマンドの中で date を実行して差し込む 全ステップ
    Try T-21・T-19・T-14・T-16・T-17 画面の層の Red を実行して記録する。passed 以外を数える。ステップの終わりに check を緑にして push。時刻を残す。cd は絶対パス 全ステップ
    Bolt 7 の既知の課題 書類の一覧の表とリンクのスタイルを画面ごとに書いた ステップ 2 で共通の CSS に移す

    スコープ¶

    設計の約束（Try T-1）¶

    設計の約束 出典 この Bolt
    顧客 Web と社内業務 Web で別のレイアウト・ナビゲーションにする UI 設計「ナビゲーションとレイアウト」、ADR-005 入れる
    顧客 Web は左サイドナビ、狭いときは上部のメニューに畳む。社内は左サイドナビ 同上 入れる。ナビの項目は、いまある画面だけを出す（顧客: 見積依頼。社内: 見積依頼、KPI）。ない画面の項目は、画面を作る Bolt で足す
    ヘッダーに企業名・利用者名とログアウト 同上 仮の主体の名前を出す。ログアウトは認証（US-18）で足す
    顧客 Web のすべての画面の下部に、窓口と受付時間を利用者のタイムゾーンで示す UI 設計（WCAG 3.2.6、R-11） 入れる。受付時間は UI 設計の画面イメージの値を仮に使い、利用者のタイムゾーンは Asia/Tokyo（US-18 の後に利用者の設定にする）
    ナビの現在項目を太字と aria-current="page" で示す 同上 入れる
    操作の大きさ 24 × 24 CSS px 以上、画面幅 320 CSS px、固定ヘッダーの scroll-padding UI 設計「共通部品」 入れる（共通の CSS）
    表は狭い画面で時系列のリストに切り替える UI 設計「共通部品」画面幅 入れない。表の横スクロールの囲み（WCAG 1.4.10 の表の例外）を共通の部品にする。リストへの切り替えは一覧が増えてから
    C-03 の段階入力: 輸送条件・貨物・書類・確認の 4 段階、各段階で下書き保存 UI 設計 C-03 4 段階を入れる。下書き保存は R1.0（入れない。確認ポイント 3）
    C-03 の「過去の依頼から複製」「取り下げる」 UI 設計 C-03 入れない（R1.0、US-05）
    htmx の部分更新は一覧の絞り込みなどに限る UI 設計「部分更新を使う箇所」 htmx は同梱して読み込むだけにする。部分更新を使う画面はまだない（確認ポイント 2）

    入れるもの・入れないもの¶

    入れる 入れない（後の Bolt）
    WebJars の Bootstrap 5.3・htmx 2.0、共通の CSS Thymeleaf Layout Dialect、フロントエンドのビルド
    顧客 Web と社内業務 Web の共通レイアウト（フラグメント）と、既存の 7 画面と入口の一覧の移行 ログアウト、言語の切替、役割に応じたナビの出し分け（US-18・US-16）
    C-03 の作成と編集の 4 段階の入力（ブラウザの中でパネルを切り替える） 段階ごとの下書き保存（R1.0）、段階ごとのサーバーの検証
    確認の段階の入力内容のまとめ 経路候補の比較（S-06）のプロトタイプ（W3）

    設計（この Bolt の範囲）¶

    ドメインモデル・状態遷移・データモデル¶

    業務の型、状態、表は変えない（画面の層だけの Bolt）。ドメインモデル図・状態遷移図・ER 図は省く。

    画面遷移とレイアウト¶

    注（設計への反映。ステップ 1 で反映する）: UI 設計に次を書く。

    • 共通レイアウトの実装（Thymeleaf のフラグメント、WebJars、共通の CSS の置き場）と、いまあるナビの項目
    • C-03 の段階入力を、R1.0 で下書きを保存するまでは 1 つのフォームの中のパネルの切り替えにすること。JavaScript がないときは全段階を 1 画面で示すこと。エラー要約のリンクを選ぶと、その項目のある段階を開いてフォーカスを移すこと

    開始準備の検証¶

    検証 見つけたこと 対応
    詳細（UI 設計） C-03 の段階入力は「各段階で下書き保存する」。下書き保存は R1.0 の範囲（ドメインモデル Q-INV-01 の注） 確認ポイント 3。段階の切り替えだけを入れ、保存は R1.0 に残す
    詳細（UI 設計） ナビの項目には、まだない画面（予約、追跡の照会、問い合わせ、通知、経路設計など）が並ぶ いまある画面だけを出し、ない項目は画面を作る Bolt で足す（確認ポイント 1）
    詳細（技術スタック） WebJars（webjars-locator-lite）、Bootstrap 5.3.x、htmx 2.0.x は選定済み 外部ライブラリの導入として計画の承認で確かめる（確認ポイント 2）
    横断（開発戦略） 序盤はアウトサイドイン。骨格は既存の画面の層のシナリオを安全網にする移行 新しい振る舞い（ナビ、窓口の案内、段階入力）だけ新しいシナリオで駆動する
    横断（BC の独立性） レイアウトのフラグメントは identity と quotation の両方の画面が使う。テンプレートは templates/layout/ に置き、どのコンテキストの Java の型にも依存しない（モデルの値だけで描く） 問題なし。ナビの項目は設定の値でなく、レイアウトの中の固定のリンクにする
    横断（過去の計画との連続性） 画面の層のシナリオは文言とキー操作で操作する（Bolt 3 R-13）。表の横スクロールの囲み（Bolt 5）、押せる範囲（Bolt 5）、aria-disabled（Bolt 4） 部品の作りは変えず、スタイルだけを共通の CSS に移す

    AI の仮定¶

    • 段階の見出しは、段階の名前と番号を持つリストにし、現在の段階に aria-current="step" を付ける。前の段階の見出しはリンクにして戻れるようにする。
    • 「次へ」で段階を移ったら、フォーカスを次の段階の見出しへ移す（支援技術に段階の変化を伝える）。
    • 共通の CSS は Bootstrap の上書きを最小にし、24 CSS px の操作範囲、scroll-padding、表の横スクロールの囲み、長い語の折り返しだけを足す。
    • 入口の一覧（static/index.html）はテンプレートにし、レイアウトを使わない（荷主と社内のどちらでもない入口のため）。Bootstrap の見た目だけをそろえる。
