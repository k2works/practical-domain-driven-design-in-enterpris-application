    Bolt 37f3 計画 - 「区間」の語のそろえ（荷主の画面とマニュアルは「航海」）¶

    基本情報¶

    項目 内容
    Bolt 第 37f3 回（W6 の 17 本目）
    予定 W6（2026-11-09 の週。前倒しで着手できる）。作業は約 2.5 時間（check・uiTest・manualScreenshots・SonarQube・CI の待ちを除く）
    アプローチ アウトサイドイン（画面の構造。荷主の画面を描くテストを外側の Red にする）
    対象 「区間」は社内の語とし、荷主に見せる画面とマニュアルでは「航海」にする。(1) 荷主の追跡の照会の結果（C-10）の見える文字「区間 1、航海 V100、JPTYO から KRPUS」を「航海 V100、JPTYO から KRPUS」に（社内の S-12 は「区間」のまま）、(2) 経路の表の読み上げ（aria-label）「確定した経路の区間（…）」を「確定した経路の航海（…）」に（荷主の C-04・C-17 と社内の S-04 の共通の部品）、(3) マニュアル 4 章・5 章の「区間」を「航海」に、用語集に「区間」を社内の語として足す。C-10 のキャプチャを撮り直す
    GitHub #50（「区間」の論点を閉じる）
    SP 0
    承認ゲート 計画と終了報告。画面の見える文字の変更（C-10）。スキーマ・認可・環境変数・開発データ・CI は変えない
    開始準備で決めたこと 2026-10-24、human:kakimomokuri（Bolt 37f の開始準備の決定 (4) に足す）: (1) C-10 の見える文字も直し、番号を落として「航海 V100、JPTYO から KRPUS」にする（順序付きのリストが順を示す）。社内の S-12 は「区間」のままにし、文字列を作る部品を荷主用と社内用に分ける。見える変化なので、マニュアル 5 章のキャプチャを撮り直す（動画は新しく撮らず、過去の Bolt の動画もそのまま）、(2) 経路の表の aria-label は荷主・社内の別なく「確定した経路の航海」にする（部品は分けない）

    Bolt ゴール¶

    荷主に見せる画面とマニュアルから社内の語「区間」をなくし、Bolt 37e4 の決定（荷主には「最初の航海」）と語をそろえる。

    開始準備で確かめたこと¶

    • 前提の直し: release_plan :772 と Bolt 37e4b の報告 :61・:73 は「荷主の画面の『区間』は aria-label だけ（見える変化がない）」としていたが、荷主の C-10 に見える文字として出ていた（tracking/tracking-records/show.html:27 の leg.summary()）。開始準備の決定 (1) で範囲に入れた
    • C-10 の文字列: tracking/interfaces/web/TrackingRecordViews.java:195 の legSummary（"区間 " + legNo + "、航海 " + …）。:181・:193 の注のとおり S-12（社内）と C-10 で共通。見出しは Bolt 27 で「予定」（:24）
    • 経路の表: quotation/fragments/assigned-route.html:14 の th:aria-label="|確定した経路の区間（${route.label()}）|"（表の領域の名前。読み上げだけ）。見出しはすでに「航海／積地 → 揚地／出発予定／到着予定」（:18-21）。使う画面は C-17（approval.html:21）、C-04（detail.html:67）、S-04（staff/quotations/show.html:36・new.html:104）
    • 荷主向けの文言の Java: 見える文字に「区間」はない（TransportRequestLabels・QuotationViews は Javadoc だけ）
    • 社内の画面の「区間」（対象外）: テンプレート 5 か所、Java の文言 6 か所（S-02・S-04・S-06・S-07・S-09・S-12）
    • テスト: C-10 は CustomerTrackingControllerTest.java:184（"区間 1、航海 V100、JPTYO から KRPUS"）と ui/CustomerTrackingUiSteps.java:87（containsText("区間 1")。query_tracking_ui.feature:36・:59、main_flow_ui.feature:43）。S-12 は TrackingRecordControllerTest.java:194-195、ui/TrackingUiSteps.java:84-85（変えない）。経路の表の aria-label を確かめるテストは 0 件。Bolt 37e4 の「区間」が出ないことの確かめ（RouteRedesignUiSteps.java:104・:119）は見える文字だけを見る
    • マニュアル: 4 章 :89・:142（「区間ごとの航海・積地 → 揚地…」）、5 章 :20（「予定区間」）・:98（「予定の区間」）・:112（「区間ごとの航海・積地から揚地…」）。用語集に「区間」の項目はなく、:44（出発済み）が「荷主の画面には『区間』『出発済み』と示さず」と書く。キャプチャで「区間」が見えるのは assets/05-tracking-result.png だけ（manual_screenshots.feature:104）
    • 設計の文書: ui_design :160（C-17「区間ごとの航海…」）、:165（C-10「予定区間の…区間の要約」）、:1004（C-17 の画面イメージの列「区間 | 航海 | …」。実装と食い違う）、:1378（C-10 の画面イメージ「1. 区間 1、航海 V100…」）。:159・:956 は「社内の語（区間…）を出さず」とすでに書く。domain_model の用語集の「区間」「予定区間」はモデルの名前で変えない
    • 動画: C-10 の「区間 1」は過去の動画（bolt-27 の query-tracking、bolt-28 の main-flow）に写る。開始準備の決定 (1) で撮り直さない。新しい動画も撮らない（見える変化はあるが、W6 のデモ項目に当たるシナリオがない。開発戦略 :141・:185、release_plan :789）
    • 番号を落としても区別できる: 候補は同じ航海・同じ港を 2 回使わず（RouteCandidateFinder.java:61・:65、user_story :298）、追跡の予定はつながる（前の区間の揚地と次の区間の積地が同じ。Schedule.java:30-40）ので、行は航海番号と積地・揚地で区別でき、順はリストの並びで示せる
    • システムメタファー: ui_design :47-51 は「顧客 Web と社内業務 Web で同じ語彙を使う」とし、時刻表の行を「確定した経路版の区間」とする。この Bolt の決定（区間は社内の語）は例外になるので、注を足す
