    cargo-tracker Bolt 14 開発成果物レビュー（2026-10-06）¶

    レビュー対象¶

    • 範囲: f1173bd^..36edf6a（Bolt 14 のステップ 1〜4。apps/cargo-tracker と docs）
    • 内容: US-18 の password によるログインと session。Spring Security の form login と Spring Session JDBC、企業・利用者・役割・監査記録の表、A-01・A-03・A-04、役割ごとのナビと準備中の画面、仮の主体の置き換え、開発環境の入力済み
    • 視点: xp-programmer、xp-tester、xp-architect、xp-technical-writer、xp-user-representative の 5 つ（並列）。セキュリティの観点を必ず含めた

    総合評価¶

    モジュールの切り方（共有カーネルの AuthenticatedActor、引数の解決を identity に閉じ込め、quotation は Spring Security を知らない）、password を先に照合して利用停止を後で拒む AC2 の工夫、境界の 3 点と T-40 の順序のテストは、5 つの視点のどれからも評価された。Red が Green より先にあることも確かめられた。

    一方で、失敗に倒れない箇所（8 時間の上限が属性のない session で外れる、引数の解決が未認証で null、開発用の守りが Flyway より後に動きうる）、役割とホームの対応の食い違い（画面のない役割が A-04 を循環する）、無操作 30 分のテストが設定の誤りを見つけられないこと、利用者がつまずいた画面（A-04・A-03・準備中）の案内の不足、設計文書の反映漏れが指摘された。無操作 30 分のテストを既定と違う値で書き直したところ、server.servlet.session.timeout が Spring Session に効いていないことが分かった（30 分は既定値の一致で成り立っていた）。

    改善提案（重要度順）¶

    高¶

    # 提案 箇所 指摘元
    R-01 役割とホームの対応を 1 か所に集め、画面のない役割は A-04 にする（荷主・営業以外はホームが /staff/** で 403 になり循環する） SecurityConfiguration、RoleHomeAuthenticationSuccessHandler、HomeController programmer、tester、architect、technical-writer
    R-02 8 時間の上限を fail-closed にする（認証済みなのにログインの時刻がない session も失効）。属性の名前を固定の値にする SessionLifetimeFilter、SessionLifetime programmer、tester、architect
    R-03 開発用の設定と開発用のデータの Flyway の場所を、マイグレーションより前に確かめる（dev,prod の誤りで本番の DB に開発用の利用者が入りうる） DevLoginGuard、application-dev.properties architect
    R-04 session の直列化の互換を壊す変更の扱いを ADR に書く CargoUserDetails、ADR-012 architect
    R-05 A-04 の問い合わせ先を荷主にも分かる文言にする error/403.html user-representative
    R-06 ui_design の準備中の画面の「予定の週」、手順書の入口の一覧の記述を直す ui_design.md、application_development_setup.md technical-writer

    中¶

    # 提案 箇所 指摘元
    R-07 引数の解決を fail-closed にし（未認証なら例外）、レイアウトは Optional で受け取る AuthenticatedActorArgumentResolver、CurrentActorAdvice programmer、architect
    R-08 無操作 30 分の設定の鍵が効くことを、既定と違う値で確かめる。「30 分ちょうど」のテストの名前を実態に合わせる AuthenticationSecurityIntegrationTest、application.properties tester
    R-09 GET のログアウト、AC1 の監査の企業と時刻、形式の誤ったメールアドレスの監査、役割と CSRF の代表の POST、ホームの振り分けのテストを足す AuthenticationSecurityIntegrationTest tester
    R-10 principal_name（100 文字）をメールアドレス（320 文字）に合わせる V20261006140100__create_spring_session.sql architect
    R-11 CSP に frame-ancestors・form-action・base-uri・object-src を足す。htmx のインラインの style を止める SecurityConfiguration、layout/common.html architect、programmer
    R-12 監査の listener の失敗の理由の求め方を整理する。W5 のロックは application のサービスへ AuthenticationAuditListener programmer、architect
    R-13 失敗の後に session に置くメールアドレスの長さを上限で切る。匿名の session の増加をリスク台帳に KeepEmailAuthenticationFailureHandler programmer、architect
    R-14 A-03 に問い合わせ先と、ログインの後に戻ることを書く。準備中の画面に当面の連絡先を書く session-expired.html、placeholder.html user-representative
    R-15 ログインの前に開いた画面へ戻るシナリオを画面の層に足す login_ui.feature user-representative
    R-16 文書の食い違いを直す（存在しないメールアドレスの記録、roles の複数、ナビの方針、権限外の試行の記録の時期） ADR-012、data_model、domain_model、ui_design technical-writer、architect
    R-17 W5 で見直すこと（多要素の成功のイベント、要素の権限、request ごとの DB、テストの主体）を ADR に書く ADR-012 architect
    R-18 規則を「identity 以外は Spring Security に依存しない」に一般化し、常に通る規則（仮の主体）を消す AuthenticationArchitectureTest architect、tester

    低¶

    # 提案 箇所 指摘元
    R-19 利用者の Javadoc（照合の前→後）、予約語の変数名、SonarQube の指摘 User、AuditRecord* ほか programmer、SonarQube
    R-20 413 の一般の文言に戻り先、レイアウトのコメント、タイムゾーンの記述、README の書き換えの案内 テンプレート、README technical-writer
    R-21 準備中の画面の前処理に request の値を渡さない旨をコメントする placeholder.html architect
    R-22 幅の狭い画面でヘッダーの企業名・利用者名が出ない layout/customer.html user-representative
    R-23 テストの補助（TestActors・WithAuthenticatedActor）が identity の内部にある テスト architect
    R-24 email の正規化の Java と DB の差（Unicode の空白・特殊な大文字） EmailAddress、CHECK architect
    R-25 監査の検証の順が時刻でなく操作の名前で決まる。テストの補助の細部（全体の件数、Cookie の形式、失敗の待ち） テスト tester

    懸念事項¶

    • 承認ゲート（業務のルールとスキーマ、セキュリティ）を /goal Bolt 14 により止めずに通した（programmer）。終了報告の議題の先頭で人の承認を取る。
    • H2 のコンソールが、認証・CSRF・フレームの禁止で使えなくなっていた（programmer、technical-writer、architect）。
    • 入力の保持と失効の前の警告（ACC-06）は、利用者の信頼にかかわるため W5 で必ず入れる（user-representative）。
    • 画面の文言の「password」は、荷主には「パスワード」が自然（user-representative、technical-writer）。
    • ステージング・本番に利用者を作る手段が US-16 まで無い（user-representative）。
    • multipart の超過は CSRF の確認の段で起きる。Tomcat・Spring の更新で壊れやすい（programmer、architect）。

    スコープ外の発見¶

    • ALB の後ろでの server.forward-headers-strategy（W10、architect）。
    • 運用手順書の全体を Bolt 14 の後の状態に合わせる（technical-writer）。
    • カスタマーサポートの受付時間が仮の値のまま（user-representative）。

    対応結果¶

    判断（2026-10-06、Bolt 14 のステップ 5。人の指示 /goal Bolt 14 により AI の判断で進めた。T-36）¶

    ID 判断 理由
    D-49 高の R-01〜R-06 と、中の R-07〜R-18 はこの Bolt で直す。テストを先に書き（Red 75d8fe6）、直した（Green 89eb6ad、文書 16a5967） セキュリティの守りを失敗に倒し、利用者の行き止まりをなくすのは US-18 の範囲。後に回すと W5 の TOTP と混ざる
    D-50 無操作 30 分の期限は spring.session.timeout で決める 既定と違う値のテストで、server.servlet.session.timeout が Spring Session に効いていないことが分かった。30 分は既定の値と一致していただけ
    D-51 役割とホームの対応はルートのコントローラーの 1 か所に置き、ログインの後もルートを通す。画面のない役割は A-04 対応を 2 か所に置くと食い違う。荷主・営業以外の役割の画面を作る Bolt で対応を足す
    D-52 H2 のコンソールは外す（依存と設定を消し、手順書を直した） コンソールを使うには、その道筋だけ CSRF の確認を外す必要があり、SonarQube も脆弱性として止めた。開発環境でも守りに穴を開けない
    D-53 低の R-22〜R-25 と、懸念の「password」の画面の文言は、この Bolt では直さない R-22 はヘッダーの設計（メニューの中に出す）を W5 の利用者の管理と合わせて決める。R-23 は本体の型を公開しないために identity に置いている（本体の検査の対象外）。R-24 は利用者の登録（US-16）で入力を ASCII に限るかと合わせて決める。R-25 はいまの逐次の実行では問題が出ない。「password」は文書の用語で、画面の文言を変えるかは人に確かめる（終了報告の議題）

    改善提案ごとの対応¶

    # 対応
    R-01 直した。LoginSuccessHandler はルートへ移し、HomeController が役割のホームを 1 か所で決める。経路設計者は A-04（テストを足した）
    R-02 直した。SessionLifetimeFilter は認証済みで属性がない session を失効させる。属性の名前は cargotracker.session.authenticatedAt。フィルターの単体テストを足した（境界の 3 点、属性なし、未認証）
    R-03 直した。DevLoginGuard.check を identity.devlogin に移し、Flyway の設定の組み立て（FlywayConfigurationCustomizer）で動かす。dev の外の db/dev-data も止める
    R-04 ADR-012 の「ネガティブ」に、互換を壊す配備では platform.spring_session を消す手順を書いた。リスク台帳に足した
    R-05 直した。「荷主の方は担当営業に、社内の方はシステム管理者にお問い合わせください。」
    R-06 直した
    R-07 直した。未認証なら AuthenticationCredentialsNotFoundException（A-01 へ）。Optional<AuthenticatedActor> も受け持つ
    R-08 直した（D-50）。SessionTimeoutPropertyIntegrationTest は 10 分を設定して 600 秒が入ることを確かめる。「30 分ちょうど」は「30 分」に改め、ミリ秒の誤差を Javadoc に書いた
    R-09 テストを足した
    R-10 直した。V20261006150000__widen_spring_session_principal_name.sql（両方のベンダー）。長いメールアドレスのログインのテストを足した
    R-11 直した。htmx は htmx-config の meta で style を足させない
    R-12 失敗の理由は例外の種類で先に分けるようにした。ロックを application へ置くことは ADR-012 の「W5 で見直すこと」に書いた
    R-13 直した。匿名の session はリスク台帳に足した
    R-14 直した
    R-15 シナリオを足した（login_ui.feature）
    R-16 直した
    R-17 ADR-012 に書いた
    R-18 直した
    R-19 直した（SonarQube の品質ゲートは 2 回不合格になり、3 回目で PASS）
    R-20 直した
    R-21 直した
    R-22〜R-25 直さない（D-53）
