    cargo-tracker Bolt 6〜8 開発成果物レビュー（2026-10-03）¶

    レビュー対象¶

    • Bolt 6〜8 の変更: Bolt 5 のクローズ（1be0b4b）から 06144c3 まで。コードは 85 ファイル（追加 4,173 行）
    • Bolt 6: 荷主の見積依頼の一覧（C-02）・詳細（C-04）・編集（C-03）、荷主企業での絞り込み、差戻しの知らせ（SendBackNotice）、出し直しの結果（ResubmissionOutcome）
    • Bolt 7: 必要書類の添付（Q-INV-16、RequiredDocumentPolicy、DocumentMediaType）、書類の保存のポートとローカルの実装、required_document の表、版ごとの保存と出し直しでの引き継ぎ、荷主と営業の取得、413 の案内
    • Bolt 8: WebJars の Bootstrap・htmx、顧客 Web と社内業務 Web の共通レイアウト、C-03 の段階入力のプロトタイプ（UI-HO-04）
    • 文書: Bolt 6 計画〜Bolt 8 終了報告、設計文書・要件定義・手順書の差分
    • 観点: xp-programmer、xp-tester、xp-architect、xp-technical-writer、xp-user-representative の 5 つ（並列に実施）
    • 経緯: Bolt 6〜8 は、各 Bolt の終わりに開発レビューを行わずに閉じていた（理由の記録なし）。人の指摘で、W1 の完了後に 3 つの Bolt をまとめてレビューした

    総合評価¶

    Bolt 5 で決めた方針（業務の拒否は値、壊れた前提は例外）は Bolt 6〜8 でも保たれている（programmer）。書類の保存をポートにし、オブジェクトキーにファイル名を使わず、形式を中身で判定して attachment・nosniff で返す作りは、ADR-001・007・008 とデータモデルの追記専用の方針にそろっている（architect）。Q-INV-16 の境界値と他社を 404 にする否定テストは、単体・業務ルール層・統合・Web の各層に揃っている（tester）。差戻しの理由を読み、版 2 を出し直す流れは荷主の目線で一通り使える（user-representative）。前回の Bolt 5 の指摘（審査記録の UNIQUE、全件の書き戻し、一覧の N+1）も解消されている（architect）。

    一方、次が重大度「高」として挙がった。

    • 書類が絡むと業務が止まる: 引き継いだ書類を差し替えられず、送り状の直しを求められても出し直せない。誤りの再表示で、正しく選んだ書類が知らされないまま消える（user-representative）
    • 画面の表示の誤り: 差戻しの不足事項の改行が潰れる（user-representative）。エラー要約で表示名が二重に出る（technical-writer）
    • 書類の保存とトランザクション: 孤児ファイルが正常系（出し直しの競合、採番の前の保存）でも出る。ファイルの書き込みが DB のトランザクションの中で行われる（architect、programmer、tester）
    • 認証のない社内の画面から書類の実ファイルを取れる（architect）
    • 書類の行を毎回 IfAbsent で書き込む: Bolt 5 の R-03 の方針とずれる（programmer）
    • 413 の経路にテストがない（tester）
    • レビューを省いたことが記録されていない。Bolt 8 の終了報告に承認前の文が残っている（technical-writer）

    改善提案（重要度順）¶

    高¶

    # 提案 箇所 指摘元 AI の提案する対応方針
    R-01 引き継いだ書類を差し替えられるようにする（同じ種類を選び直せば版 2 で差し替わる、で足りる）。今のシナリオは行き止まりを正しい振る舞いとして固めている attach_required_documents.feature、D-20 user-representative 人の判断（D-25）
    R-02 誤りの再表示で書類の選択が消えることを、エラー要約と書類の段階に必ず出す new.html、SubmissionViolationMessages user-representative 修正。受け付けた書類をサーバーで保持して引き継ぐのは後の Bolt
    R-03 不足事項の改行を保って表示する C-04 detail.html:31、S-03 user-representative 修正（white-space: pre-line）。画面のテストを足す
    R-04 エラー要約の文言から表示名を外し、二重に出ないようにする。ui_design.md の例と合わせ、画面のテストを完全一致にする SubmissionViolationMessages.java:73-75、SubmitTransportRequestUiSteps.java:220 technical-writer 修正
    R-05 孤児ファイルの経路（出し直しの競合、採番の前の保存、DB の保存の失敗）の片付け方と、保存をトランザクションの外に出すかを決める。出し直しで書類に違反があるときにファイルを保存しないテストを足す TransportRequestCommandService.java:66-166 architect、programmer、tester 方針は人の判断（D-26）。テストはいま足す
    R-06 認証のない /staff/** から全社の書類の実ファイルを取れる。ステージングに置く前提を明記する TransportRequestReviewController の document() architect、tester 人の判断（D-27）
    R-07 書類の行を、新しい版のときだけ INSERT する（IfAbsent をやめる）。審査記録（Bolt 5 の R-03）と同じ考え方にそろえる MyBatisTransportRequestRepository.java:120-133、TransportRequestMapper.xml programmer 修正
    R-08 multipart の上限（55 MB）を超えたときに 413 と案内を返す経路のテストを足す（RANDOM_PORT）。Tomcat の maxSwallowSize で接続のリセットにならないかを確かめる UploadLimitAdvice、application.properties:42-43 tester、architect 修正
    R-09 Bolt 8 の終了報告の承認前の文（50・127・159 行）を決定に合わせる。Bolt 6〜8 のレビューを省いたことと、このレビューで補ったことを報告とリリース計画に書く bolt_08_report.md、release_plan.md technical-writer 修正（レビューの計画のステップ 4）
