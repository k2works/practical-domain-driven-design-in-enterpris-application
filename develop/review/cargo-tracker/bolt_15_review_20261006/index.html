    cargo-tracker Bolt 15 運用成果物レビュー（2026-10-06）¶

    レビュー対象¶

    • 範囲: 41ff69d2..1028af52（Bolt 15 のステップ 1〜4）
    • 内容: apps/cargo-tracker/Dockerfile（build・runtime・demo）、.dockerignore、build.gradle の copyDemoLibs、ops/scripts/deploy_demo.js、gulpfile.js、.env.example、Heroku デモ環境セットアップ手順書、ADR-013、Bolt 15 計画
    • 視点: xp-architect（インフラ設計）、xp-tester（信頼性・セキュリティ）、xp-project-manager（運用性）の 3 つ（並列。operating-review）

    総合評価¶

    本番の成果物に H2 を入れない約束（ADR-007、AT-06）を守ったまま dev のデモを動かす構成（bootJar を変えず、copyDemoLibs と demo のステージで H2 だけを足す）は、3 つの視点のどれからも評価された。runtime のイメージが dev で落ちることを失敗の側から確かめたこと、R14 を計測して -Xmx300m に固定したこと、取り消せない削除をタスクにしなかったこと、つまずきを手順書に残したことも評価された。

    一方で、リポジトリと GitHub Pages が公開のため「URL は関係者にだけ伝える」が成り立たないこと、ADR と計画が旧いタスク名（heroku:*）のままで実装と食い違うこと、配備のガードがブランチを見ず build にしかないこと、動いているコミットが分からないこと、ロールバックの手順がないことが指摘された。runtime のステージに Heroku の都合（PORT・sh -c・EXTRA_CLASSPATH）が混ざっていて、W10 の ECS の出発点としては分け直しが要ることも指摘された。

    改善提案と対応¶

    高¶

    # 提案 箇所 指摘元 対応
    R-01 公開のリポジトリと GitHub Pages に URL と開発用の password があり、「URL は関係者にだけ伝える」が成り立たない ADR-013、手順書、README PM D-54: 公開を前提に ADR-013 を直す。URL は docs に残す
    R-02 ADR-013 が旧いタスク名（heroku:*）と heroku container:push のまま。ビルドの構成（copyDemoLibs、3 つのステージ、確認ポイント 13 の案と却下の理由）が決定にない ADR-013 3 視点 この Bolt で直す
    R-03 配備のガードが build にしかなく、push・release を単独で動かすと未検証のイメージが出る deploy_demo.js テスター この Bolt で直す（push にもガードを掛ける）
    R-04 イメージと release にコミットの SHA がなく、何が動いているか分からない deploy_demo.js テスター この Bolt で直す（イメージのラベルと Config Vars DEMO_REVISION、status で表示）
    R-05 Secure のない session の Cookie が公開の URL で動くことが ADR の帰結にない ADR-013 テスター、アーキテクト この Bolt で直す（ADR のネガティブに書く）

    中¶

    # 提案 箇所 指摘元 対応
    R-06 計画の本文（構成図・スコープ・打ち切り・リスク・DoD・デモ項目）が旧いタスク名のまま 計画 PM、アーキテクト この Bolt で直す
    R-07 ガードがブランチを見ない（「develop の緑のコミットから」を守らせていない） deploy_demo.js 3 視点 この Bolt で直す（HEAD が develop で、origin/develop に含まれる。CI は develop の実行を見る）
    R-08 ロールバックの手順がない 手順書 テスター この Bolt で直す（heroku releases・heroku rollback、前のコミットからの配備）
    R-09 スリープからの起動の時間を「終了報告を参照」としている 手順書 PM この Bolt で直す（計測値を手順書に書く）
    R-10 -Xmx300m は Heroku だけの値（Fargate は cgroup が効き MaxRAMPercentage が正しい） ADR-013、手順書 アーキテクト この Bolt で直す
    R-11 runtime のステージに EXTRA_CLASSPATH・PORT・sh -c が混ざる Dockerfile アーキテクト W10 に回す（runtime は exec 形式、PORT と demo-lib は demo で上書き）
    R-12 展開した extracted/ を 1 つのレイヤーで入れるため、コードの変更で全体を送り直す Dockerfile アーキテクト W10 に回す（extract --layers）
    R-13 イメージの検証が手作業だけ（runtime に H2 がない、demo が起動する）。forward headers の振る舞いがテストで固定されていない CI、テスト テスター、アーキテクト W10 に回す（ECR・ECS の最初の受入条件にする）
    R-14 ビルドの context に gitignore されたファイルが入りうる（作業ツリーの確かめに出ない） deploy_demo.js、.dockerignore テスター W10 に回す（git archive から作った context でビルドする案）。この Bolt では手順書に書く
    R-15 公開のファイル置き場としての悪用と、Heroku のアカウント全体が止められる恐れ ADR-013 アーキテクト、テスター この Bolt で直す（ADR のネガティブと、気づいたら stop する運用）
    R-16 1 人に Heroku のアカウント・費用・停止の手段が集中する 手順書、リリース計画 PM この Bolt で直す（手順書に所有者、リリース計画のリスクに足す）

    低¶

    # 提案 対応
    R-17 log-runtime-metrics を deploy:demo:setup で有効にする この Bolt で直す
    R-18 R14 の判断の基準（memory_total が 450 MB を超えたら dyno の種類を人に諮る） この Bolt で直す（手順書）
    R-19 copyDemoLibs を Sync にする（古い jar を残さない） この Bolt で直す
    R-20 webUrl() の正規表現を JSON.parse にし、取れないときに案内して止める この Bolt で直す
    R-21 container:login をしていないときの push の失敗の案内 この Bolt で直す
    R-22 ADR のコンプライアンスに「dev に H2 Console と devtools を入れない」 この Bolt で直す
    R-23 ADR-008 から ADR-013 への参照 この Bolt で直す（ADR の索引の注記）
    R-24 ベースイメージの digest での固定、--platform=$BUILDPLATFORM、Gradle のキャッシュの mount、jar の名前の glob W10 に回す
    R-25 DEMO_SKIP_GUARD を使ったことの記録の置き場 この Bolt で直す（手順書: 使ったら終了報告かジャーナルに理由を書く）
    R-26 シェルの文字列への環境変数の埋め込み（execFileSync の配列へ） W10 に回す（値は手元の .env だけで、実害は小さい）
    R-27 動画のアドレスバーに URL が映るか 対応しない（D-54 で URL は公開とした。Playwright の録画はアドレスバーを映さない）

    人の決定¶

    ID 決定 日付

    D-55 デモのない期間も常時起動にする（Eco のスリープに任せる。費用は定額で増えない）。週次の見直しで状態とログを確かめ、W10 でステージングができたら要否を見直す 2026-10-06、human:kakimomokuri
    D-56 上の表の「この Bolt で直す」と「W10 に回す」の分け方 2026-10-06、human:kakimomokuri

    エージェント別フィードバック詳細¶

    xp-architect（高: 1 / 中: 4 / 低: 6） ADR-008・007 との整合と AT-06 の保持を評価。ADR-013 の本文の食い違い（高）、`runtime` への Heroku の都合の混入、レイヤーの分割、`-Xmx` の Heroku 専用の明記、ブランチのガード（中）、`$BUILDPLATFORM`、依存のキャッシュ、jar の名前の glob、`copyDemoLibs` の漏れのスモーク、digest の固定、`webUrl` の JSON（低）。セキュリティは公開のファイル置き場の悪用、Secure のない Cookie、H2 Console と devtools を入れない約束。スコープ外は ADR-008 からの参照、`readonlyRootFilesystem` と `/tmp`、イメージの層までの AT-06。
    xp-tester（高: 3 / 中: 5 / 低: 4） 失敗の側からの確かめ、T-41、R14 の原因の分析、安全側に倒れるガードを評価。ガードが `build` にしかない、SHA がない、Secure のない Cookie が ADR にない（高）、ブランチ、gitignore されたファイル、ロールバック、イメージの自動の検証と forward headers のテスト、旧いタスク名（中）、`Sync`、digest、`execFileSync`、`DEMO_SKIP_GUARD` の記録（低）。運用リスクは R14 の余裕と判断の基準、ガードの誤判定（設計文書の変更、concurrency による取り消し）。
    xp-project-manager（高: 2 / 中: 3 / 低: 4） ガードによる約束の強制、削除を手で行うこと、命名、つまずきの表、計測値の根拠を評価。URL の秘匿が成り立たない、ADR の旧いタスク名（高）、計画の旧いタスク名、ブランチ、スリープの値（中）、`log-runtime-metrics`、`container:login` の案内、`DEMO_SKIP_GUARD` の記録先、`webUrl` の例外（低）。運用リスクは属人化、止め忘れの方針、リスク台帳。
