    cargo-tracker W6 横断の開発成果物レビュー（2026-11-02）¶

    レビュー対象¶

    • W6 の変更（git diff 7070b2374~1 92851c424。572 ファイル、約 3.4 万行）。Bolt 36〜38g の 34 本で、経路設計（US-06・US-07: 情報不足、確定の時の情報版の照合、再設計要、出発済み、Golden dataset v0）と利用者の管理（US-16・US-18 AC9: 登録と招待、ロックと TOTP の解除、本人への通知、担当範囲の受け渡しと判定、範囲外の試行の記録 ADR-019）
    • 各 Bolt は終了報告の前に開発レビュー済みなので、Bolt をまたいで初めて見えるもの（重複・一貫性・設計の流れ・残った負債）に絞った。各 Bolt の既知の課題と #50 の項目は繰り返さない
    • W6 の締めの追加の作業（2026-11-02、human:kakimomokuri の指示）。品質ゲートは別に流した（W6 完了報告書）

    総合評価¶

    モジュールの境界は W6 を通して保たれた。トップレベルの allowedDependencies は 1 本も増えておらず、担当範囲の外の記録は共有カーネルのポートを使う依存性逆転で循環を避けている（ADR-019）。前例の写しを ArchUnit の名前の規則で数えられるようにし、拒否の再表示を UserAdministrationRefusal で 1 か所に受けたので、Bolt を細かく割っても形はおおむねそろった。荷主と社内で語を書き分け（「航海」「見直し」と「区間」「再設計要」）、404 の案内は章と画面をまたいで同じ文である。

    一方で、Bolt をまたいで見ると次の 3 種類の問題が残った。

    • 利用者の業務の出口がない。再設計要と出発済みの案件は、経路設計者と営業の案内が互いを指し合い、閉じる手段がない。W7 で評価の入口をつなぐと、本番で実際に起き始める。担当企業の付け忘れも見えない
    • 写しの形が揃っていない。担当範囲の判定の置き方が 2 通りある。テストも、見積りだけにある確かめがほかの 3 つのコンテキストにない。S-02 だけが空の文の扱いと語で違う
    • 入口の文書が後の Bolt に追いついていない。8 章のキャプチャが情報不足の規則の前のままで、00 章・用語集・2.8・domain_model の用語集も W6 の後半の Bolt を反映していない

    指摘の数: 高 5、中 18、低 13（5 視点の合計。重なりを含む）。

    改善提案（重要度順）¶
